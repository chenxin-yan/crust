Node standalone binaries: `"runtime": "node", "artifact": "binary"` (or `--artifact binary` for a node project) now builds one Node.js single executable per command and platform with tsdown's executable builder, behind the usual Node launcher and platform packages. `@crustjs/crust` now depends on `tsdown` and `@tsdown/exe`, which the installed crust runs with the external `node` on PATH; no global tsdown is needed. That node is the embedded runtime for every target: it must satisfy `engines.node` and the installed tsdown's own requirements (its package engines and executable minimum, Node 26+ with tsdown 0.23), checked before `.crust/` is replaced. Crust never installs or upgrades it. Targets use Node's release names (`linux-x64`, `linux-arm64`, `darwin-x64`, `darwin-arm64`, `win-x64`, `win-arm64`; no musl); cross-platform builds download and cache that target's official Node.js archive of the same version, which needs `tar`/`xz`, or `unzip` for Windows targets on other hosts, and macOS executables are only signed when built on macOS. Application dependencies are bundled and any other leftover import fails the build; `crust.bunPlugins` is rejected for Node binaries. Staged Node binary packages omit `engines.node`, except on a root that publishes library `exports`. `resolveArtifactDir()` now resolves next to the executable inside a Node single executable application.

Node standalone binaries: `"runtime": "node", "artifact": "binary"` (or `--artifact binary` for a node project) now builds one Node.js single executable per command and platform with tsdown's executable builder, behind the usual Node launcher and platform packages. `@crustjs/crust` now optionally depends on `tsdown` and `@tsdown/exe`, which the installed crust runs with the external `node` on PATH; no global tsdown is needed. Package managers skip them, rather than failing an engine-strict install, under a Node outside tsdown's engines or with optional dependencies disabled; every other build still works, and Node binary builds then report the missing backend, or a reachable tsdown other than the version crust pins (such as the project's own), before replacing `.crust/` (reinstall with optional dependencies under a compatible Node). That node is the embedded runtime for every target: it must satisfy `engines.node` and the installed tsdown's own requirements (its package engines and executable minimum, Node 26+ with tsdown 0.23), checked before `.crust/` is replaced. Crust never installs or upgrades it. Targets use Node's release names (`linux-x64`, `linux-arm64`, `darwin-x64`, `darwin-arm64`, `win-x64`, `win-arm64`; no musl); every target's official Node.js archive of the same version is downloaded, verified, unpacked, and cached before `.crust/` is replaced, so a missing `tar` (GNU tar also needs `xz` for Linux targets) or `unzip` (Windows targets on other hosts) keeps the previous build, and macOS executables are only signed when built on macOS. Application dependencies are bundled and any other leftover import fails the build; `crust.bunPlugins` is rejected for Node binaries. Staged Node binary packages omit `engines.node`, except on a root that publishes library `exports`. `resolveArtifactDir()` now resolves next to the executable inside a Node single executable application.

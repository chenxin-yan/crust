Add `json()`, an Extension with a recursive `--json` flag for machine-readable output. With `--json`, stdout carries only JSON: the Command Action's result is printed to stdout as one line of JSON (nothing for `undefined`), the action's and Contexts' `stderr()` lines go to stderr, and failures are written to stderr as JSON: a `CrustError`'s `toJSON()`, or `{ "message": … }` for any other error. A result JSON cannot represent exactly (BigInt, cycles, functions, class instances, `-0`) fails the command with exit code 1. Exit codes are otherwise unchanged. Text the action and Contexts print with `stdout()` moves to stderr as it's printed, except in a command that declares `.output()`: it returns data, so under `--json` its JSON result replaces that text, and the text is written to stderr only when the command returns nothing, fails, or is cancelled. Write progress and instructions that must appear while such a command runs, such as a login URL, with `stderr()` or a spinner. `json()` sets the invocation's renderer, so it can't be combined with another Extension that does. Unknown commands and argv syntax errors still use the default rendering, because they fail before `--json` is parsed. A failure another Extension's `onError` hook claims keeps that Extension's format, and a Context cleanup failure after an already-rendered failure prints Core's plain-text `Cleanup failed:` line. Under `run()`, failures are read from `outcome.error`. `json()` also adds a "JSON output" section to the root command's documentation (help, man page, and skills) describing this contract: "--json prints the command's result as JSON on stdout (NDJSON for streaming commands). Other output goes to stderr; commands that declare an output schema print only the JSON."

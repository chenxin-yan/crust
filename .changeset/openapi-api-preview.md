`api preview` prints the request a generated command or a request path would send, and sends nothing: `acme api preview users delete -- 42` (the command's own arguments and flags after `--`) or `acme api preview /users/42 -X DELETE`. It builds the request with the same plan and checks as the command, returns `{ method, url, headers, bodyKind, body, bound? }` through `.output()` (so `--json` and MCP get it as data), never calls `auth()`, a Context of the command, `.onConfirm()`, a `bind` function or `fetch`, shows a bound value as its `{name}` placeholder, and redacts `Authorization`, `Proxy-Authorization`, `Cookie` and `X-Api-Key` headers. Like `api`, MCP offers it only with `include: [["api", "preview"]]`. `api preview …` without a leading `/` used to request the path `preview`; a request path starts with `/`. The new `.onMissing((field) => …)` chain method asks for a generated command's missing required values on a terminal outside CI: it gets a `MissingField` (`name`, `in`, `kind`, `choices`, `multiple`, `description`) and resolves to the value as text, for example from `@crustjs/prompts`' `input()` or `select()`, and the answers are bound with the input bound before, such as `--input`. An override's `paginate` on a result that is not a list leaves the operation out; in an app that adds the generated commands, `api --list` marks it and `crust build` fails (`paginate-needs-array`).

`api preview` prints the request a generated command or a request path would send, and sends nothing: `acme api preview users delete -- 42` (the command's own arguments and flags after `--`) or `acme api preview /users/42 -X DELETE`. It builds the request with the same plan and checks as the command, returns `{ method, url, headers, bodyKind, body, bound? }` through `.output()` (so `--json` and MCP get it as data), never calls `auth()`, a Context of the command, `.onConfirm()`, a `bind` function or `fetch`, shows a bound value as its `{name}` placeholder, and redacts `Authorization`, `Proxy-Authorization`, `Cookie` and `X-Api-Key` headers. Like `api`, MCP offers it only with `include: [["api", "preview"]]`. `api preview …` without a leading `/` used to request the path `preview`; a request path starts with `/`. An override's `paginate` on a result that is not a list leaves the operation out; in an app that adds the generated commands, `api --list` marks it and `crust build` fails (`paginate-needs-array`). `api`'s description now reads "Send a request to any endpoint, or browse the OpenAPI spec; prefer a specific command when one exists", as help, `search`, skills and `schema()` show it beside the generated commands.

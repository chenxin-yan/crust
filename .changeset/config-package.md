---
"@crustjs/config": minor
---

New package `@crustjs/config`: a CLI's settings as one typed Context read from JSON config files. `defineConfig({ name, global, project }).flags({...})` returns the `config` Context factory: the options say where the files are, and the chained `.flags()` declares the settings, as on a command. Each setting is the flag definition of a string, number or boolean flag; the Context owns those flags, so argv, `--input`, typed `run()` input and `env` resolve as for any flag, and what is still unset comes from the project file (`<name>.config.json`, the nearest from the working directory up), then the global file (`config.json` in `configDir(name)`), then the `default`. `required` is checked, and `default` applied, after the files; `flag: false` makes a setting read only from its variable and the files; such a setting reads `process.env`, so `run(path, input, { env })` does not reach it. `await ctx.config` is typed as the settings would be as flags. The files are read through `@crustjs/store` when a command first reads `ctx.config`, so `--help`, `--version` and commands that do not use the config never read them; a broken file fails only a command that reads the config. `config.global` is the typed store of the global file, for a `config set` command, and `config.jsonSchema()` returns the JSON Schema of a file. Needs no change to `@crustjs/core`.

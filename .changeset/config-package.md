---
"@crustjs/config": minor
---

New package `@crustjs/config`: a CLI's settings, read from JSON config files, as one typed Context per setting. `defineConfig({ name, global, project }).flags({...})` declares them: the options say where the files are, and the chained `.flags()` takes each setting as the flag definition of a string, number or boolean flag. It returns `settings` (each setting's Context factory, named after it), `extension` (`.extend(config.extension)` provides them all), `jsonSchema()`, and with `global` set, `global`, the typed store of the global file for a `config set` command. A command `.use()`s the settings it reads, takes only their flags, and reads each with `await ctx.<name>`: its flag (argv, `--input`, typed `run()` input), then its variable, then the project file (`<name>.config.json`, the nearest from the working directory up), then the global file (`config.json` in `configDir(name)`), then its `default`. `required` is checked, and `default` applied, after the files; `flag: false` makes a setting read only from its variable and the files, and such a setting reads `process.env`, so `run(path, input, { env })` does not reach it. The files are read through `@crustjs/store` once per invocation, when a command reads a setting its flag and variable did not give, so `--help`, `--version`, commands that use no setting, and settings given on the command line never read them. A test replaces one setting with its `.of()` double. Needs no change to `@crustjs/core`.

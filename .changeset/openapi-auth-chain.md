`auth` moves from `defineApi()`'s options to the handle's chain: `defineApi({ spec, baseUrl }).auth(bearerAuth(auth.token))`. `.auth()` reads the Contexts of the Context factories `.use()`d before it from `input.ctx`, and `bearerAuth()`'s resolver gets them as `ctx`: `.use(profile).auth(bearerAuth(async ({ ctx, signal, baseUrl }) => …))` puts `--profile` on the generated commands, `api`, and the commands that `.use(acme.client)`, and the app `.provide()`s `profile` before `.extend(acme.extension)`. Each `.auth()` makes a new `client`, which the handles after it share; a second `.auth()` replaces the first, and without one requests carry no credentials. `ApiClient` gains a second type parameter, the Contexts its `auth` reads, so a command that uses the client of another `.auth()` than the handle the app extends fails to compile when the two read Contexts of different types; a helper that takes any handle's client is generic in it. `ApiClientOptions` is no longer exported; `ApiAuth<Ctx>` types what `.auth()` takes. `api preview` sets up no Context.

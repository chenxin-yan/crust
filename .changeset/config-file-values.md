Flags can take values from a JSON config file. A flag declares its top-level key with `config: "org"` (non-empty, no `.`; a TypeScript error and a `DEFINITION` error otherwise), and `config({ name, project, user })` from `@crustjs/extensions` reads the project file found by walking up from the working directory and the user file `config.json` in `configDir(name)`; the project file wins key by key. Precedence is argv > bound input > `env` > config file > `default` under `execute()`, and bound input > `run()` input > `env` > config file > `default` under `run()`. `ctx.sources` reports `"config"`. A malformed file fails the command, `--help` included, naming the path; a wrong value names the file and key, never the value, and like an invalid environment value does not block `--help`. A `required` flag with a `config` key may be omitted from typed `run()` input and from command input (`--input`, `schema`, MCP). Help, man pages, `--llms`, and skills show `[config: org]`, and schema issues for env and config values name their origin, such as `flags.region (from $ACME_REGION)`. Extensions bind such values themselves with `ctx.bindInput({ flags }, { source: "config", from })`.

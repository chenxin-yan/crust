Every definition-shape validation now has exactly one home per path. Compile-time brands (`FIX_*`) own statically checkable mistakes — variadic placement, defaults outside literal `choices`, spelling/name collisions, reserved `__proto__` spellings, section audience exclusivity, dependency closure. Dynamically assembled definitions (config-built flags, args, commands, Extensions) fail loud with `DEFINITION` errors at the same composition points instead of silently misbehaving: duplicate or mid-tuple-variadic args, empty, `no-`-prefixed, or `__proto__` flag spellings, `__proto__` command names, duplicate sibling names at `.add()`, Extension flag collisions at prepare, async `parse` implementations behind a sync type (`PARSE`), out-of-`choices` dynamic defaults, and sections carrying both `only` and `except`. Runtime otherwise validates only what types cannot see: argv values, dynamic strings, recipe behavior, and transitive dependencies above an `.of()` cut (lazy `missing-context`).

New brands reject statically known empty flag spellings (`FIX_EMPTY_SPELLING`), empty command names at `.add()` (`FIX_EMPTY_NAME`), empty argument names (`FIX_EMPTY_NAME`), `.as()` renames landing on an own alias (`FIX_ALIAS_SHAPE`), and Extension collisions: flag spellings — declared or provided-Context-owned — against application flags (root or any subcommand's) and earlier Extensions at `.extend()`/`.add()` (`FIX_ALIAS_COLLISION`), pairwise owned-flag collisions within one Extension's `provides` tuple, and provided Context names replacing a Context already on the path (`FIX_DUPLICATE_CONTEXT`). Sealed command recipes cannot see ancestor spellings, so a recipe-provided Context flag colliding with an ancestor Context's flag fails at materialization.

Routing hardening: argv tokens matching inherited `Object.prototype` keys (`mycli constructor`, `mycli __proto__`) now report `COMMAND_NOT_FOUND` instead of crashing, and typed `run()` positional/flag lookups no longer resolve inherited keys.

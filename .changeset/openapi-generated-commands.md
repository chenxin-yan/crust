`defineApi()` generates a command per operation of the pinned spec: `new Crust("acme").extend(acme.extension).add(...acme.commands)`. Each is an ordinary app command in its first tag's group, with path parameters as arguments, typed query, header and top-level body field flags, the JSON body as a `--body` JSON flag whose schema stands alone for `schema` and MCP, and `.output()` with the response's JSON Schema; it prints the result for people and returns it. The handle's chain shapes them: `.use()` (Contexts for the callbacks, typed), `.onConfirm()`, `.each()` and `.override()` (one `OperationOverride` shape: `exclude`, `group`, `name`, `hidden`, `description`, `flagName`, `positional`, `bind`, `confirm`, `paginate`, `unwrap`, `outputSchema`, with names checked against a registered spec), and `.add(group, ...commands)`. An operation that does not fit is left out, and nothing throws for one operation. In an app that adds the generated commands, `api --list` marks it `[unavailable: <code>]`, and `crust build` fails, listing each problem with its fix, when configuration can settle it (a name clash, a stale or unknown override, positionals out of order, `confirm` without `.onConfirm()`) or when the document is not OpenAPI 3.0 or 3.1, and skips an operation no configuration can make a command (a required non-JSON body, an unsupported required parameter, a missing or shared operationId). `app.snapshot()` shows the generated commands for a snapshot test of the CLI's surface. `Operation` (what `.each()` receives) is an exported type. `crust build` writes the spec's data files to `<id>/` beside `spec.json`: an index of the generated root commands and top-level groups, which a built CLI reads at start, and the part of the spec the root commands and each top-level group need, which a command reads when it first runs, so start-up does not grow with the size of the API. Above twice the spec's size, those parts are not written and every command reads `spec.json`. A built CLI without its `<id>/` directory has no generated commands, and every invocation fails with a message naming the directory, without a stack. The build fails when the app's generated commands are not those of the handle whose `extension` it uses.

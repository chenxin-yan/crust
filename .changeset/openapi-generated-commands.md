`defineApi()` generates a command per operation of the pinned spec: `new Crust("acme").extend(acme.extension).add(...acme.commands)`. Each is an ordinary app command in its first tag's group, with path parameters as arguments, typed query, header and top-level body field flags, the JSON body as a `--body` JSON flag whose schema stands alone for `schema` and MCP, and `.output()` with the response's JSON Schema; it prints the result for people and returns it. The handle's chain shapes them: `.use()` (Contexts for the callbacks, typed), `.onConfirm()`, `.each()` and `.override()` (one `OperationOverride` shape: `exclude`, `group`, `name`, `hidden`, `description`, `flagName`, `positional`, `bind`, `confirm`, `paginate`, `unwrap`, `outputSchema`, with names checked against a registered spec), and `.add(group, ...commands)`. `acme.lint()` returns a `Diagnostic` for every problem in turning the spec into commands, from the document itself (an unsupported version, an operation without an operationId, an operationId several operations share) to the mapping (unsupported inputs, collisions, stale overrides); an operation with an error is left out, and `api --list` marks it `[unavailable: <code>]`. `acme.manifest()` is the sorted command surface with those errors, to snapshot in a test so a spec bump shows its CLI diff. `Operation` (what `.each()` receives) and `Diagnostic` are exported types. `crust build` writes the spec's data files to `<id>/` beside `spec.json`: an index of the generated root commands and top-level groups, which a built CLI reads at start, and the part of the spec the root commands and each top-level group need, which a command reads when it first runs, so start-up does not grow with the size of the API. Above twice the spec's size, those parts are not written and every command reads `spec.json`. A built CLI without its `<id>/` directory has no generated commands, and every invocation fails with a message naming the directory, without a stack. The build fails when the app's generated commands are not those of the handle whose `extension` it uses.

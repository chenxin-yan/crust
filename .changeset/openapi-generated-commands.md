`defineApi()` generates a command per operation of the pinned spec: `new Crust("acme").extend(acme.extension).add(...acme.commands)`. Each is an ordinary app command in its first tag's group, with path parameters as arguments, typed query, header and top-level body field flags, the JSON body as a `--body` JSON flag whose schema stands alone for `schema` and MCP, and `.output()` with the response's JSON Schema; it prints the result for people and returns it. The handle's chain shapes them: `.use()` (Contexts for the callbacks, typed), `.onConfirm()`, `.each()` and `.override()` (one `OperationOverride` shape: `exclude`, `group`, `name`, `hidden`, `description`, `flagName`, `positional`, `bind`, `confirm`, `paginate`, `unwrap`, `outputSchema`, with names checked against a registered spec), and `.add(group, ...commands)`. `acme.lint()` returns a `Diagnostic` for every problem in turning the spec into commands, from the document itself (an unsupported version, an operation without an operationId, an operationId several operations share) to the mapping (unsupported inputs, collisions, stale overrides); an operation with an error is left out, and `api --list` marks it `[unavailable: <code>]`. `acme.manifest()` is the sorted command surface with those errors, to snapshot in a test so a spec bump shows its CLI diff. `Operation` (what `.each()` receives) and `Diagnostic` are exported types. A built CLI that adds the generated commands reads its `<id>/spec.json` at start.

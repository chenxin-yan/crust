## Decisions: what was and was not adopted

Prioritize falsifiable assertions, correct failure attribution and isolation. Do not equate shared implementation with redundant public behavior. Public exports/output, parser input variants, independent prompt defaults, build-hook order and cross-package seams remain useful regression contracts.

**First implementation:** repaired callback-only assertions and lazy-context false positives; corrected the unreachable double-extend fixture; converted type wrappers; fixed execute capture to use returned status; drove prompts through existing fake IO/readline; tightened masking and output; consolidated repeated prompt/default/spinner/notifier cases; replaced fish's discarded smoke output with completion probes. Preserved man→skills preceding-build-hook integration, all meaningful type constraints and security boundaries. `.oxlintrc.json` adds only the `.test-d.ts` test override.

**Second implementation:** awaited six scaffold rejections; install-step fixture now records executed argv/cwd instead of its own input file; all package builds must succeed before staging assertions; removed the silent prior-test-dependent binary execution case while retaining independent host execution; repaired actual skills conflict continuation with a dangling link; pinned manifest omission and relative navigation; consolidated duplicate store validation/cause checks; separated store/utils type checks; made style expectations independent/exact; moved resolver/source fixtures out of source directories. Supervisor-approved surgical MDX fixes remove a conflicting reused-command alias and await a queued prompt answer before inspecting the submitted screen. The three-level deep skill overview link is `../../../SKILL.md`, not the raw audit's incorrectly suggested `../../SKILL.md`.

**Configuration:** CI now runs `bun test scripts/*.test.ts` (Bun's bare `scripts` is a substring filter, not directory selection). Root `test` is unchanged so `bun run test --force` forwarding remains valid; root-only script tests are still a separate explicit command. Current docs parity checks use `apps/docs/tests/cli-reference.test.ts`; the parent's removal of the compiled-docs smoke and `check:output` is preserved.

**Rejected/deferred trims:** no blanket deletion of manifest/core-help formatting pass-throughs, lifecycle/multiple-store integration, CLI aliases, initializer public exports, resolver generated-code guards, or the create end-to-end test. No mass style-suite relocation/table inflation or padding/primitive grouping purely to reduce case counts. Shared skills fixture extraction, import/style cleanups and optional RuleTester reporting changes were unnecessary churn. Optional new branch tests are listed separately below, not silently described as implemented.

# Model Contexts as command dependencies

A Context is a named dependency attached with `.provide()`, inherited by descendant commands, and constructed only for the resolved command path. Every `context()` definition returns a factory that must be invoked, including zero-option factories, so the API reads as `context("db", factory)` → `.provide(db(...))` → `ctx.db` without runtime function-arity detection. Context factories receive only their options, and duplicate names on a command path are definition errors; beta includes neither a Context dependency graph nor order-dependent access to previously constructed Contexts. Core disposes values implementing `Symbol.dispose` or `Symbol.asyncDispose` in reverse construction order after success or failure, using the runtime's native resource protocol instead of a Crust-specific teardown API. This keeps command-specific work lazy and the contract narrow rather than treating Contexts as application singletons, arbitrary bags, replaceable bindings, or a dependency-injection container.

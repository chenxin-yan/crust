# Separate programmatic run from terminal execution

Crust uses `.handle(handler)` to define a Command Handler, `.run(argv)` for programmatic invocation, and `.execute()` as the terminal CLI boundary. Command-level `preRun` and `postRun` hooks are removed: setup and cleanup belong to Contexts, while cross-cutting behavior belongs to Extensions. `run()` accepts injectable `stdout(text)` and `stderr(text)` callbacks that are also available to Command Handlers and Extensions, resolves with no value after successful cleanup, and throws the original definition, parse, Context, or handler failure without rendering that failure or changing process status. `execute()` invokes the same pipeline with terminal arguments, renders a failure once, sets `process.exitCode` (`1`, or `130` for a standard `AbortError` cancellation), and resolves rather than terminating the process. Prompt cancellation uses `DOMException(..., "AbortError")` instead of a prompt-specific error-name convention. This adds a testable embedding path without overloading one method with configuration and invocation or risking truncated output and cleanup.

# Selection research and version-matched implementation notes

Survey snapshot: **2026-09-20**. Sources below are primary package metadata, official documentation and the exact installed package artifacts. Metadata engines/types claims are not execution evidence. Installed versions are independently pinned in `package.json`/`package-lock.json`; `build.ts` checks installed versions. The benchmark's source and bundle conformance are the execution evidence.

## Broader survey / reserves

The initial research considered roughly 28 meaningful candidates. The cap favors familiar frameworks, typed builders and parser/framework pairs, not maintenance/security judgments. The implementation **did not widen the pool** after conformance exclusions.

- [Optique `@optique/core` 1.3.0](https://registry.npmjs.org/@optique%2fcore/1.3.0): typed combinators; core doesn't execute application commands, unlike `@optique/run`. Strong future expansion, not measured here. [Official overview](https://github.com/dahlia/optique).
- [Effect CLI 0.77.2](https://registry.npmjs.org/@effect%2fcli/0.77.2): distinct Effect execution/platform layer; peers and Node/Bun platform setup must be counted. [Versioned docs](https://raw.githubusercontent.com/Effect-TS/effect/%40effect%2Fcli%400.77.2/packages/cli/README.md).
- [Cliffy `@cliffy/command` 1.3.1](https://jsr.io/@cliffy/command/meta.json): current JSR metadata explicitly supports **Node and Bun**, not Deno-only. JSR installation/resolution is a reproducibility consideration, not grounds for a compatibility claim. [Toolkit](https://github.com/c4spar/cliffy). Its `@cliffy/flags` is another parser counterpart.
- [command-line-args 6.0.2](https://registry.npmjs.org/command-line-args/6.0.2): schema parser with separate help package and external consumer types; staged command parsing rather than a native command tree. [Docs](https://github.com/75lb/command-line-args).
- [Meow 14.1.0](https://registry.npmjs.org/meow/14.1.0): typed CLI/helper wrapper, overlaps parser/helper coverage rather than adding native command routing. [Docs](https://github.com/sindresorhus/meow).
- [ts-command-line-args 2.5.1](https://registry.npmjs.org/ts-command-line-args/2.5.1): typed wrapper around command-line-args 5.x, not an independent engine. [Docs](https://github.com/Roaders/ts-command-line-args).
- [nest-commander 3.21.0](https://registry.npmjs.org/nest-commander/3.21.0): Nest decorators/lifecycle around Commander 11.1.0 and Nest peers; different workload from a tiny plain CLI. [Docs](https://nest-commander.jaymcdoniel.dev/en/features/commander/).
- [JSR `@std/cli` 1.0.32](https://jsr.io/@std/cli/meta.json), subpath `parse-args`: TS standard-library parser; package-level Bun unknown marker does not establish pure subpath compatibility either way. [API](https://jsr.io/@std/cli/doc/parse-args/).
- [Peowly 2.0.1](https://registry.npmjs.org/peowly/2.0.1): typed parseArgs helper/help layer, not an independent tokenizer. [Docs](https://github.com/voxpelli/peowly).
- [args-tokens 0.29.0](https://registry.npmjs.org/args-tokens/0.29.0): Gunshi's underlying token parser/combinators, another possible framework/parser pair. [Gunshi attribution](https://github.com/kazupon/gunshi).
- Exact npm name [`typescript-commander`](https://registry.npmjs.org/typescript-commander) returned **Not Found** during research. No invented version or silent substitution.

## Interpretation and remaining uncertainty

The README specifies the measurable contract/lifecycle. TS consumer checking, runtime conformance, and bundle isolation are separate checks; metadata can't substitute for them. Published unpacked package size is not a fixture bundle size. TypeScript source language doesn't guarantee consumer declarations; consumer declarations don't prove precise inference. Root `skipLibCheck`/local `skipLibCheck` bypass dependency internals but not fixture use-site checking.

Native number semantics differ, so every adapter requests textual numbers and the same finite-number application validation instead of pretending native coercion is identical. Core's built-in number parser accepts Infinity; the fixture's shared application guard rejects it. All schema construction is inside every warm invocation, including fresh Clipanion registration/state machine compilation. Nothing is cached selectively to favor Crust.

An exploratory rejection check for `--region --force` showed Commander intentionally consumes `--force` as a required option's string value, while some other parsers treat it as an option. Option-like text was already outside the bounded contract; that ambiguous argv is not a shared rejection test. Missing-value checks use end-of-argv, and explicitly empty values are still rejected.

Raw smoke output is harness evidence only; no performance conclusion is drawn here. Single-file Node-target bundles run on both supplied runtimes; Bun-target CommonJS builtin bridges were observed to be runtime-specific, which is why one portable target is used uniformly. Source APIs not exercised by these fixtures (help, plugins, discovery, completion, assets) remain outside conclusions. The final expensive run belongs after independent review on an otherwise idle machine.

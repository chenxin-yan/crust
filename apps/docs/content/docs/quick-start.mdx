## Create a new project

<Steps>
<Step>
### Create a project

```npm
npx create-crust@latest my-cli
cd my-cli
```

<Files>
  <Folder name="my-cli" defaultOpen>
    <Folder name="src" defaultOpen>
      <File name="cli.ts" />
    </Folder>
    <File name="package.json" />
    <File name="tsconfig.json" />
    <File name="README.md" />
    <File name=".gitignore" />
  </Folder>
</Files>

</Step>
<Step>
### Run it

```npm
npm run dev -- Ada --greet Welcome
# Welcome, Ada!
```

The `help()` extension generates usage from the same definitions:

```npm
npm run dev -- --help
```

```
my-cli - A CLI built with Crust

Usage:
  my-cli [name] [options]

Arguments:
  [name]             Your name [default: "world"]

Options:
  -g, --greet                  Greeting to use [default: "Hello"]
  -v, --version                Show version number
  -h, --help                   Show help
```

</Step>
<Step>
### Add a subcommand

Chain `.command()` onto the root:

<include lang="ts" meta='title="src/cli.ts"'>
  ../../examples/quick-start/subcommand.ts
</include>

```npm
npm run dev -- build --minify
# minify: true

npm run dev -- Ada
# Hello, Ada!
```

`my-cli build` routes to the subcommand; anything else still reaches the root action. Inline `.command()` suits app-local commands. Move to `defineCommand` and [split files](/docs/guide/commands#split-across-files) when a command needs its own file or reuse.

</Step>
<Step>
### Build it

```npm
npm run build
npm run start Ada
```

`crust build` stages the publishable npm package(s) in `.crust/`. See [Build and distribution](/docs/guide/build-and-distribution) for cross-platform targets and the `.crust/` layout.

<Callout type="info">
  Both `create-crust` and `crust` CLI are built with crust. If you would like to see crust in
  action. Check out the crust repo on GitHub
</Callout>

</Step>
</Steps>

## Manual setup

To add Crust without the scaffolder, follow the steps below from your project directory. If configuration files already exist, merge the settings rather than replacing them.

<Steps>
<Step>
### Choose your runtime

The runtime runs your CLI; the package manager installs dependencies. For Bun and Node.js, use whichever package-manager tab you prefer.

<Tabs items={["Bun", "Node.js", "Deno"]} groupId="quick-start-runtime" persist>
<Tab value="Bun">

Use Bun 1.4 or later.

```npm
npm install @crustjs/core @crustjs/extensions
npm install -D typescript @types/bun
```

Set the module format in `package.json`, keeping the dependencies added above:

```json title="package.json (partial)"
{
  "type": "module"
}
```

```json title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ESNext",
    "lib": ["ESNext"],
    "types": ["bun"],
    "module": "Preserve",
    "moduleResolution": "bundler",
    "allowImportingTsExtensions": true,
    "verbatimModuleSyntax": true,
    "noEmit": true,
    "strict": true,
    "skipLibCheck": true
  },
  "include": ["src"]
}
```

</Tab>
<Tab value="Node.js">

Use Node.js 22.18 or later to run TypeScript directly, without a separate runner.

```npm
npm install @crustjs/core @crustjs/extensions
npm install -D typescript @types/node@22
```

Set the module format in `package.json`, keeping the dependencies added above:

```json title="package.json (partial)"
{
  "type": "module"
}
```

```json title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ESNext",
    "lib": ["ESNext"],
    "types": ["node"],
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "allowImportingTsExtensions": true,
    "verbatimModuleSyntax": true,
    "erasableSyntaxOnly": true,
    "noEmit": true,
    "strict": true,
    "skipLibCheck": true
  },
  "include": ["src"]
}
```

</Tab>
<Tab value="Deno">

Use Deno 2.8 or later. Deno installs npm packages and checks TypeScript itself:

```sh
deno add npm:@crustjs/core npm:@crustjs/extensions
```

For a new Deno-only project, this creates the dependency mappings in `deno.json`; no `package.json`, `tsconfig.json`, or separate TypeScript installation is needed. In an existing npm-based project, Deno can use its `package.json` dependencies instead.

If your project already has a `tsconfig.json`, preserve Deno's globals with `"lib": ["ESNext", "deno.window"]` and `"types": []` in its `compilerOptions`.

</Tab>
</Tabs>

</Step>
<Step>
### Create the entrypoint

Create `src/cli.ts`. The same code works on all three runtimes:

<include lang="ts" meta='title="src/cli.ts"'>
  ../../examples/quick-start/manual.ts
</include>

</Step>
<Step>
### Run and check it

<Tabs items={["Bun", "Node.js", "Deno"]} groupId="quick-start-runtime" persist>
<Tab value="Bun">

```sh
bun run src/cli.ts Ada
bun run src/cli.ts --help
bunx tsc --noEmit
```

</Tab>
<Tab value="Node.js">

```sh
node src/cli.ts Ada
node src/cli.ts --help
npx tsc --noEmit
```

</Tab>
<Tab value="Deno">

```sh
deno run --allow-env src/cli.ts Ada
deno run --allow-env src/cli.ts --help
deno check src/cli.ts
```

`--allow-env` lets Crust read environment variables for execution and terminal styling. As your CLI adds file, network, or subprocess access, grant the additional [Deno permissions](/docs/guide/runtime-support#deno-permissions) it needs.

</Tab>
</Tabs>

</Step>
</Steps>

### Build when ready

You don't need `@crustjs/crust` to run the source. When you're ready to distribute your CLI, follow [Build and distribution](/docs/guide/build-and-distribution#set-up-packagejson) to add the build tooling and package configuration.

## Create a new project

<Steps>
<Step>
### Create a project

```npm
npx create-crust@latest my-cli
cd my-cli
```

Pick a package manager once; the tabs remember it across the docs. `create-crust` detects the package manager that launched it and installs dependencies with the same one. The scaffolder creates:

<Files>
  <Folder name="my-cli" defaultOpen>
    <Folder name="src" defaultOpen>
      <File name="cli.ts" />
    </Folder>
    <File name="package.json" />
    <File name="tsconfig.json" />
    <File name="README.md" />
    <File name=".gitignore" />
  </Folder>
</Files>

</Step>
<Step>
### Run it

The generated `dev` script is `bun run src/cli.ts`, so [Bun](https://bun.sh) runs the CLI whichever package manager installed it.

```sh
bun run dev Ada --greet Welcome
# Welcome, Ada!
```

The `help()` extension generates usage from the same definitions:

```sh
bun run dev --help
```

```
my-cli - A CLI built with Crust

Usage:
  my-cli [name] [options]

Arguments:
  [name]             Your name [default: "world"]

Options:
  -g, --greet                  Greeting to use [default: "Hello"]
  -v, --version                Show version number
  -h, --help                   Show help
```

</Step>
<Step>
### Add a subcommand

Chain `.command()` onto the root:

<include lang="ts" meta='title="src/cli.ts"'>
  ../../examples/quick-start/subcommand.ts
</include>

```sh
bun run dev build --minify
# minify: true

bun run dev Ada
# Hello, Ada!
```

`my-cli build` routes to the subcommand; anything else still reaches the root action. Inline `.command()` suits app-local commands. Move to `defineCommand` and [split files](/docs/guide/commands#split-across-files) when a command needs its own file or reuse.

</Step>
<Step>
### Build it

```sh
bun run build
bun run start Ada
```

Standalone mode compiles a binary to `dist/cli`; runtime mode bundles to `dist/cli.js`. See [Build and distribution](/docs/guide/build-and-distribution) for cross-platform targets and npm packaging.

<Callout type="info">
  Both `create-crust` and `crust` CLI are built with crust. If you would like to see crust in
  action. Check out the crust repo on GitHub
</Callout>

</Step>
</Steps>

## Add to an existing project

<Steps>
<Step>
### Install

```npm
npm install @crustjs/core @crustjs/extensions
npm install -D @crustjs/crust
```

`@crustjs/crust` is only needed for `crust build`. Skip it if you bundle with `bun build` or run the source directly. Deno projects install with `deno add npm:`; see [Runtime support](/docs/guide/runtime-support).

</Step>
<Step>
### Configure `package.json`

```json title="package.json"
{
  "type": "module",
  "bin": { "my-cli": "dist/cli" },
  "scripts": {
    "dev": "bun run src/cli.ts",
    "build": "crust build",
    "start": "./dist/cli"
  }
}
```

`dev` runs the TypeScript source with Bun regardless of which package manager installed the dependencies. `crust build` reads `src/cli.ts` and writes to `dist` by default; pass `--entry` for a different file. `bin` points at the built resolver so `bun link` and npm installs expose the command.

</Step>
<Step>
### Configure `tsconfig.json`

The scaffolder ships this config. Match `types`, `module`, and `moduleResolution` if you merge into an existing one; the rest is strictness.

<include lang="json" meta='title="tsconfig.json"'>
  ../../../../packages/create-crust/templates/base/tsconfig.json
</include>

</Step>
<Step>
### Add the entrypoint

Create `src/cli.ts` with the file from [Add a subcommand](#add-a-subcommand), then:

```sh
bun run dev --help
```

</Step>
</Steps>

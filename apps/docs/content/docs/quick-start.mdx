## Create a new project

<Steps>
<Step>
### Create a project

```npm
npx create-crust@latest my-cli
cd my-cli
```

Pick a package manager once; the tabs remember it across the docs. `create-crust` detects the package manager that launched it and installs dependencies with the same one. It also asks which runtime the project develops and builds for: Bun (the default), Node.js, or Deno; pass `--runtime bun|node|deno` to skip the prompt. The scaffolder creates:

<Files>
  <Folder name="my-cli" defaultOpen>
    <Folder name="src" defaultOpen>
      <File name="cli.ts" />
    </Folder>
    <File name="package.json" />
    <File name="tsconfig.json" />
    <File name="README.md" />
    <File name=".gitignore" />
  </Folder>
</Files>

</Step>
<Step>
### Run it

The generated `dev` script runs `src/cli.ts` with the runtime you picked (`bun run`, `node`, or `deno run -A`), whichever package manager installed the dependencies.

```npm
npm run dev -- Ada --greet Welcome
# Welcome, Ada!
```

The `help()` extension generates usage from the same definitions:

```npm
npm run dev -- --help
```

```
my-cli - A CLI built with Crust

Usage:
  my-cli [name] [options]

Arguments:
  [name]             Your name [default: "world"]

Options:
  -g, --greet                  Greeting to use [default: "Hello"]
  -v, --version                Show version number
  -h, --help                   Show help
```

</Step>
<Step>
### Add a subcommand

Chain `.command()` onto the root:

<include lang="ts" meta='title="src/cli.ts"'>
  ../../examples/quick-start/subcommand.ts
</include>

```npm
npm run dev -- build --minify
# minify: true

npm run dev -- Ada
# Hello, Ada!
```

`my-cli build` routes to the subcommand; anything else still reaches the root action. Inline `.command()` suits app-local commands. Move to `defineCommand` and [split files](/docs/guide/commands#split-across-files) when a command needs its own file or reuse.

</Step>
<Step>
### Build it

```npm
npm run build
npm run start Ada
```

Bun and Deno projects compile standalone binaries behind a `dist/cli` resolver; Node projects bundle to `dist/cli.js`. See [Build and distribution](/docs/guide/build-and-distribution) for cross-platform targets and npm packaging.

<Callout type="info">
  Both `create-crust` and `crust` CLI are built with crust. If you would like to see crust in
  action. Check out the crust repo on GitHub
</Callout>

</Step>
</Steps>

## Add to an existing project

<Steps>
<Step>
### Install

```npm
npm install @crustjs/core @crustjs/extensions
npm install -D @crustjs/crust
```

`@crustjs/crust` is only needed for `crust build`. Skip it if you bundle another way or run the source directly. Deno projects install with `deno add npm:`; see [Runtime support](/docs/guide/runtime-support).

</Step>
<Step>
### Configure `package.json`

```json title="package.json"
{
  "type": "module",
  "bin": { "my-cli": "dist/cli" },
  "scripts": {
    "dev": "bun run src/cli.ts",
    "build": "crust build",
    "start": "./dist/cli"
  }
}
```

This is the Bun shape; `dev` runs the TypeScript source with Bun regardless of which package manager installed the dependencies. `crust build` reads `src/cli.ts` and writes to `dist` by default; pass `--entry` for a different file. `bin` points at the built resolver so `npm link` and npm installs expose the command. Node and Deno projects add `"crust": { "runtime": "node" }` or `"deno"` and use their own `dev` and `bin` values; see [Set up `package.json`](/docs/guide/build-and-distribution#set-up-packagejson).

</Step>
<Step>
### Configure `tsconfig.json`

The scaffolder ships this config for Bun. Match `types`, `module`, and `moduleResolution` if you merge into an existing one; the rest is strictness. Node projects use `"types": ["node"]`; Deno projects use `"lib": ["ESNext", "deno.window"]` and `"types": []` because `deno check` reads this file and a supplied `lib` replaces Deno's own globals.

```json title="tsconfig.json"
{
  "compilerOptions": {
    "lib": ["ESNext"],
    "types": ["bun"],
    "target": "ESNext",
    "module": "Preserve",
    "moduleDetection": "force",
    "moduleResolution": "bundler",
    "allowImportingTsExtensions": true,
    "verbatimModuleSyntax": true,
    "noEmit": true,
    "strict": true,
    "skipLibCheck": true,
    "noFallthroughCasesInSwitch": true,
    "noUncheckedIndexedAccess": true
  },
  "include": ["src"]
}
```

</Step>
<Step>
### Add the entrypoint

Create `src/cli.ts` with the file from [Add a subcommand](#add-a-subcommand), then:

```npm
npm run dev -- --help
```

</Step>
</Steps>

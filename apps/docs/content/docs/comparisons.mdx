---
title: Comparisons
description: Compare Crust's command-authoring model with other CLI frameworks.
---

Crust is designed for Bun and TypeScript. Its distinguishing API choices are immutable command builders, inferred Command Handler inputs, app-wide Extensions, lazy typed Contexts, and Standard Schema support.

```ts
import { Crust } from "@crustjs/core";
import { help } from "@crustjs/extensions";

const app = new Crust("deploy")
  .extend(help())
  .args([{ name: "target", type: "string", required: true }])
  .flags({ dryRun: { type: "boolean", short: "d" } })
  .handle(({ args, flags, stdout }) => {
    stdout(`${flags.dryRun ? "Preview" : "Deploy"}: ${args.target}`);
  });

await app.execute();
```

| Concern                 | Crust approach                                               |
| ----------------------- | ------------------------------------------------------------ |
| Runtime                 | Bun-native, ESM                                              |
| Command definitions     | Immutable fluent builders                                    |
| Type inference          | Derived from argument, flag, schema, and Context definitions |
| Reusable capabilities   | Root-only `.extend()` with plain Extension values            |
| Command dependencies    | Lazy `.provide()` Contexts inherited by descendants          |
| Validation              | Built-ins or any Standard Schema on the definition           |
| Programmatic invocation | `.run(argv, io)` throws original errors                      |
| Terminal invocation     | `.execute()` renders errors and sets exit status             |
| Distribution            | Standalone Bun executables or runtime packages               |

Choose based on your runtime, distribution needs, and preferred authoring model. Crust deliberately makes Bun and TypeScript part of its contract rather than abstracting over every JavaScript runtime.

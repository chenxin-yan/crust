## `CrustError`

Framework definition, routing, parsing, and validation failures use `CrustError`.

```ts
class CrustError<C extends CrustErrorCode = CrustErrorCode> extends Error {
  readonly code: C;
  readonly details: CrustErrorDetails<C>;
  cause?: unknown;

  constructor(
    code: C,
    message: string,
    ...details: undefined extends CrustErrorDetails<C>
      ? [] | [CrustErrorDetails<C>]
      : [CrustErrorDetails<C>]
  );

  is<T extends CrustErrorCode>(code: T): this is CrustError<T>;
  withCause(cause: unknown): this;
  toJSON(): { code: C; message: string; details: CrustErrorDetails<C> };
}
```

Use `code` or `.is(code)` instead of matching messages. The constructor's details argument is optional for codes whose entry in `CrustErrorDetailsMap` includes `undefined`; `COMMAND_NOT_FOUND` requires its details payload.

```ts
try {
  await app.run(path, input);
} catch (error) {
  if (error instanceof CrustError && error.is("VALIDATION")) {
    for (const issue of error.details?.issues ?? []) {
      console.error(`${issue.path}: ${issue.message}`);
    }
  }
}
```

## Codes

```ts
type CrustErrorCode = "DEFINITION" | "PARSE" | "VALIDATION" | "COMMAND_NOT_FOUND";
```

| Code                | Meaning                                                                                              |
| ------------------- | ---------------------------------------------------------------------------------------------------- |
| `DEFINITION`        | Invalid application definition: empty names, collisions, invalid combinations, or other setup errors |
| `PARSE`             | Argv syntax or built-in value parsing failed                                                         |
| `VALIDATION`        | Required-value or Standard Schema validation failed                                                  |
| `COMMAND_NOT_FOUND` | A token did not match a child command name or alias                                                  |

## Propagation boundaries

`.run(path, input, io)` throws the original error without rendering it or changing process status. Context setup and Command Action failures are not wrapped in `CrustError`. Pulling an unprovided Context is a `DEFINITION` `CrustError` with `details.reason === "missing-context"`; its message names the Context and recommends `.provide()`. Pulling a flag-owning Context before validation reports `flags-before-validation`.

```ts
const failure = new Error("database unavailable");
const app = new Crust("my-cli").action(() => {
  throw failure;
});

await app.run([]); // throws the same `failure` object
```

`.execute()` renders a failure once, sets `process.exitCode = 1`, and resolves. Extension `onError` hooks can render or delegate presentation but cannot turn the invocation into success.

A prompt cancellation is a standard `DOMException` named `AbortError`. Programmatic `.run()` throws it. Terminal `.execute()` sets exit code `130` and offers it to Extension `onError` hooks; the default renderer stays silent when no hook claims it.

```ts
try {
  await app.run(path, input);
} catch (error) {
  if (error instanceof Error && error.name === "AbortError") {
    // cancellation
  }
}
```

`toJSON()` returns `code`, `message`, and `details`. It intentionally omits `cause`.

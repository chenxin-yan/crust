All types on this page are exported from `@crustjs/core`.

## Definition types

### `ValueType`

```ts
type ValueType = "string" | "number" | "boolean" | "url" | "path" | "json";
```

| Value     | Runtime value                        |
| --------- | ------------------------------------ |
| `string`  | `string`                             |
| `number`  | `number`                             |
| `boolean` | `boolean`                            |
| `url`     | `URL`                                |
| `path`    | Absolute `string`, with `~` expanded |
| `json`    | `unknown` from `JSON.parse()`        |

### `ArgDef`

```ts
type ArgsDef = readonly ArgDef[];
```

Core-value argument definitions share these fields:

| Field         | Type                       | Description                                                       |
| ------------- | -------------------------- | ----------------------------------------------------------------- |
| `name`        | `string`                   | Key in the Command Handler's `args` object                        |
| `type`        | `ValueType`                | Required for a typed core value; omit only for raw or schema mode |
| `description` | `string`                   | Help text                                                         |
| `required`    | `true`                     | Reject an absent value                                            |
| `variadic`    | `true`                     | Collect remaining tokens; allowed only on the final argument      |
| `default`     | Value matching `type`      | Value used when absent                                            |
| `choices`     | `readonly string[]`        | Allowed values for string arguments                               |
| `parse`       | `(raw: string) => unknown` | Synchronous transform for string arguments                        |

A variadic value is always an array. `parse` runs once per element for a variadic string argument.

```ts
const args = [
  { name: "target", type: "string", choices: ["browser", "node"] },
  { name: "files", type: "path", variadic: true },
] as const satisfies ArgsDef;
```

A schema-backed argument has `name`, optional `description` and `variadic`, and a Standard Schema:

```ts
const args = [{ name: "port", schema: z.coerce.number().int().min(1) }] as const satisfies ArgsDef;
```

The schema receives `string | undefined`, or `string[]` for a variadic argument. It exclusively owns coercion, defaults, requiredness, choices, and validation, so `type`, `required`, `default`, `choices`, and `parse` are not available in this variant. The schema's output type reaches the Command Handler.

An argument with neither `type` nor `schema` is a raw definition and returns the raw token value.

### `FlagDef`

```ts
type FlagsDef = Record<string, FlagDef>;
```

Core-value flag definitions support:

| Field         | Type                       | Description                                     |
| ------------- | -------------------------- | ----------------------------------------------- |
| `type`        | `ValueType`                | Token grammar and value conversion              |
| `description` | `string`                   | Help text                                       |
| `short`       | `string`                   | Short alias such as `"v"` for `-v`              |
| `aliases`     | `string[]`                 | Additional long aliases                         |
| `required`    | `true`                     | Reject an absent value                          |
| `inherit`     | `true`                     | Make the flag available to descendants          |
| `multiple`    | `true`                     | Collect repeated occurrences into an array      |
| `default`     | Value matching `type`      | Value used when absent                          |
| `choices`     | `readonly string[]`        | Allowed values for string flags                 |
| `parse`       | `(raw: string) => unknown` | Synchronous transform for string flags          |
| `noNegate`    | `true`                     | Disable generated `--no-name` for boolean flags |

```ts
const flags = {
  verbose: { type: "boolean", short: "v", inherit: true },
  include: { type: "string", multiple: true },
  port: { type: "number", default: 3000 },
} satisfies FlagsDef;
```

Schema-backed flags support `type: "string" | "boolean"`, `schema`, and the syntax fields `description`, `short`, `aliases`, `inherit`, and `multiple`. Boolean schema flags also support `noNegate`. `type` only declares token consumption: a string flag consumes a token; a boolean flag is a toggle.

```ts
const flags = {
  port: { type: "string", schema: z.coerce.number().int().min(1) },
  enabled: { type: "boolean", schema: z.boolean().default(false) },
} satisfies FlagsDef;
```

The schema receives the raw `string | undefined` or `boolean | undefined`; with `multiple: true` it receives the corresponding array. `required`, `default`, `choices`, and `parse` cannot be mixed into schema mode.

### `CommandMeta`

```ts
interface CommandMeta {
  name: string;
  description?: string;
  usage?: string;
  aliases?: readonly string[];
  hidden?: boolean;
}
```

`hidden` removes a command from user-facing help, completion, man-page, typo-suggestion, and skill listings without disabling direct routing.

## Command Snapshots

Command Snapshots are readonly, serializable descriptions. They contain no Command Handler, parser, schema, or Context functions and are deeply frozen at public boundaries.

### `CommandSnapshot`

```ts
interface CommandSnapshot {
  readonly meta: Readonly<CommandMeta>;
  readonly hasHandler: boolean;
  readonly args: readonly ArgSnapshot[];
  readonly flags: Readonly<Record<string, FlagSnapshot>>;
  readonly subCommands: Readonly<Record<string, CommandSnapshot>>;
}
```

`flags` contains effective inherited and local flags. Command Handlers, Extension hooks, and `COMMAND_NOT_FOUND` details receive snapshots rather than mutable runtime internals.

### `ArgSnapshot`

```ts
interface ArgSnapshot {
  readonly name: string;
  readonly type?: ValueType;
  readonly description?: string;
  readonly required?: boolean;
  readonly variadic?: boolean;
  readonly choices?: readonly string[];
  readonly default?: unknown;
}
```

### `FlagSnapshot`

```ts
interface FlagSnapshot {
  readonly type: ValueType;
  readonly description?: string;
  readonly short?: string;
  readonly aliases?: readonly string[];
  readonly required?: boolean;
  readonly inherit?: boolean;
  readonly multiple?: boolean;
  readonly noNegate?: boolean;
  readonly choices?: readonly string[];
  readonly default?: unknown;
}
```

Snapshots omit schemas and parse functions. `URL` defaults become strings, and array defaults are copied and frozen.

## Command Handler context

### `CrustCommandContext<A, F, Ctx>`

```ts
interface CrustCommandContext<A, F, Ctx> {
  args: InferArgs<A>;
  flags: InferFlags<F>;
  ctx: Readonly<Ctx>;
  rawArgs: string[];
  command: CommandSnapshot;
  stdout: (text: string) => void;
  stderr: (text: string) => void;
}
```

`InferArgs` and `InferFlags` are internal type plumbing, not root exports. `.args()`, `.flags()`, and `.provide()` infer these fields without explicit generic arguments.

## Context types

### `ContextFactory`

```ts
interface ContextFactory<Name extends string, Options, Value> {
  (options: Options): ContextInstance<Name, Value>;
}
```

`context(name, setup)` always returns a factory. Invoke it even when `Options` is `void`.

### `ContextInstance`

```ts
interface ContextInstance<Name extends string = string, Value = unknown> {
  readonly kind: "context";
  readonly name: Name;
  setup(): Value | Promise<Value>;
}
```

Attach an instance with `.provide()`. Core constructs it lazily on the resolved path.

### `ContextMap`

```ts
type ContextMap = Record<string, unknown>;
```

The map shape used for inferred `ctx` values.

## Extension types

### `ExtensionConfig`

```ts
interface ExtensionConfig {
  readonly flags?: Readonly<Record<string, ExtensionFlagDef>>;
  readonly commands?: readonly ExtensionCommand[];
  readonly intercept?: ExtensionIntercept;
  readonly handleError?: ExtensionErrorHandler;
}
```

### `Extension`

```ts
interface Extension extends ExtensionConfig {
  readonly name: string;
}
```

`extension(name, config)` returns a frozen structural value.

### `ExtensionFlagDef`

```ts
type ExtensionFlagDef = FlagDef & { readonly recursive?: boolean };
```

An Extension owns contributed flags. `recursive` defaults to `true`; `false` contributes the flag only to the root.

### `ExtensionCommand`

A structural type satisfied by a configured `Crust` builder. Extension commands are contributed at the application root.

### `ExtensionContext`

```ts
interface ExtensionContext {
  readonly argv: readonly string[];
  readonly rootCommand: CommandSnapshot;
  readonly command: CommandSnapshot;
  readonly commandPath: readonly string[];
  readonly args: Readonly<Record<string, unknown>>;
  readonly flags: Readonly<Record<string, unknown>>;
  readonly rawArgs: readonly string[];
  readonly stdout: (text: string) => void;
  readonly stderr: (text: string) => void;
}
```

`args` and `flags` are syntax-parsed values. Extension hooks do not alter application Command Handler types.

### Hook types

```ts
type ExtensionNext = () => Promise<void>;

type ExtensionIntercept = (context: ExtensionContext, next: ExtensionNext) => void | Promise<void>;

type ExtensionErrorHandler = (
  error: unknown,
  context: ExtensionContext,
  next: ExtensionNext,
) => void | Promise<void>;
```

`intercept` runs after routing and syntax parsing but before application value validation and Context construction. It short-circuits by not calling `next()`; calling `next()` more than once is a `DEFINITION` error. Extension-owned command inputs are validated before interception.

`handleError` is a terminal presentation chain used by `.execute()` only. Render the error or call `next()` to delegate. Core preserves a nonzero failure outcome either way.

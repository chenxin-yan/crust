import { Callout } from "fumadocs-ui/components/callout";

```ts
import { Crust } from "@crustjs/core";
```

Every definition method returns a new builder. The original builder is unchanged. Fluent methods preserve the builder surface: a root stays a `Crust` and a child created with `.sub()` or inside `.command(name, callback)` stays a `ChildCrust` — identical except that root-only `.extend()` is absent.

## Constructor

```ts
new Crust(name: string)
```

Creates a root command builder. An empty or whitespace-only name throws a `CrustError` with code `DEFINITION`.

```ts
const app = new Crust("my-cli");
```

## `.meta(meta)`

```ts
meta(meta: Omit<CommandMeta, "name">): Crust
```

Sets `description`, `usage`, `aliases`, or `hidden`. The constructor, `.sub()`, or inline `.command()` supplies the name.

```ts
const app = new Crust("issue").meta({
  description: "Manage issues",
  aliases: ["issues", "i"],
});
```

Aliases must be non-empty, contain no whitespace, not start with `-`, and not collide with sibling names or aliases.

## `.args(defs)`

```ts
args<const NewA extends ArgsDef>(
  defs: NewA & ValidateVariadicArgs<NewA>,
): Crust
```

Defines an ordered tuple of positional arguments. Only the last argument may be variadic.

```ts
const app = new Crust("copy").args([
  { name: "source", type: "path", required: true },
  { name: "destinations", type: "path", variadic: true },
] as const);
```

A definition can instead carry a Standard Schema. Schema-backed arguments receive the raw string, `undefined` when absent, or `string[]` when variadic. The schema owns coercion, defaults, requiredness, choices, and validation; do not mix it with `type`, `default`, `required`, `choices`, or `parse`.

```ts
const app = new Crust("serve").args([
  { name: "port", schema: z.coerce.number().int().min(1) },
] as const);
```

## `.flags(defs)`

```ts
flags<const F extends FlagsDef>(
  defs: F & ValidateNoPrefixedFlags<ValidateFlagAliases<F>>,
): Crust
```

Defines named flags. Flag keys omit the `--` prefix.

```ts
const app = new Crust("serve").flags({
  verbose: { type: "boolean", short: "v", inherit: true },
  port: { type: "number", default: 3000 },
  include: { type: "string", multiple: true },
});
```

`inherit: true` exposes a flag to descendant commands. Boolean flags support generated `--no-name` negation unless `noNegate: true` is set. Names and aliases beginning with `no-` are reserved.

Schema-backed flags require `type: "string" | "boolean"` only to declare whether the flag consumes a token. Their schema owns the value rules and receives the raw parsed value.

```ts
const app = new Crust("serve").flags({
  port: { type: "string", schema: z.coerce.number().int().min(1) },
});
```

## `.provide(context)`

```ts
provide<const C extends ContextInstance>(context: C): Crust
```

Attaches a Context produced by invoking a `context()` factory. Contexts are inherited by descendants, constructed in registration order only for the resolved command path, and available through `ctx` in the Command Handler.

```ts
import { context, Crust } from "@crustjs/core";

const database = context("database", (options: { url: string }) => ({
  url: options.url,
  async [Symbol.asyncDispose]() {},
}));

const app = new Crust("my-cli")
  .provide(database({ url: "postgres://localhost/app" }))
  .handle(({ ctx }) => {
    ctx.database.url;
  });
```

Values implementing `Symbol.dispose` or `Symbol.asyncDispose` are disposed in reverse construction order after success or failure. A duplicate Context name on one command path throws `DEFINITION`.

## `.extend(...extensions)`

```ts
extend(...extensions: readonly Extension[]): Crust
```

Registers application-wide Extensions. `.extend()` exists only on root builders — child builders (`ChildCrust`) do not expose it.

```ts
import { help, version } from "@crustjs/extensions";

const app = new Crust("my-cli").extend(help(), version("1.2.3"));
```

Extension-owned command or flag name and alias collisions throw `DEFINITION` when the application is prepared.

See [Extensions](/docs/guide/extensions) for authoring custom Extensions.

## `.handle(handler)`

```ts
handle(
  handler: (ctx: CrustCommandContext<A, Eff, Ctx>) => void | Promise<void>,
): Crust
```

Defines the Command Handler. It runs after routing, parsing, validation, Extension interception, and Context construction.

```ts
const app = new Crust("greet")
  .args([{ name: "name", type: "string", required: true }] as const)
  .handle(({ args, flags, ctx, rawArgs, command, stdout, stderr }) => {
    stdout(`Hello, ${args.name}!`);
  });
```

The context contains typed `args`, typed effective `flags`, typed Context values in `ctx`, `rawArgs` after `--`, the resolved `CommandSnapshot`, and injectable `stdout(text)` and `stderr(text)` callbacks.

## `.command(name, callback)`

```ts
command(
  name: string,
  callback: (command: ChildCrust) => ChildCrust,
): Crust
```

Creates and registers a child command. The callback receives a child builder typed with the parent's `inherit: true` flags and Contexts, and must return a child builder.

```ts
const app = new Crust("my-cli")
  .flags({ verbose: { type: "boolean", inherit: true } })
  .command("deploy", (command) =>
    command.flags({ environment: { type: "string", required: true } }).handle(({ flags }) => {
      flags.verbose;
      flags.environment;
    }),
  );
```

## `.command(builder)`

```ts
command(builder: ChildCrust): Crust
```

Registers an unattached child builder created with `.sub(name)`, using the child's existing name. Only child builders are accepted — a standalone `new Crust(name)` is not attachable.

## `.sub(name)`

```ts
sub<N extends string>(name: N): ChildCrust
```

Creates an unattached child builder typed with the parent's effective flags and Contexts. Register it with `.command(builder)`.

```ts title="app.ts"
export const app = new Crust("my-cli").flags({
  verbose: { type: "boolean", inherit: true },
});
```

```ts title="commands/deploy.ts"
import { app } from "../app.ts";

export const deploy = app.sub("deploy").handle(({ flags }) => {
  flags.verbose;
});
```

```ts title="cli.ts"
import { app } from "./app.ts";
import { deploy } from "./commands/deploy.ts";

await app.command(deploy).execute();
```

See [Split command files](/docs/guide/split-files) for the import-order rule.

## `.run(argv, io?)`

```ts
run(
  argv: readonly string[],
  io?: {
    stdout?: (text: string) => void;
    stderr?: (text: string) => void;
  },
): Promise<void>
```

Invokes an application programmatically. `argv` is required and does not include the executable name.

```ts
const stdout: string[] = [];
await app.run(["Ada"], {
  stdout: (text) => stdout.push(text),
  stderr: (text) => stdout.push(text),
});
```

`run()` resolves after successful cleanup. It does not render errors, run Extension `handleError` hooks, or change `process.exitCode`. Definition, parse, Context, Command Handler, and cancellation failures are thrown unchanged.

## `.execute(options?)`

```ts
execute(options?: { argv?: string[] }): Promise<void>
```

Runs the terminal boundary. By default it parses `process.argv.slice(2)`; `options.argv` is useful in tests.

```ts
await app.execute();
```

`execute()` renders a failure once through the Extension `handleError` chain ending in Core's renderer, sets `process.exitCode` to `1`, and resolves. A standard `AbortError` cancellation is silent and sets exit code `130`.

<Callout type="warn">
  Use `.handle(handler)` to define behavior. `.run(argv, io)` is only programmatic invocation;
  `.execute()` is the terminal entry point.
</Callout>

The version extension adds `--version` / `-v` to the root command, printing the CLI name and version.

## Usage

```ts
import { Crust } from "@crustjs/core";
import { version } from "@crustjs/plugins";

const main = new Crust("my-cli").extend(version("1.0.0")).run(() => {
  /* ... */
});

await main.execute();
```

```sh
$ my-cli --version
my-cli v1.0.0

$ my-cli -v
my-cli v1.0.0
```

## Configuration

### Static Version

Pass a string literal:

```ts
version("1.0.0");
```

### Dynamic Version

Pass a function that returns the version string. The function is called lazily — only when `--version` is actually used:

```ts
import pkg from "../package.json";

version(() => pkg.version);
```

Or read it at import time:

```ts
import pkg from "../package.json";

version(pkg.version);
```

### Default Version

If no version is provided, it defaults to `"0.0.0"`:

```ts
version(); // Outputs: my-cli v0.0.0
```

## Behavior

### Root Command Only

The `--version` flag is only registered on the root command. Using `--version` on a subcommand has no effect:

```sh
$ my-cli --version        # Shows version
$ my-cli build --version  # Does NOT show version (parsed as a build flag)
```

### Output Format

```
<command-name> v<version>
```

The command name comes from `meta.name` of the root command.

### The `--` Separator

Like the help extension, `--version` is not recognized after `--`. See [the `--` separator](/docs/guide/arguments#the----separator) for details.

## Type

```ts
type VersionValue = string | (() => string);

function version(versionValue?: VersionValue): Extension;
```

`@crustjs/create` copies template directories, interpolates variables, renames dotfiles, resolves conflicts, and runs post-scaffold steps. It does not provide prompts or terminal UI.

## Install

```npm
npm install @crustjs/create
```

Pair it with any CLI and prompt libraries needed by your create tool.

## Locating templates

| `template` value                                | Resolves from                        | Use for                                                       |
| ----------------------------------------------- | ------------------------------------ | ------------------------------------------------------------- |
| `new URL("../templates/base", import.meta.url)` | The module that contains the call    | Templates shipped inside your generator package               |
| `"./templates/base"`                            | The user's current working directory | Templates in the project where the command runs               |
| `"/srv/templates/base"`                         | That exact filesystem path           | A location already resolved by your own code or configuration |

Ship templates inside your generator with an `import.meta.url` URL. `npx`, `bun x`, and global installs run the generator from a cache while the working directory is the user's project, so a relative string would resolve there instead.

- Only `file:` URLs are accepted, and the template must be a directory.
- Convert an existing filesystem path with `pathToFileURL()` rather than concatenating `file://`.

## Template conventions

```json title="templates/base/package.json"
{
  "name": "{{name}}",
  "description": "{{description}}"
}
```

- Text files replace `{{identifier}}` placeholders from `context`; placeholders without a value stay unchanged.
- Files with a null byte in their first 8 KiB are binary and copied without interpolation.

```text
templates/base/_gitignore   -> my-project/.gitignore
templates/base/__tests__/   -> my-project/__tests__/
```

- A single leading `_` on a file name becomes `.`; `__` stays unchanged. Directory names are never renamed.
- To layer templates, call `scaffold()` more than once with `conflict: "overwrite"`.

### Custom renderer

Pass `render` to use a template engine instead of `{{identifier}}` interpolation. It receives each text file's contents and `context`, may return a string or a promise, and its output is written as-is without a second interpolation pass. Binary files never reach it.

```ts
await scaffold({
  template: new URL("../templates/base", import.meta.url),
  dest: "./my-project",
  context: { name: "my-app" },
  render: (source, context) => source.replaceAll("<%= name %>", context.name ?? ""),
});
```

- Templates run through `render` as trusted code.
- Destination conflict and symlink checks still happen before any file is rendered.
- An error thrown or rejected by `render` fails `scaffold()`; files written earlier in the call remain.

See [Locating templates](#locating-templates) for how `template` resolves.

| `conflict`          | Non-empty destination                                                   |
| ------------------- | ----------------------------------------------------------------------- |
| `"abort"` (default) | Throws before writing                                                   |
| `"overwrite"`       | Replaces conflicting files and leaves unrelated destination files alone |

Symlinks in the destination:

- `dest` itself may be a symlink; its target is the destination.
- Symlinks that stay inside the destination are followed.
- An existing file or directory that is a symlink resolving outside the destination, or to a missing target, throws before any file is written.
- Containment is checked again before each write, including binary copies. A redirected destination root or an escaping link created during rendering aborts the call; earlier writes remain.

<Callout type="warn">
  These path checks are not atomic with filesystem writes. Use a destination whose directories
  untrusted processes cannot modify concurrently.
</Callout>

## `runSteps(steps, cwd, options?)`

```ts
await runSteps(
  [{ type: "install" }, { type: "git-init", commit: "Initial commit" }],
  "./my-project",
);
```

Steps run in order and stop at the first error. Inside a Crust command, pass the action's `stderr` as `options.stderr` so non-fatal warnings go through the invocation's output.

`options.signal` cancels the steps: on abort, the running child gets `SIGTERM`, and on macOS and Linux so do its descendants, such as the workers a `command` step's shell started. Once they exit, `runSteps()` rejects with `signal.reason` and skips the remaining steps. Any still running 5 seconds later get `SIGKILL`, so a step that ignores `SIGTERM` cannot hang the command. On Windows, which has no graceful signal, the child's whole process tree ends at once. A second Ctrl-C ends the command right away without waiting. It defaults to the ambient terminal signal, which inside a Crust command is the invocation's `signal`, so Ctrl-C and `SIGTERM` end the command with exit 130 or 143.

## Utilities

```ts
interpolate("Hello, {{name}}!", { name: "world" }); // => "Hello, world!"
```

- `interpolate(content, context)` replaces placeholders in a string; it is the default `render`.
- `detectPackageManager(cwd?)` returns a `PackageManager`: it checks lockfiles, then `npm_config_user_agent`, and defaults to npm.
- `isInGitRepo(cwd?)` reports whether the path is inside a Git work tree.

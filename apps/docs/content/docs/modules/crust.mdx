`@crustjs/crust` provides the `crust` CLI. Bun and Deno targets are standalone executables; `--runtime node` emits a bundled executable JavaScript file. The application API comes from [`@crustjs/core`](/docs/modules/core) and [`@crustjs/extensions`](/docs/modules/extensions).

## Install

```sh
bun add -d @crustjs/crust
```

The npm entry is a small Node launcher for a standalone executable with Bun embedded. Node is required to launch the packaged tool; a separate Bun installation is not.

## Commands

| Command                                                            | Description                                                                                                  |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| [`crust build`](/docs/guide/build)                                 | Validate and build a CLI: Bun/Deno standalone executables or a Node JS bundle (`--runtime`, `crust.runtime`) |
| [`crust publish`](/docs/guide/build#publishing-with-crust-publish) | Publish staged npm packages created by `crust build --package`                                               |

`crust build` evaluates the entry point under Bun before compiling for any target runtime, including Node and Deno. Packaged Crust uses its embedded Bun for this snapshot subprocess, which has a 30-second timeout. Target-only APIs used during preparation can fail under Bun. `.execute()` runs registered Extension build hooks in order, writes the refreshed Command Snapshot and temporary Build Report after all hooks finish, and exits before dispatch. Before compilation, the CLI prints one line per hook with its Extension id and up to three reported artifact paths; hooks that return nothing are marked as having run without an artifact report. The temporary report is not copied to the output directory.

The build command can embed `PUBLIC_*` constants from Bun's current-directory environment or explicit `--env-file` inputs (Bun and Node runtimes; Deno builds reject `--env-file`). See [Environment variables](/docs/guide/environment).

## Distribution modes

### Standalone binaries

The default `crust build` output is a raw binary and resolver script. Use it for release archives, containers, or custom distribution channels.

### Per-platform npm packages

`crust build --package` supports Bun targets only and stages platform-specific binary packages and a root Node launcher package. End users need Node to launch it; the platform binaries embed Bun. Use [`crust publish`](/docs/guide/build#publishing-with-crust-publish) to publish the staged set.

## Extension artifacts

Registered Extensions own build artifacts. For example, [`man()`](/docs/modules/man) writes `<outdir>/man/<name>.1`, [`skill()`](/docs/modules/skills) writes `<outdir>/skills`, and [`completion()`](/docs/modules/extensions/completion) writes `<outdir>/completions`. `crust build --package` ships these directories in the root npm package and includes them in npm `files`, with copies under each platform package's `bin/` directory. No Extension-specific build flags are required. `--no-validate` skips snapshot preparation, its runtime validation, and all build hooks. With `--package`, it also prevents artifact directories from being staged, even if they already exist.

Install this package only as a development dependency; generated applications do not need it at runtime.

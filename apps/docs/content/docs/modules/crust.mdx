`@crustjs/crust` provides the `crust` CLI. The application API comes from [`@crustjs/core`](/docs/modules/core) and [`@crustjs/extensions`](/docs/modules/extensions).

## Install

```sh
bun add -d @crustjs/crust
```

## Commands

| Command                                                            | Description                                                    |
| ------------------------------------------------------------------ | -------------------------------------------------------------- |
| [`crust build`](/docs/guide/build)                                 | Validate and compile a CLI to standalone executables           |
| [`crust publish`](/docs/guide/build#publishing-with-crust-publish) | Publish staged npm packages created by `crust build --package` |

`crust build` runs the entry point in a snapshot subprocess before compiling it. The subprocess sets the `SNAPSHOT_PATH_ENV` lockstep tooling constant (`CRUST_INTERNAL_SNAPSHOT_PATH`) to a temporary file; `.execute()` writes the validated Command Snapshot there and exits before dispatch. Application code should not set this internal environment variable.

The build command can embed `PUBLIC_*` constants from Bun's current-directory environment or explicit `--env-file` inputs. See [Environment variables](/docs/guide/environment).

## Distribution modes

### Standalone binaries

The default `crust build` output is a raw binary and resolver script. Use it for release archives, containers, or custom distribution channels.

### Per-platform npm packages

`crust build --package` stages platform-specific binary packages and a root resolver package. Use [`crust publish`](/docs/guide/build#publishing-with-crust-publish) to publish the staged set.

## Generated man pages

`crust build --man` renders the Command Snapshot produced by the build subprocess and writes `<outdir>/man/<name>.1`. Validation and man generation share one subprocess, and the entry point does not need to export its root builder. See [`@crustjs/man`](/docs/modules/man).

Install this package only as a development dependency; generated applications do not need it at runtime.

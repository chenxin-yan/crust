title: "Crust"
description: Build and distribute Crust applications for Bun, Deno, and Node.
---

`@crustjs/crust` provides the `crust` CLI. `crust build` writes the publishable npm packages for your CLI to `.crust/`, and `crust publish` uploads them.

## Install

```npm
npm install -D @crustjs/crust
```

The npm package is itself built with `crust build`, so its `bin` is a Node launcher that runs a platform-specific standalone executable with Bun embedded. Node is required to start it; a separate Bun installation is not. Without `bun` on `PATH`, arm64 hosts cannot build their own target (Bun would copy the running `crust` executable onto itself); the error names the other targets, or install Bun.

## Commands

```sh
crust build --target bun-linux-x64
# Runtime: bun (default)
# Staging 1 distribution target(s) in .../.crust...
#   → linux-x64: .../.crust/linux-x64/bin/my-cli-bun-linux-x64
# ✓ Staged 2 npm package(s) successfully: (excerpt)
```

[`crust build`](/docs/guide/build-and-distribution) validates your CLI and stages it in `.crust/`. [`crust publish`](/docs/guide/build-and-distribution#publish-with-crust-publish) publishes what `crust build` staged.

### `crust build` options

| Option                        | Type                          | Default      | Description                                                                                                               |
| ----------------------------- | ----------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------- |
| `-e, --entry`                 | string                        | `src/cli.ts` | Entry file path                                                                                                           |
| `-o, --outfile`               | string                        | none         | Write one binary or bundle to this path instead of staging `.crust/` (one `--target`, or this machine's)                  |
| `--minify`, `--no-minify`     | boolean                       | none         | Minify the output (default for bun and node; unsupported for deno)                                                        |
| `--runtime`                   | string: `bun \| deno \| node` | none         | Build runtime (overrides package.json crust.runtime; otherwise inferred from deno.json or @types/node, defaulting to bun) |
| `-t, --target`                | string, repeatable            | none         | Canonical compiler target(s). Omit to build all platforms for Bun or Deno.                                                |
| `--env-file`                  | string, repeatable            | none         | Explicit env file(s) used for build-time constants; repeatable                                                            |
| `--bun-plugin`                | string, repeatable            | none         | Bun bundler plugin module(s) to apply (default export); repeatable. Bun and Node builds only                              |
| `--validate`, `--no-validate` | boolean                       | `true`       | Materialize command definitions before compiling; `--no-validate` also skips Extension build hooks                        |

### `crust publish` options

```sh title="Dry-run output (excerpt)"
crust publish --dry-run
# Publish order: linux-x64 -> ... -> root
#   → linux-x64: npm publish --access public
```

Publishing reads `.crust/manifest.json` and runs `npm publish` in each staged directory, so `npm` must be on `PATH`. npm is used instead of `bun publish` because it supports [trusted publishing](https://docs.npmjs.com/trusted-publishers) from CI; `bun publish` does not. Without a prior `crust build`, it fails with `Run crust build before crust publish`.

| Option                    | Type    | Default  | Description                                              |
| ------------------------- | ------- | -------- | -------------------------------------------------------- |
| `--tag`                   | string  | none     | Override the npm dist-tag passed to npm publish          |
| `--access`                | string  | `public` | npm access level passed to npm publish                   |
| `--dry-run`               | boolean | `false`  | Print publish order and commands without publishing      |
| `--verify`, `--no-verify` | boolean | `true`   | Verify staged directories and metadata before publishing |
| `--registry`              | string  | none     | Override the registry passed to npm publish              |

## Build output

`crust build` stages the publishable npm tree in `.crust/` (`manifest.json`, `root/`, one `<platform>/` per target for Bun and Deno, and `artifacts/` from Extension build hooks) and wipes it at the start of every staged build. `--outfile` skips staging and writes one binary or bundle instead, leaving any existing `.crust/` in place. See [Build](/docs/guide/build-and-distribution#build) for the tree, the launcher, and naming rules.

## `package.json` configuration

```json title="package.json"
{
  "crust": {
    "runtime": "node",
    "include": ["templates"]
  }
}
```

| Key             | Description                                                                                                                                                      |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `crust.runtime` | Build runtime when `--runtime` is omitted. Without it, `deno.json`/`deno.jsonc` selects Deno and `@types/node` without `@types/bun` selects Node; otherwise Bun. |
| `crust.include` | Directories relative to the project root that `crust build` copies into `.crust/root/` (listed in `files`) and into each platform package's `bin/`.              |

`crust.include` entries must be existing directories inside the project (symlinks are copied dereferenced, so every symlink inside them must also resolve inside the project), cannot be named `bin`, cannot be inside `.crust`, and cannot repeat an Extension artifact directory name.

## Extension artifacts

```text
.crust/artifacts/
├── man/<name>.1
├── skills/
└── completions/
```

Registered Extensions own build artifacts. `man()`, `skill()`, and `completion()` write the directories shown when registered, and `crust build` copies each top-level directory into `.crust/root/` and every platform package's `bin/`.

`--no-validate` skips snapshot preparation and all Extension build hooks, so no artifact directories are staged.

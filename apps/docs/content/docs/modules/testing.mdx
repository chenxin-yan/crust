`@crustjs/testing` adds helpers for raw `execute()` capture and fake interactive terminals. For ordinary typed action tests, use Core's [`app.run()`](/docs/api/crust#runpath-input-options), which already captures output and returns the action result; see [Testing](/docs/guide/testing).

## Install

```npm
npm install -D @crustjs/testing
```

`@crustjs/core` is a required peer. `@crustjs/prompts` is an optional peer needed only by the `@crustjs/testing/interactive` entry point; the root entry point works without it. TypeScript is an optional peer.

## `captureExecute(app, argv)`

<include lang="ts">../../../examples/modules/testing.ts#execute</include>

`captureExecute()` drives raw argv through `execute()` in-process and returns `stdout`, `stderr`, and `exitCode`. It restores the previous process exit state after capture. Use it for parser errors, rendered failures, and Extension `onError` output. `app` is anything with Crust's `execute({ argv, io })` method (`ExecutableApp`).

## `runInteractive(app, path, input?)`

Import from `@crustjs/testing/interactive`; this entry point requires `@crustjs/prompts`. `path` and `input` are typed like `app.run()`, so a definition must be added to the application before it can be addressed.

<include lang="ts">../../../examples/modules/testing.ts#interactive</include>

`waitFor()` polls the ANSI-stripped screen and defaults to a 5000 ms timeout. It fails as soon as the invocation fails or completes without a match, rather than waiting for the timeout. Call `type()` or `keys()` after the expected prompt appears, then await `done`.

`done` rejects with the error from a failed outcome. One ambient [`withTerminalIO`](/docs/modules/progress#output-sinks) scope sends prompts, progress, and `ctx.stderr()` to the fake screen.

`ctx.stdout()` is not included, so use `run()` for stdout assertions.

## Custom prompts

`@crustjs/testing` does not re-export prompt-author helpers. Test custom prompts with [`renderPrompt()`](/docs/modules/prompts#testing-custom-prompts) from `@crustjs/prompts/testing`.

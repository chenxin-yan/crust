`@crustjs/testing` adds helpers for raw `execute()` capture and fake interactive terminals. Use core `run()` for ordinary typed action tests.

## Install

```sh
bun add -d @crustjs/testing
```

The required peer packages are `@crustjs/core`, `@crustjs/progress`, and `@crustjs/prompts`. TypeScript is an optional peer.

## Application contracts

```ts
interface ExecutableApp {
  execute(options?: { argv?: string[]; io?: CaptureIO }): Promise<number>;
}
```

`captureExecute()` accepts this structural contract. `runInteractive()` accepts a Crust application and infers its command path and input.

An inert definition must be added to an application before the typed helpers can address it. Core's typed invocation rules are documented under [`run()` path and input](/docs/api/crust#runpath-input-io).

## `app.run(path, input?)`

```ts
const outcome = await app.run(["build"], { flags: { minify: true } });
if (outcome.status === "failed") throw outcome.error;
expect(outcome.stdout).toContain("Built");
```

Use `run()` to capture stdout, stderr, and the Command Action outcome without terminal parsing. See the [core `run()` reference](/docs/api/crust#runpath-input-io) for result branches and capture boundaries.

## `runInteractive(app, path, input?)`

<include lang="ts">../../../examples/modules/testing.ts#interactive</include>

`waitFor()` polls the ANSI-stripped screen and defaults to a 5000 ms timeout. Call `type()` or `keys()` after the expected prompt appears, then await `done`.

One ambient [`withTerminalIO`](/docs/modules/progress#output-sinks) scope sends prompts, progress, and `ctx.stderr()` to the fake screen. `ctx.stdout()` is not included, so use `run()` for stdout assertions.

## Custom prompts

```ts
import { renderPrompt } from "@crustjs/prompts/testing";
```

`@crustjs/testing` does not re-export prompt-author helpers. Use [`renderPrompt()`](/docs/modules/prompts#testing-custom-prompts) for custom `(options, io?)` prompts.

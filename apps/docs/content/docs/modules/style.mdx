title: "Style"
---

`@crustjs/style` exports ANSI-aware style functions, dynamic colors, hyperlinks, and text layout helpers. Default exports read terminal capability inputs on each call; `createStyle()` creates a chainable instance with fixed settings, and `createPlainStyle()` creates plain style functions with fixed settings.

## Install

```npm
npm install @crustjs/style
```

## Quick example

<include lang="ts">../../../examples/modules/style.ts#styling</include>

Bare named styles such as `bold` and `red` are plain functions. Chain on `style` (`style.bold.red`) or on a `createStyle()` instance. Both forms support tagged templates.

## Styling

```ts
bold("direct");
bold`tagged ${value}`;
bold(red("nested"));
style.bold.red.bgYellow("chained");
```

Modifiers are `bold`, `dim`, `italic`, `underline`, `inverse`, `hidden`, and `strikethrough`. The package also exports the standard 16 foreground and 16 background names.

A bare export is a `PlainStyleFn`, and a chain is a `ChainableStyleFn`. Both can be passed where a `(text: string) => string` `StyleFn` is expected, and both return an empty string for null and undefined. Bare exports carry no chain methods and no `open`/`close` pair, so importing one does not bundle the chain engine.

## Combining styles

Combine styles by nesting bare functions, by naming a combination as a function, or by chaining on `style`:

```ts
import { bold, style, yellow } from "@crustjs/style";

bold(yellow("warning")); // nest

const warn = (text: string) => bold(yellow(text)); // name it: a `StyleFn`
warn("careful");

const warnChain = style.bold.yellow; // chain
warnChain("careful");
```

All three apply the same styles and produce the same output for the same text. An inner style closes and the outer one reopens after it, so `red(blue("a") + "b")` keeps `b` red.

|                       | Nested or named functions                         | `style` chain                                        |
| --------------------- | ------------------------------------------------- | ---------------------------------------------------- |
| Bundles               | the styles you import, plus a small shared engine | the chain engine, color parsing, and CSS color names |
| Chaining (`.red`)     | no                                                | yes                                                  |
| `open` / `close` pair | no                                                | yes                                                  |

Prefer bare functions in code that ships, such as themes and output helpers: a named combination is a plain `StyleFn`, so it fits anywhere one is accepted, such as a prompt theme slot. Use `style` when you want chaining, dynamic `fg`/`bg` chains, or the raw `open`/`close` codes.

## Dynamic colors

```ts
fg("error", "#ff0000");
fg("ocean", "rgb(0, 128, 255)");
fg("coral", [255, 127, 80]);
style.bold.fg("rebeccapurple")("note");
```

`fg()` and `bg()` accept three- or six-digit hex, RGB strings, RGB tuples, and named CSS colors. Invalid input throws `TypeError`, including when the text is empty.

The resolved `ColorDepth` is `"truecolor" | "256" | "16" | "none"`. Read `style.colorDepth`, `colorsEnabled`, or `trueColorEnabled` to inspect it.

## Color control

<include lang="ts">../../../examples/modules/style.ts#control</include>

Default exports decide from `process.stdout.isTTY`, `NO_COLOR`, `FORCE_COLOR`, `COLORTERM`, and `TERM`:

- `FORCE_COLOR=0` or `FORCE_COLOR=false` disables all ANSI.
- Any other `FORCE_COLOR` value, even an empty one, forces ANSI and overrides `NO_COLOR` and TTY detection. `1`, `2`, and `3` select 16-color, 256-color, and truecolor depth; other values detect depth from `COLORTERM` and `TERM`.
- Without `FORCE_COLOR`, a non-TTY stdout disables all ANSI. A non-empty `NO_COLOR` disables only colors: modifiers such as `bold` and hyperlinks still follow TTY detection.
- Inside a Crust command whose stdout is captured (`app.run()`, an injected `execute({ io: { stdout } })`, or the [`@crustjs/testing`](/docs/modules/testing#styled-output) helpers), stdout counts as non-TTY.

`createStyle({ mode: "always" })` enables all ANSI at truecolor depth. `mode: "never"` returns plain text, and `mode: "auto"` accepts `overrides`, such as the TTY state of the stream you write to, or fixed values for deterministic tests.

`createPlainStyle()` takes the same options and returns plain functions for every named style, with the same output as `createStyle()`. It has no chaining, `open`/`close`, or `fg`/`bg`, so it does not bundle the chain engine. Use it for styled output to a stream other than stdout:

```ts
import { createPlainStyle } from "@crustjs/style";

const err = createPlainStyle({ overrides: { isTTY: process.stderr.isTTY } });
process.stderr.write(`${err.bold(err.red("error:"))} config not found\n`);
```

|                 | Decides color from stdout and the environment | Fixed at creation from options (the environment fills the rest) |
| --------------- | --------------------------------------------- | --------------------------------------------------------------- |
| Plain functions | `bold`, `red`, …                              | `createPlainStyle(options)`                                     |
| Chainable       | `style`                                       | `createStyle(options)`                                          |

## Hyperlinks (OSC 8)

```ts
link("docs", "https://crustjs.com");
link(style.underline("Crust"), "https://crustjs.com", { id: "docs" });
```

Links emit OSC 8 sequences when modifiers are enabled (see [Color control](#color-control)) and otherwise return the label, so `NO_COLOR` does not disable them. URLs must be printable ASCII without spaces, checked even when emission is off; anything else throws `TypeError`.

## Layout

<include lang="ts">../../../examples/modules/style.ts#layout</include>

`padStart`, `padEnd`, `center`, and `stringWidth` measure visible terminal columns rather than ANSI bytes. Bun uses `Bun.stringWidth`; the Node fallback may differ for uncommon grapheme clusters. `table()` uses headers for its column count, supports per-column alignment, and accepts readonly (`as const`) headers, rows, and alignments.

## Fine print

```ts
const chain = style.bold.red;
const open = chain.open;
const close = chain.close;
```

`open` and `close` are raw static ANSI strings and do not recheck capabilities. Use `chain(text)` for capability-aware, nesting-safe output.

Direct `fg(text, input)` requires string text. Bare exports and chainables accept other stringifiable values and return `""` for nullish or empty input. Chainables still validate dynamic color input.

ANSI-safe styling primitives, terminal capability awareness, and text layout helpers. **Zero runtime dependencies.**

The mental model is one sentence: **call the chain; pass the chainable when a style is a value.** The environment (`NO_COLOR`, `FORCE_COLOR`, TTY) controls the default exports; `createStyle()` gives you a frozen, explicitly-configured instance.

## Install

```sh
bun add @crustjs/style
```

## Quick start

```ts
import { bold, green, style, fg, link } from "@crustjs/style";

console.log(green("✓"), bold("Build succeeded"));
console.log(style.bold.red("Critical failure")); // chaining
console.log(style.bold.red`Build in ${42}ms`); // tagged template
console.log(fg("brand", "#4FA83D")); // any CSS color
console.log(link("docs", "https://crustjs.com")); // OSC 8 hyperlink
```

Output automatically respects the terminal: colors need a TTY and no `NO_COLOR`; depth (truecolor / 256 / 16) is detected from `COLORTERM` / `TERM`. See [Color control](#color-control).

## Styling

**Modifiers:** `bold`, `dim`, `italic`, `underline`, `inverse`, `hidden`, `strikethrough`

**Foreground:** `black`, `red`, `green`, `yellow`, `blue`, `magenta`, `cyan`, `white`, `gray`, `brightRed`, `brightGreen`, `brightYellow`, `brightBlue`, `brightMagenta`, `brightCyan`, `brightWhite`

**Background:** `bgBlack`, `bgRed`, `bgGreen`, `bgYellow`, `bgBlue`, `bgMagenta`, `bgCyan`, `bgWhite`, `bgBrightBlack`, `bgBrightRed`, `bgBrightGreen`, `bgBrightYellow`, `bgBrightBlue`, `bgBrightMagenta`, `bgBrightCyan`, `bgBrightWhite`

Every name is a chainable function supporting three call shapes:

```ts
bold("direct call");
bold`tagged ${value} template`;
bold.red.bgYellow("chained"); // open left-to-right, close right-to-left
```

### Styles as values

Chainables are plain `(text: string) => string` functions — passing a style around is just passing the chainable. The `StyleFn` type names this contract:

```ts
import { style, type StyleFn } from "@crustjs/style";

function renderError(paint: StyleFn) {
  return paint("boom");
}

renderError(style.bold.red); // mode-aware, per-step NO_COLOR degradation
```

## Dynamic colors

`fg(text, input)` / `bg(text, input)` accept every input [`Bun.color()`](https://bun.com/docs/runtime/color) understands, and also work as chain steps:

```ts
import { fg, bg, style } from "@crustjs/style";

fg("error", "#ff0000"); // hex (3/6/8-digit)
fg("royal", "rebeccapurple"); // 148 named CSS colors (autocompleted)
fg("ocean", "rgb(0, 128, 255)"); // any CSS notation (hsl, lab, oklch, …)
fg("red", 0xff0000); // packed number
fg("coral", [255, 127, 80]); // tuple
bg("slate", { r: 100, g: 116, b: 139 }); // object

style.bold.fg("#ff8800")("warning"); // chain extension
style.fg("rebeccapurple").italic("emphasis"); // chain root
```

Invalid colors throw `TypeError: Invalid color input: ...` at call time — even when `text` is empty, so bugs can't hide.

Output adapts to the resolved depth:

| Depth         | Output                         | Detected when                                                                            |
| ------------- | ------------------------------ | ---------------------------------------------------------------------------------------- |
| `"truecolor"` | `Bun.color(input, "ansi-16m")` | `COLORTERM=truecolor\|24bit`, or `TERM` contains `truecolor`/`24bit`/ends with `-direct` |
| `"256"`       | `Bun.color(input, "ansi-256")` | `TERM` contains `256color`                                                               |
| `"16"`        | In-package quantizer¹          | Any other TTY                                                                            |
| `"none"`      | Plain text                     | Not a TTY, `NO_COLOR`, `FORCE_COLOR=0`, `TERM=dumb`, or `mode: "never"`                  |

¹ Same algorithm as `ansi-styles` / `chalk`, pending [oven-sh/bun#22161](https://github.com/oven-sh/bun/issues/22161).

Inspect the resolved tier via `style.colorDepth` (live) or `instance.colorDepth` (frozen at creation).

## Color control

Two channels, one rule each:

**The environment controls the default exports.** `style` and all named helpers re-resolve these standard variables on every call:

| Variable                           | Effect                                                                                          |
| ---------------------------------- | ----------------------------------------------------------------------------------------------- |
| `NO_COLOR` (non-empty)             | Colors off; modifiers and hyperlinks keep following TTY ([no-color.org](https://no-color.org/)) |
| `FORCE_COLOR=0` / `false`          | **All** ANSI off — overrides TTY                                                                |
| `FORCE_COLOR=1` / `2` / `3`        | Force color at 16 / 256 / truecolor depth — overrides `NO_COLOR` and non-TTY (chalk convention) |
| `FORCE_COLOR` (other, incl. empty) | Force on at the `COLORTERM` / `TERM` detected depth                                             |

```ts
// e.g. in a --color/--no-color flag handler:
process.env.FORCE_COLOR = "3"; // force on — child processes and chalk obey it too
process.env.NO_COLOR = "1"; // colors off, bold/links survive on a TTY
```

For a scoped `--color` / `--no-color` flag that sets and restores these around a single run, use [`noColor()`](/docs/modules/extensions/no-color).

**`createStyle()` freezes an explicit configuration** — resolved once at creation, immune to later env changes:

```ts
import { createStyle } from "@crustjs/style";

const s = createStyle(); // auto: snapshot of current env
const color = createStyle({ mode: "always" }); // all ANSI on, truecolor
const plain = createStyle({ mode: "never" }); // all ANSI off, plain text

// Deterministic tests — simulate any terminal without touching process globals:
const t = createStyle({
  mode: "auto",
  overrides: { isTTY: true, noColor: undefined, forceColor: undefined, colorTerm: "truecolor" },
});
```

## Hyperlinks (OSC 8)

```ts
import { link, style } from "@crustjs/style";

link("docs", "https://crustjs.com");
link("page 1", "https://example.com/p1", { id: "intro" }); // id groups segments
link(style.underline("Visit Crust"), "https://crustjs.com"); // style label, then wrap
```

Emitted on a TTY; not disabled by `NO_COLOR` (links aren't colors). URLs are validated even when emission is off. Terminal support varies — unsupported emulators show plain text.

## Layout

```ts
import { padStart, padEnd, center, table } from "@crustjs/style";

padEnd(styledText, 20); // ANSI-aware: escapes are free, CJK counts real columns
table(
  ["Name", "Age"],
  [
    ["Alice", "30"],
    ["Bob", "25"],
  ],
  { align: ["left", "right"] },
);
```

`padStart` / `padEnd` / `center` measure visible width — unlike `String.prototype.padStart`, which counts code units and ANSI escapes. `table` supports per-column alignment, padding, separators, and styled cells.

<Callout type="info">
  For width measurement and ANSI stripping, use Bun's built-ins directly: `Bun.stringWidth(text)`
  (ANSI-aware and CJK-aware by default) and `Bun.stripANSI(text)`.
</Callout>

## Fine print

**Capture semantics.** Top-level helpers and first-level properties (`style.bold`) are forwarders — they re-resolve the environment on every call. Deeper chains (`style.bold.red`) snapshot the resolved instance at access time (chalk/ansis parity). Capture the first level and chain at the call site when a reference must follow later env changes.

**`open` / `close` for hot paths.** Every chainable exposes its raw ANSI codes (chalk/ansis parity) for manual composition in tight loops. They are static strings that bypass mode detection — check `style.enabled` first. Note `chain.open + text + chain.close` matches `chain(text)` byte-for-byte only when adjacent steps have distinct close codes; when steps share one (e.g. `bold` + `dim` both close with `\x1b[22m`), `chain(text)` re-opens the outer style after each inner close to prevent bleed. Use `chain(text)` for emission.

**Defensive guarantees.** Nullish text (`bold(null)`, `fg(undefined, "#f00")`) returns `""` — never crashes, never prints styled `"undefined"`. Empty text returns `""` with no orphan escape codes, but invalid colors still throw. These protect JS callers that bypass TypeScript.

## Usage

<include lang="ts" meta='title="cli.ts"'>
  ../../../../examples/modules/extensions/version.ts
</include>

```sh
$ my-cli --version
my-cli v1.2.3
```

`version()` owns the root-only `--version` flag and its short `-v`. It prints to stdout instead of running the Command Action. Subcommands reject it wherever it is typed, since the command that runs reads every flag: `my-cli deploy --version` and `my-cli --version deploy` are both an unknown flag. A subcommand may give `-v` its own meaning, such as `--verbose`, as long as it takes no value: `my-cli -v deploy` then passes it to `deploy`.

## API

```ts
version();
version("1.2.3");
version(() => process.env.APP_VERSION ?? "dev");
```

- Without an explicit value, `version()` requires root `version` metadata; omitting it is a type error. A value typed `string | undefined` still requires that metadata, as described by [`RootMetaKey`](/docs/api/types#rootmetakey).
- A function value is called when the flag is handled.
- An explicit value affects only the version flag. It does not set root metadata for completion, skills, or other Extensions.

```ts
version("1.2.3", { format: "plain" });
// $ my-cli --version
// 1.2.3
```

`short` picks the short spelling: `"v"` (the default), `"V"` for an application that uses `-v` for something else, as ripgrep uses it for `--invert-match`, or `false` for none. `--version` itself is fixed.

```ts
version("1.2.3", { short: "V" });
// $ my-cli -V
// my-cli v1.2.3
```

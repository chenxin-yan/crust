## Usage

<include lang="ts" meta='title="cli.ts"'>
  ../../../../examples/modules/extensions/help.ts
</include>

```sh
$ my-cli --help
my-cli - My CLI

Usage:
  my-cli [options]

Commands:
  deploy     Deploy the app

Options:
  -h, --help                   Show help
```

`help()` owns the recursive `--help` and `-h` flag. It also shows help when the selected command has no Command Action. That fallback runs as a `noAction` hook, after every `preRun` hook, so `my-cli --version` still prints the version on an action-less root whatever the `.extend()` order. Subcommands are listed from their `defineCommand()` metadata without running their recipes, so a command whose recipe throws still appears.

## Section consumer

```ts
const documentedApp = new Crust("my-cli", {
  sections: [{ title: "Example", body: "my-cli deploy", only: [help] }],
});
```

Use `help` as a section consumer to include or exclude sections from its output. Hidden commands remain routable but do not appear in command listings.

## `renderHelp`

```ts
const text = await renderHelp(await app.snapshot());
// => "my-cli - My CLI\n\nUsage:\n  my-cli [options] ..."
```

`renderHelp(command, path?)` renders a Command Snapshot without running the app and resolves to the help text. The renderer and `@crustjs/style` load on the first call, so a CLI pays for them only when it prints help. `path` is the command path shown in the output and defaults to `[meta.name]`.

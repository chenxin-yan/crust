## Usage

<include lang="ts" meta='title="cli.ts"'>
  ../../../../examples/modules/extensions/quiet.ts
</include>

```sh
$ my-cli deploy
Uploading 3 files...
Deployed https://example.com

$ my-cli deploy -q
Deployed https://example.com

$ MY_CLI_QUIET=1 my-cli deploy
Deployed https://example.com
```

`quiet(options?)` provides the `quiet` Context, a boolean:

1. Declare it with [`.use(quiet)`](/docs/guide/extensions#use-an-extensions-contexts-from-a-command).
2. `await ctx.quiet` and skip the output the command can do without, such as progress lines.

Without `.extend(quiet())` on the app, `.use(quiet)` is a type error, and preparing the app throws a `DEFINITION` error.

## Behavior

The Context owns the boolean `--quiet` flag, with `-q` and `--no-quiet`. Commands that `.use(quiet)` accept it, as do the root and its inline `.command()` children; other commands reject it as an unknown flag. The value is, in order:

- `--quiet` or `-q` (true), or `--no-quiet` (false);
- the `env` variable, when you name one (see [environment variables](/docs/guide/arguments-and-flags#environment-variables));
- `false`.

`quiet()` only provides the value. It silences nothing by itself: the command decides what to skip. Other Extensions, such as [`updateNotifier()`](/docs/modules/extensions/update-notifier) and [`nextSteps()`](/docs/modules/extensions/next-steps), don't read it, and errors still print.

`--quiet` is a normal flag:

- [`input()`](/docs/modules/extensions/input) can supply it where it is accepted: `--input '{"quiet":true}'`.
- Only commands that accept it list it in `--help`, [`schema`](/docs/modules/extensions/schema), and [MCP](/docs/modules/mcp) tool inputs.

To drop all of a command's stdout in one place instead, see the [renderer example](/docs/guide/extensions#renderers).

## Limitations

`--quiet` is a Context-owned flag, so a command that accepts it cannot declare its own `quiet` flag or `-q` while `quiet()` is registered: preparing the app throws a `DEFINITION` error.

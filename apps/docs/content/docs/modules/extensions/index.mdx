title: Extensions

`@crustjs/extensions` exports the official Extensions that own no definition keys, plus standalone renderers for help and the `--llms` index. Shell completion is its own package, [`@crustjs/completion`](/docs/modules/completion).

## Install

```npm
npm install @crustjs/extensions
```

## Usage

<include lang="ts" meta='title="cli.ts"'>
  ../../../../examples/modules/extensions/index.ts
</include>

Register Extensions on the root builder, in any order: the built-ins behave the same whatever the `.extend()` order.

- Hooks of one kind, such as `preRun` and `onError`, run in registration order (see [Hooks](/docs/guide/extensions#hooks)), and so do [contributed sections](/docs/api/types#extensionsectioncontribution).
- Types and naming constraints are part of the [Extension contract](/docs/api/types#extension-types).

## Exports

A curated list of the runtime exports; the [package entry point](https://github.com/chenxin-yan/crust/blob/main/packages/extensions/src/index.ts) also exports each option type. Registering an Extension adds little startup cost: renderers, update checks, and typo suggestions load the first time they run.

| Export                                                                        | Contribution                                          |
| ----------------------------------------------------------------------------- | ----------------------------------------------------- |
| [`help(options?)`](/docs/modules/extensions/help)                             | Recursive `--help` / `-h` flag and help rendering     |
| [`renderHelp(command, path?, options?)`](/docs/modules/extensions/help)       | Resolve help text for a Command Snapshot              |
| [`version(value?, options?)`](/docs/modules/extensions/version)               | Root-only `--version` / `-v` flag (`-V` or none)      |
| [`didYouMean(options?)`](/docs/modules/extensions/did-you-mean)               | Suggestions for unknown commands and flags            |
| [`noColor()`](/docs/modules/extensions/no-color)                              | Recursive `--color` / `--no-color` flag               |
| [`updateNotifier(options)`](/docs/modules/extensions/update-notifier)         | Post-action npm update notice                         |
| [`json()`](/docs/modules/extensions/json)                                     | Recursive `--json` flag for JSON results              |
| [`jsonInput()`](/docs/modules/extensions/json-input)                          | Recursive `--input` flag for JSON arguments           |
| [`schema(options?)`](/docs/modules/extensions/schema)                         | `schema` command and root-only `--llms` flag          |
| [`renderCommandIndex(root)`](/docs/modules/extensions/schema#--llms)          | Resolve the `--llms` Markdown for a Command Snapshot  |
| [`search(options?)`](/docs/modules/extensions/search)                         | `search` command that finds commands for a task       |
| [`confirmation()`](/docs/modules/extensions/confirmation)                     | `confirm` Context: prompt or `--yes` / `-y`           |
| [`ConfirmationRequiredError`](/docs/modules/extensions/confirmation#behavior) | Thrown when confirmation is needed but can't be asked |
| [`nextSteps(options?)`](/docs/modules/extensions/next-steps)                  | `nextSteps` Context: follow-up command suggestions    |
| [`telemetry(options)`](/docs/modules/extensions/telemetry)                    | One event per run through `send`; `telemetry` command |

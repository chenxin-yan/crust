`@crustjs/extensions` exports the official Extensions, plus standalone help and completion renderers.

## Install

```npm
npm install @crustjs/extensions
```

## Usage

<include lang="ts" meta='title="cli.ts"'>
  ../../../../examples/modules/extensions/index.ts
</include>

Register Extensions on the root builder, in any order: the built-ins behave the same whatever the `.extend()` order.

- Ordered hooks such as `preRun` and `onError` follow registration order (see [Hooks](/docs/guide/extensions#hooks)), and so do [contributed sections](/docs/api/types#extensionsectioncontribution).
- Types and naming constraints are part of the [Extension contract](/docs/api/types#extension-types).

## Exports

A curated list of the runtime exports; the [package entry point](https://github.com/chenxin-yan/crust/blob/main/packages/extensions/src/index.ts) also exports each option type. Registering an Extension adds little startup cost: renderers, completion scripts, update checks, and typo suggestions load the first time they run.

| Export                                                                        | Contribution                                          |
| ----------------------------------------------------------------------------- | ----------------------------------------------------- |
| [`help()`](/docs/modules/extensions/help)                                     | Recursive `--help` / `-h` flag and help rendering     |
| [`renderHelp(command, path?)`](/docs/modules/extensions/help)                 | Resolve help text for a Command Snapshot              |
| [`version(value?, options?)`](/docs/modules/extensions/version)               | Root-only `--version` / `-v` flag                     |
| [`completion(options?)`](/docs/modules/extensions/completion)                 | Shell completion command and build artifacts          |
| [`renderBashCompletion(root, options?)`](/docs/modules/extensions/completion) | Resolve bash completion for a Command Snapshot        |
| [`renderZshCompletion(root, options?)`](/docs/modules/extensions/completion)  | Resolve zsh completion for a Command Snapshot         |
| [`renderFishCompletion(root, options?)`](/docs/modules/extensions/completion) | Resolve fish completion for a Command Snapshot        |
| [`didYouMean(options?)`](/docs/modules/extensions/did-you-mean)               | `COMMAND_NOT_FOUND` presentation                      |
| [`noColor()`](/docs/modules/extensions/no-color)                              | Recursive `--color` / `--no-color` flag               |
| [`updateNotifier(options)`](/docs/modules/extensions/update-notifier)         | Post-action npm update notice                         |
| [`json()`](/docs/modules/extensions/json)                                     | Recursive `--json` flag for JSON results              |
| [`input()`](/docs/modules/extensions/input)                                   | Recursive `--input` flag for JSON arguments           |
| [`schema()`](/docs/modules/extensions/schema)                                 | `schema` command and root-only `--llms` flag          |
| [`confirm()`](/docs/modules/extensions/confirm)                               | `confirm` Context: prompt or `--yes`                  |
| [`ConfirmationRequiredError`](/docs/modules/extensions/confirm#behavior)      | Thrown when confirmation is needed but can't be asked |
| [`nextSteps(options?)`](/docs/modules/extensions/next-steps)                  | `nextSteps` Context: follow-up command suggestions    |

## Usage

<include lang="ts" meta='title="cli.ts"'>
  ../../../../examples/modules/extensions/update-notifier.ts
</include>

When the registry reports version `2.0.0`, the action writes `Done` to stdout and the hook writes this notice to stderr, so piped stdout stays clean:

```text
╭──────────────────────────────────────╮
│                                      │
│   Update available  1.2.3 → 2.0.0    │
│   Run npm install -g my-cli@latest   │
│                                      │
╰──────────────────────────────────────╯
```

The hook checks only after a completed Command Action, and awaits the check before the invocation ends. Network, registry, cache, and response failures do not change a successful outcome. A notice for the same latest version is shown once while the cache remembers it.

## When checks are skipped

The hook skips the check entirely (no cache read, no network request, no notice) when:

- `CI` is set to anything other than an empty string, `0`, or `false` in any letter case
- `NO_UPDATE_NOTIFIER` is set to any non-empty value, so users can opt out
- `process.stderr` is not a TTY, for example when stderr is redirected to a file or pipe

The TTY check reads `process.stderr` even when `run()` or `execute()` receives custom IO callbacks.

## API

  name="UpdateNotifierOptions"
/>

- The current version comes from `currentVersion` or root metadata. Without a string `currentVersion`, `.extend()` is a type error unless the root declares `version`.
- The notice appears when npm's `latest` dist-tag is newer by SemVer precedence.
- `timeoutMs` bounds only the registry request, not cache operations or the whole hook. Ctrl-C or `SIGTERM` ends the request at once.
- `updateDocsUrl` adds a `See <url> to update` line to the notice.

## Update command

```ts
updateNotifier({
  packageName: "my-cli",
  updateCommand: { scope: "global" },
});
```

Without `updateCommand`, the notice suggests no command. Otherwise:

- a string displays a fixed command;
- `{ scope: "global" | "local" }` builds the standard install command for the detected package manager (npm, pnpm, Yarn, or Bun), such as `pnpm add -g my-cli@latest`;
- a resolver receives `{ packageName, packageManager }` and returns the command.

Resolvers and package-manager detection run only when a notice is shown.

```ts
updateNotifier({
  packageName: "my-cli",
  updateCommand: ({ packageName, packageManager }) => `${packageManager} run update-${packageName}`,
});
```

Package-manager detection checks `npm_config_user_agent`, then `npm_execpath`, then the runtime executable name, and defaults to npm. Yarn global updates use `npm install -g <package>@latest`.

## Cache

```ts
updateNotifier({
  packageName: "my-cli",
  cache: { intervalMs: 60 * 60 * 1000 },
});
```

The default adapter stores state in `update-notifier.json` under the package's platform [state directory](/docs/modules/store#storage-paths), and ignores state cached for a different `registryUrl`. An unreadable cache counts as empty. Set `cache: false` to skip all cache reads and writes and check on every run.

title: Did You Mean
description: Present command-not-found errors with typo suggestions.
---

## Usage

<include lang="ts" meta='title="cli.ts"'>
  ../../../../examples/modules/extensions/did-you-mean.ts
</include>

```sh
$ my-cli deply
Unknown command "deply". Did you mean "deploy"?

Available commands: deploy
# exit code: 1
```

`didYouMean()` presents `COMMAND_NOT_FOUND` errors in `execute()`. It suggests the visible sibling command closest to the typed name:

- Candidates are command names and their aliases; the suggestion always prints the canonical name.
- A candidate matches when it starts with the typed text or is a few edits away from it.
- Prefix matches rank first, then fewer edits; ties go alphabetically.
- Hidden commands are never suggested.

Without a match, the message has no `Did you mean` part.

## API

```ts
new Crust("my-cli").extend(didYouMean({ mode: "help" }));
```

<auto-type-table
  path="../../../../../../packages/extensions/src/did-you-mean.ts"
  name="DidYouMeanOptions"
/>

| `mode`              | Output                                    |
| ------------------- | ----------------------------------------- |
| `"error"` (default) | Message and available commands, on stderr |
| `"help"`            | Message and the parent's help, on stdout  |

The exit code stays 1 in both modes.

## Limitations

- A parent with a Command Action treats an unknown token as a positional argument, so no `COMMAND_NOT_FOUND` occurs and nothing is suggested.
- [`run()`](/docs/api/crust#runpath-input-options) returns the failed outcome without presenting it.

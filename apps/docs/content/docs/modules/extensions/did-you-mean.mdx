## Usage

<include lang="ts" meta='title="cli.ts"'>
  ../../../../examples/modules/extensions/did-you-mean.ts
</include>

```sh
$ my-cli deply
Unknown command "deply". Did you mean "deploy"?

Available commands: deploy
# exit code: 2

$ my-cli deploy --forse
Error: Unknown flag "--forse". Did you mean "--force"?
# exit code: 2
```

`didYouMean()` presents `COMMAND_NOT_FOUND` errors in `execute()`. It suggests the visible sibling command closest to the typed name:

- Candidates are command names and their aliases; the suggestion always prints the canonical name.
- A candidate matches when it starts with the typed text or is at most two edits away from it, cobra's cutoff. An empty word matches nothing.
- Prefix matches rank first, then fewer edits; ties go alphabetically.
- Hidden commands are never suggested.

Without a match, the message has no `Did you mean` part.

It also suggests a flag for an unknown flag, from the flag name in Core's `PARSE` error (`details.reason` is `"unknown-flag"`):

- Candidates are the long spellings the command accepts: flag names, their aliases of two or more characters, the members of an [exclusive group](/docs/guide/arguments-and-flags#one-of-several-flags), and `no-<name>` for a negatable flag (also matched through `no-<alias>`). The same matching rule applies.
- Hidden flags are never suggested, and neither is anything for a one-character name such as `-x`: every short name is within two edits of it.
- The suggestion is added to the error's message, which then renders as usual: Core's `Error:` line, or the error JSON under [`--json`](/docs/modules/extensions/json) when `didYouMean()` is registered before `json()`. `mode` does not apply to flags.

## API

```ts
new Crust("my-cli").extend(didYouMean({ mode: "help" }));
```

<auto-type-table
  path="../../../../../../packages/extensions/src/did-you-mean.ts"
  name="DidYouMeanOptions"
/>

| `mode`              | Output                                    |
| ------------------- | ----------------------------------------- |
| `"error"` (default) | Message and available commands, on stderr |
| `"help"`            | Message and the parent's help, on stdout  |

The exit code stays 2 in both modes, and for a flag suggestion.

## Limitations

- A parent whose Command Action declares arguments treats an unknown word as an argument, so no `COMMAND_NOT_FOUND` occurs and nothing is suggested, unless the action declines the word with [`unknownCommand()`](/docs/api/errors#unknowncommandcommand-name).
- [`run()`](/docs/api/crust#runpath-input-options) returns the failed outcome without presenting it.

title: No Color
description: Control terminal color with a recursive Extension flag.
---

## Usage

<include lang="ts" meta='title="cli.ts"'>
  ../../../../examples/modules/extensions/no-color.ts
</include>

```sh
$ my-cli --no-color
FORCE_COLOR=unset NO_COLOR=1
```

`noColor()` adds a recursive boolean `color` flag with no default. Normal boolean negation provides both `--color` and `--no-color`.

## Behavior

```sh
my-cli --color           # FORCE_COLOR=3; NO_COLOR is cleared
my-cli --no-color        # NO_COLOR=1; FORCE_COLOR is cleared
my-cli deploy --no-color # the flag is recursive
```

- The previous values are restored after the command finishes. Child processes started meanwhile inherit the new values.
- The variables are set before any flag handler runs, so `--help --no-color` prints help without color whatever the `.extend()` order.
- When neither flag is present, the environment is unchanged and [`@crustjs/style` color detection](/docs/modules/style#color-control) applies as usual.

<Callout title="Overlapping programmatic runs">
  The environment is process-global. Overlapping [`run()`](/docs/api/crust#runpath-input-options)
  calls may share a direction (all `--color` or all `--no-color`); the previous values return after
  the last one finishes. Starting a run with the opposing flag while another is in flight fails it
  with a `DEFINITION` `CrustError`.
</Callout>

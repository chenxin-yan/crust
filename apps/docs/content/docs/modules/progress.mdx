title: "Progress"
description: Progress indicators for CLI applications — task-scoped and imperative spinners, plus determinate progress.
---

`@crustjs/progress` provides stderr-based progress indicators for building polished CLI experiences: `spinner()` (task-scoped, or an imperative start/stop handle when called without a `task`) and `progress()` (determinate `current/total`), all with message updates, theming, SIGINT policy, and non-TTY fallbacks.

## Install

```sh
bun add @crustjs/progress
```

## Quick Example

```ts
import { spinner } from "@crustjs/progress";

const data = await spinner({
  message: "Fetching data...",
  task: async () => {
    const res = await fetch("https://api.example.com/data");
    return res.json();
  },
});
```

## API

### `spinner(options)`

Display a spinner animation while an async task runs. Non-interactive and output-only. On completion it prints a success (`✓`) or error (`✗`) line to `stderr`.

In non-interactive environments, the spinner skips animation and ANSI escape codes. Only the final success or error line is printed.

```ts
await spinner({
  message: "Installing dependencies...",
  task: async ({ updateMessage }) => {
    await installDeps();
    updateMessage("Building project...");
    await buildProject();
    updateMessage("Running checks...");
    await runChecks();
  },
  spinner: "arc",
});
```

### `spinner(options)` without `task` — imperative handle

Called without a `task`, `spinner()` returns a handle whose `start` and `stop` can live in different call frames — workflow engines, logger adapters, anywhere a task callback does not fit. `stop()` takes the final outcome, so a failure can render `✗` without throwing:

```ts
import { spinner } from "@crustjs/progress";

const handle = spinner({ message: "Deploying..." });
handle.start();

// ...later, in another call frame:
if (failed) {
  handle.stop("error", "Deploy failed");
} else {
  handle.stop("success", "Deployed");
}
```

`stop()` is idempotent; the default outcome is `"success"`. `SpinnerOutcome` is the union `"success" | "error"`.

### `progress(options)`

Determinate progress rendered as `⠋ <message> (<current>/<total>)`:

```ts
import { progress } from "@crustjs/progress";

const bar = progress({ total: files.length, message: "Translating" });
bar.start();
for (const file of files) {
  await translate(file);
  bar.advance(1, file.name);
}
bar.stop("success", "All files translated");
```

### SIGINT policy

`SpinnerSigintPolicy` is `"exit" | false`. By default an interactive spinner uses `"exit"`: it installs a `SIGINT` handler that restores the cursor and exits with code 130. Applications that own SIGINT (cleanup, log flushing) can opt out with `sigint: false` — the spinner then installs no handler, and the application's cleanup should call `stop()` to restore the cursor:

```ts
const handle = spinner({ message: "Working...", sigint: false });
process.once("SIGINT", () => {
  handle.stop("error", "Cancelled");
  flushLogs();
  process.exit(130);
});
```

### Updating the message

Passed into the task callback so you can update the current message while the task runs.

```ts
await spinner({
  message: "Preparing...",
  task: async ({ updateMessage }) => {
    updateMessage("Uploading...");
    await upload();
  },
});
```

### `SpinnerType`

Built-in options:

- `"dots"`
- `"line"`
- `"arc"`
- `"bounce"`

Or provide a custom frame set:

```ts
const custom = { frames: ["⊶", "⊷"], interval: 150 };
```

## Themes

`@crustjs/progress` has its own theme contract with four slots:

- `spinner`
- `message`
- `success`
- `error`

<auto-type-table path="../../../../../packages/progress/src/theme.ts" name="ProgressTheme" />

`PartialProgressTheme` is `Partial<ProgressTheme>` and is accepted for theme overrides.

The default theme uses these styles:

- `spinner`: `magenta`
- `message`: `bold`
- `success`: `green`
- `error`: `red`

There is no global theme state. Pass per-call `theme` overrides:

```ts
import { spinner } from "@crustjs/progress";
import { cyan, green } from "@crustjs/style";

await spinner({
  message: "Working...",
  theme: { spinner: cyan, success: green },
  task: async () => doWork(),
});
```

The bare `progress`/`spinner` exports use `defaultTheme`. Resolution order: `defaultTheme` ← per-call `theme` option. The public theme exports are `defaultTheme`, `ProgressTheme`, and `PartialProgressTheme`.

## Non-interactive behavior

When `stderr` is not a TTY, `spinner()` does not animate and does not emit cursor-control ANSI sequences. `updateMessage()` still works and updates the message used in the final success or error line.

`@crustjs/progress` writes progress indicators to stderr by default. It supports task-scoped spinners, imperative handles, determinate progress, themes, injected output, and static non-TTY output.

## Install

```npm
npm install @crustjs/progress
```

## Quick example

<include lang="ts">../../../examples/modules/progress.ts#spinner</include>

`spinner()` starts the indicator, awaits `task`, and prints a final line. The task receives `updateMessage()`.

```text
✓ Running checks
```

## API

Call `spinner({ task })` for a task-scoped indicator. Call `spinner()` without `task` for a `SpinnerHandle`, or `progress()` for a `ProgressHandle`.

### `spinner(options)`

```ts
await spinner({ message: "Building", task: async () => build() });
// success: ✓ Building
// failure: ✗ Building
```

`task` may return a value or a promise; `spinner({ task })` always returns a promise. A failed task prints the error line, then rejects with the task error. Non-TTY output omits animation and cursor-control sequences.

Interactive spinners and progress indicators keep the animated frame on one row: the whole frame (spinner symbol, message, count, and any text a custom theme adds) is cut with `…` at its first line break or where it would reach the terminal's last column. The message is cut first, so `progress()` keeps its count while the symbol and count fit; the final `✓`/`✗` line prints the message in full. Each redraw erases only the spinner's row, so complete lines the task writes to the same terminal, such as `console.log()` output while the spinner draws on stderr, stay on screen after the frame they interrupted. A write without a trailing newline begins on the spinner's row and is erased by the next frame; if it wraps, only its last row is erased. Narrowing a terminal that also reflows the cursor's row can leave the start of the previous frame above the spinner.

### Imperative spinner

```ts
const handle = spinner({ message: "Deploying" });
handle.start();
handle.updateMessage("Uploading");
handle.stop("success", "Deployed"); // ✓ Deployed
```

`stop()` defaults to `"success"` and later calls do nothing.

### `progress(options)`

<include lang="ts">../../../examples/modules/progress.ts#progress</include>

`progress()` renders `<message> (<current>/<total>)`. `advance()` defaults to one unit, changes the count, and may replace the message.

```text
✓ Files complete (2/2)
```

Calling `advance()` before `start()` changes the count without repainting. The updated count appears after the handle starts or in its final line.

### SIGINT policy

```ts
const handle = spinner({ message: "Working", sigint: false });
```

`SpinnerSigintPolicy` is `"exit" | false`. The default `"exit"` policy restores the cursor and re-raises `SIGINT` when no other listener remains. Use `false` when the application owns cleanup, and call `stop()` from that cleanup. Calling `process.exit()` while an interactive spinner is running restores the cursor under either policy when the sink writes synchronously.

### Custom spinner frames

```ts
spinner({ message: "Working", spinner: { frames: ["⊶", "⊷"], interval: 150 } });
```

Built-in names are `"dots"`, `"line"`, `"arc"`, and `"bounce"`. A custom frame array must not be empty.

## Themes

```ts
import { spinner } from "@crustjs/progress";
import { cyan } from "@crustjs/style";

spinner({ message: "Working", theme: { spinner: cyan } });
```

A `ProgressTheme` has `spinner`, `message`, `success`, and `error` style slots. Per-call values merge over `defaultTheme`; `PartialProgressTheme` names the override type.

## Output sinks

<include lang="ts">../../../examples/modules/progress.ts#sink</include>

A per-call `sink` wins over ambient terminal output, which wins over `process.stderr`. `withTerminalIO(io, fn)` takes the same optional `{ input, output }` streams as [`@crustjs/prompts`](/docs/modules/prompts#injecting-io) and shares its ambient scope.

## Non-interactive behavior

```text
✓ Deploying
✗ Deploy failed
```

A non-TTY sink gets one final line with no animation or cursor-control sequences. `updateMessage()` still determines the final message.

Default theme slots decide color from `sink.isTTY`, applying the `NO_COLOR` and `FORCE_COLOR` rules from [`@crustjs/style` color control](/docs/modules/style#color-control). Theme functions you pass, such as `@crustjs/style` imports, keep their own detection, which checks stdout.

---
title: "Man"
description: Generate mdoc(7) manual pages from Crust Command Snapshots.
---

`@crustjs/man` generates section 1 manual pages at build or publish time.

## Install

```sh
bun add -d @crustjs/man
```

Peer dependency: `@crustjs/core`.

## `man(options?)`

Register the build-only Extension to generate a manual whenever `crust build` prepares the application:

```ts
import { Crust } from "@crustjs/core";
import { man } from "@crustjs/man";

const app = new Crust("my-cli").extend(man());
```

`man()` writes `<outdir>/man/<name>.1`. Pass `man({ section: 5 })` to select another section and filename, and `man({ name: "my-tool" })` when the installed command name differs from the application name (for example, `crust build --name` or a diverging npm `bin` key). Extension presence is the source of intent; there is no `--man` build flag. `crust build --no-validate` skips all build hooks, including this one. Package builds stage the generated directory and populate npm `files` and `man` metadata.

## `writeManPage(options)`

```ts
function writeManPage(options: WriteManPageOptions): Promise<void>;
```

<auto-type-table
  path="../../../../../packages/man/src/write-man-page.ts"
  name="WriteManPageOptions"
/>

`writeManPage` renders a prepared Command Snapshot, creates parent directories, and writes the page.

```ts
import { writeManPage } from "@crustjs/man";
import { app } from "./cli.ts";

const root = await app.snapshot();
await writeManPage({
  root,
  name: "my-cli",
  outfile: "man/my-cli.1",
  section: 1,
});
```

`section` defaults to `1`. `date` overrides the `.Dd` value. Without `date`, rendering uses `SOURCE_DATE_EPOCH` in UTC when set, then falls back to the current local date. Generated dates use the English `Month D, YYYY` form expected by mdoc.

## `renderManPageMdoc(options)`

```ts
function renderManPageMdoc(options: RenderManPageMdocOptions): string;
```

<auto-type-table
  path="../../../../../packages/man/src/mdoc.ts"
  name="RenderManPageMdocOptions"
/>

Use this lower-level function when you want to render mdoc without writing a file. It does not accept a live command definition.

```ts
import { renderManPageMdoc } from "@crustjs/man";

const source = renderManPageMdoc({
  root: snapshot,
  name: "my-cli",
});
```

The renderer uses semantic mdoc(7) flag and argument macros. Its subcommand summary lists only the root command's immediate visible children. Root `meta.sections` visible to the `man` (`crust:man`) consumer are appended after the built-in sections as mdoc `.Sh` sections. Sections on visible subcommands are collected recursively with Core's `visibleSectionsFor()` helper under `.Sh COMMANDS`, with one `.Ss` subsection per canonical command path.

Target a section to man pages with `only: [man]`, or exclude it with `except: [man]`:

```ts
import { Crust } from "@crustjs/core";
import { man } from "@crustjs/man";

const documentedApp = new Crust("my-cli", {
  sections: [{ title: "FILES", body: "~/.config/my-cli.json", only: [man] }],
});
```

Prepare the command tree through the supported `app.snapshot()` method before calling either API. The package uses `buildCommandDocumentation()` from `@crustjs/core/tooling` internally for its lockstep first-party rendering model.

## Package script

```json
{
  "scripts": {
    "generate:man": "bun run scripts/generate-man.ts"
  },
  "files": ["dist", "man"],
  "man": ["./man/my-cli.1"]
}
```

Preview and lint locally:

```sh
bun run generate:man
man -l man/my-cli.1
mandoc -T lint -W warning man/my-cli.1
```

`writeManPage()` remains the lower-level API for custom pipelines that do not use the Extension build lifecycle.

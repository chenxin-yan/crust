`@crustjs/man` renders mdoc(7) manual pages from your command definitions, one per command: during `crust build` through the `man()` Extension, or from your own script.

## Install

```npm
npm install -D @crustjs/man
```

The package has a peer dependency on `@crustjs/core`.

## `man(options?)`

```ts
import { Crust } from "@crustjs/core";
import { man } from "@crustjs/man";

const app = new Crust("my-cli")
  .extend(man())
  .command("remote", (remote) => remote.command("add", (add) => add.action(() => {})));
```

```text
.crust/artifacts/man/my-cli.1
.crust/artifacts/man/my-cli-remote.1
.crust/artifacts/man/my-cli-remote-add.1
```

`man()` only registers a [build hook](/docs/modules/crust#extension-artifacts); it writes nothing at runtime. During `crust build`, the hook returns a page for every visible command, `man/<name>.<section>`, which the build writes, copies into the staged packages, lists in the root package's `man` field, and records as artifacts of `crust:man`.

- A page is named after its command's full path joined with `-`, as `git-commit(1)` documents `git commit`: `my-cli remote add` gets `my-cli-remote-add.1`, read with `man my-cli-remote-add`. The root page is named after the root command, which [`crust build` requires to match the installed command](/docs/modules/crust#commands-and-entries-bin).
- Hidden commands, and everything under them, get no page.
- The build fails when a page name is not letters, digits, `.`, `_`, and `-` starting with a letter or digit, naming the command, or when two commands get the same page name, such as `a-b` and `a b`.
- Pass `man({ section: 5 })` to change the section and file name.
- `man.id` is the Extension identity, for [section filtering](#page-contents).

## `writeManPage(options)`

```ts
import { writeManPage } from "@crustjs/man";

const root = await app.snapshot();
await writeManPage({ root, outfile: "man/my-cli.1" });
// Writes man/my-cli.1
```

<auto-type-table
  path="../../../../../packages/man/src/write-man-page.ts"
  name="WriteManPageOptions"
/>

`writeManPage()` renders one page of a Command Snapshot, the root's unless `path` names a command, creates parent directories, and writes it. Use it for a custom pipeline outside `crust build`, such as a package script:

```json title="package.json"
{
  "scripts": { "generate:man": "bun run scripts/generate-man.ts" },
  "files": ["dist", "man"],
  "man": ["./man/my-cli.1"]
}
```

```sh
npm run generate:man
man -l man/my-cli.1
mandoc -T lint -W warning man/my-cli.1
```

Here `scripts/generate-man.ts` imports your app and calls `writeManPage()` as above; npm's `man` field installs the page.

## `renderManPageMdoc(options)`

```ts
import { renderManPageMdoc } from "@crustjs/man";

const root = await app.snapshot();
const source = renderManPageMdoc({ root });
console.log(source.startsWith(".Dd ")); // => true
```

`renderManPageMdoc()` returns one page's mdoc text without writing a file: the root's, or with `path: ["remote", "add"]` that command's. It accepts a Command Snapshot, not a live definition, and throws for a path that names no visible command.

## Page contents

Each page documents its command: name, synopsis, description, `SUBCOMMANDS` (immediate visible children), `OPTIONS` (its effective flags, inherited ones included), `ARGUMENTS`, `EXAMPLES` from the command's `examples`, and `SEE ALSO`, which names the parent's page and each child's.

- Commands and flags of a [`.group()`](/docs/api/crust#grouptitle-block) are listed under a `.Ss` with its title. Grouped commands come first and the rest follow under `.Ss Additional commands`; ungrouped flags, including inherited ones, come first, without a subsection.
- A value-taking flag shows its `valueName`, or its type, as its `Ar` argument. A flag that can repeat (`multiple`, or `type: "count"`) ends with `...`.
- The command's [documentation sections](/docs/guide/commands#documentation-sections) follow as their own `.Sh`, before `SEE ALSO`, with uppercased titles (`Files` renders as `.Sh FILES`). Same-title sections merge at their first position.
- Descriptions, usage lines, and section bodies are plain text: backslashes and leading `.` or `'` are escaped, so `C:\tmp` or `\fB` render literally rather than as roff.
- Without `date`, `.Dd` uses `SOURCE_DATE_EPOCH` in UTC when set, then the current local date, in the English `Month D, YYYY` form mdoc expects.

```ts
new Crust("my-cli", {
  sections: [{ title: "FILES", body: "~/.config/my-cli.json", only: [man] }],
});
```

Use `only: [man]` to include a section only in manual pages, or `except: [man]` to omit it there.

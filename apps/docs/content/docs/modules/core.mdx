---
title: "Core"
description: Supported command-authoring runtime for Crust applications and Extensions.
---

`@crustjs/core` defines commands, routes and validates argv, constructs Contexts, applies Extensions, and runs Command Actions.

## Install

```sh
bun add @crustjs/core
```

## Quick example

```ts
import { Crust } from "@crustjs/core";

const app = new Crust("hello")
  .flags({ name: "verbose", type: "boolean", short: "v" })
  .action(({ flags, stdout }) => stdout(flags.verbose ? "hello!" : "hello"))
  .command("wave", (command) => command.action(({ stdout }) => stdout("o/")));

await app.execute();
```

Inline `.command()` defines app-local leaf subcommands; extract to [`defineCommand`](/docs/api/crust) when a command needs its own file, reuse, or a package. Commands declare Context demand with `.use(...factories)` and applications supply values with `.provide(...instances)`.

## Context-owned flags

Use top-level `ContextConfig.flags` when a flag exists to construct a dependency. The Context defines and consumes the flag once; `.provide()` installs it on the current command and later-added descendants:

```ts
import { Crust, defineContext, defineFlag } from "@crustjs/core";

const apiKey = defineFlag("api-key", { type: "string" });
const api = defineContext("api", { flags: [apiKey] }, ({ flags }) => ({
  apiKey: flags["api-key"],
}));

const app = new Crust("my-cli").provide(api());
```

Downstream commands and other Context setups call `await ctx.api`. See [Contexts](/docs/guide/contexts).

## Runtime exports

| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

| `defineExtensionId(id)`               | Mint a branded Extension identity from a non-empty, already-trimmed string                                                                                               |
| `defineFlag(name, definition)`        | Define one named flag, preserving its literal definition                                                                                                                 |
| `defineArg(name, definition)`         | Define one named positional argument, preserving its literal definition                                                                                                  |
| [`CrustError`](/docs/api/errors)      | Framework error for definition, routing, parsing, and validation failures                                                                                                |

## Typed invocation types

These types back [`run(path, input?, io?)`](/docs/api/crust) and the [`@crustjs/testing`](/docs/modules/testing) helpers.

| Type                | Description                                                                 |
| ------------------- | --------------------------------------------------------------------------- |
| `AnyCrust`          | Completed-app inspection and invocation with unknown result; no authoring   |
| `CommandTree`       | Compile-time command tree accumulated by `.add()`                           |
| `CommandPath`       | Every valid typed path through a command tree, including the root path `[]` |
| `CommandShape`      | Argument, flag, children, and action result shape of one command            |
| `CommandShapeAt`    | Resolve the command shape at a typed path                                   |
| `RunInput`          | Structured `args`, `flags`, and `raw` values accepted by `run()`            |
| `RunOutcome`        | Captured output with completed/result, finished/by, or failed/error         |
| `RunInputArguments` | Input tuple for a shape: optional when nothing is required                  |
| `RunArguments`      | Full `run()` rest tuple: input plus optional invocation I/O                 |
| `InputArgs`         | Pre-parse structured argument values for an argument definition list        |
| `InputFlags`        | Pre-parse structured flag values for a flag definition record               |
| `ParseResult`       | Syntax-parsed arguments, flags, and raw tokens before schema validation     |
| `ValidatedInput`    | Fully validated argument and flag values passed beyond the parser boundary  |
| `ParsedArgValue`    | Runtime-erased syntax-parsed positional value                               |
| `ParsedFlagValue`   | Runtime-erased syntax-parsed flag value                                     |

When calling `run()`, scalar JSON inputs accept JSON primitives, structurally compatible named interfaces, and mutable or readonly arrays/tuples; repeated JSON inputs use mutable occurrence arrays. URL inputs accept `URL` values. Types exclude non-JSON values such as `Date`, functions, and `bigint`. Payload identity is preserved without serialization or arbitrary unknown decoding. `undefined` omits optional input. Actual value kinds and input names are checked automatically.

Structured positionals must form a prefix; defaults do not fill gaps. Required core variadics without defaults use nonempty tuples. Known inputs stay strict, including literal choices and fresh-object excess keys. Dynamic authoring uses the same APIs; spread collections into variadic methods. Genuinely dynamic `AnyCrust` views permit broad paths/inputs with unknown results. See [Runtime input](/docs/guide/types#runtime-input).

`run()` is quiet and resolves after cleanup to `RunOutcome<R>`. Every branch has captured `stdout`/`stderr`: `completed` carries the typed action `result`, `finished` the finishing Extension `by`, and `failed` the original escaping `error` with partial output. It never presents errors or changes exit status. Inspect the status explicitly; `execute()` remains the live terminal adapter.

## Command boundary types

| Type                  | Description                                                          |
| --------------------- | -------------------------------------------------------------------- |
| `CrustCommandContext` | Typed context passed to a Command Action, including `rootCommand`    |
| `InvocationIO`        | Injectable `stdout` and `stderr` callbacks shared with Context setup |
| `CommandSnapshot`     | Readonly, serializable command description                           |
| `ArgSnapshot`         | Serializable argument projection                                     |
| `FlagSnapshot`        | Serializable flag projection                                         |

Every `run()` owns a quiet output capture. Optional callbacks forward each write once after capture; omitted channels stay quiet and sink failures become failed outcomes. Callback payloads are joined with `"\n"` without a trailing newline, trimming, or splitting multiline writes. Capture memory is proportional to output; separate streams do not promise total ordering or byte-perfect transcripts.

Core threads invocation IO through the existing ambient terminal seam, isolating nested/concurrent runs. Default prompt/progress output reaches captured stderr; progress uses non-TTY static lines. Prompt input is separate, and explicit terminal streams take precedence. Direct console/process writes, subprocesses, files, and explicit prompt streams are not intercepted. `execute()` without injected IO preserves native terminal behavior; use [runInteractive](/docs/modules/testing#runinteractiveapp-path-input) for fake-terminal interaction.

## Section consumers

A command section without an audience is available to every renderer. Use `only` or `except` with section consumers to narrow it; the two fields are mutually exclusive. A `SectionConsumer` is either a branded `ExtensionId` or an Extension/factory object carrying one, so official renderers can be passed directly while custom renderers can use their minted id:

```ts
import {
  defineExtensionId,
  type CommandSection,
  type CommandSnapshot,
  type ExtensionId,
} from "@crustjs/core";
import { sectionsFor, visibleSectionsFor } from "@crustjs/core/tooling";

export const WEB_DOCS: ExtensionId = defineExtensionId("acme:web-docs");

const sections: readonly CommandSection[] = [
  { title: "Overview", body: "Visible everywhere." },
  { title: "Web example", body: "Visible in web docs.", only: [WEB_DOCS] },
];

const webSections = sectionsFor(sections, WEB_DOCS);

function collectWebSections(snapshot: CommandSnapshot) {
  return visibleSectionsFor(snapshot, WEB_DOCS);
}
```

`visibleSectionsFor()` returns only section-bearing visible commands in canonical path order. The root path is `[]`; hidden commands and their descendants are skipped. Extension identities remain plain strings at runtime and match by value, so targeting remains stable when snapshots are cloned or serialized. Renderer packages expose their ids on factory statics; core has no built-in consumer registry. Official consumer ids use the `crust:` namespace, reserved by convention for official Crust identities. Third-party packages should namespace published ids with their own prefix, as in `acme:web-docs` above.

## Tooling subpath

Call `app.snapshot()` to prepare a frozen Command Snapshot for man-page, skill, and build generators. It materializes Extension contributions and command definitions and validates Extension-produced documentation sections without calling Command Actions. Command-authored sections are validated immediately by the constructor or `defineCommand()`. Authored and Extension-contributed documentation is available on each command under `meta.sections`.

The package root contains invocation-time authoring and execution APIs. Build- and render-time helpers live under `@crustjs/core/tooling`:

| Export                                                                             | Behavior                                                                                                                                                                                        |
| ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `isListed(command)`                                                                | Returns `false` only when `command.meta.hidden === true`.                                                                                                                                       |
| `sectionsFor(sections, consumer)`                                                  | Applies `only` / `except` audience filters while preserving section declaration order.                                                                                                          |
| `visibleSectionsFor(snapshot, consumer)`                                           | Returns section-bearing visible commands with the root at `[]`; hidden subtrees are skipped and children are traversed by locale-sorted canonical name.                                         |
| `formatDefault(value)`                                                             | Formats declared defaults; arrays become comma-separated values and strings retain JSON quotes.                                                                                                 |
| `formatDescription(description, default, choices, formatter?)`                     | Appends `[default: …]` and `[choices: …]` annotations in that order, optionally passing each annotation through `formatter`.                                                                    |
| `buildCommandDocumentation(snapshot, path?)`                                       | Builds a presentation-neutral visible tree with resolved usage, unfiltered `sections`, argument tokens, and every accepted flag spelling. `children` preserve Command Snapshot insertion order. |
| `CommandDocumentation` / `DocumentationArg` / `DocumentationFlag` / `UsageSegment` | The model and component types returned by `buildCommandDocumentation()`.                                                                                                                        |
| `SNAPSHOT_PATH_ENV` / `BUILD_OUT_DIR_ENV`                                          | Lockstep subprocess constants used for snapshot preparation and registered Extension `build` hooks.                                                                                             |

The subpath also re-exports `CommandSnapshot`. Except for that type consumed by `app.snapshot()`, these helpers are intended for first-party tooling that moves in lockstep with core.

Use [`@crustjs/extensions`](/docs/modules/extensions) for the official Extensions and [`@crustjs/crust`](/docs/modules/crust) as a development dependency for build tooling.

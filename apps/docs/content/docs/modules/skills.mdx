`@crustjs/skills` renders agent skills from a Command Snapshot. Build output is shipped with the CLI, then linked into agent directories when a user installs it.

## Install

```sh
bun add @crustjs/skills
```

## Packaged skills workflow

<include lang="ts">../../../examples/modules/skills.ts#write</include>

`writeSkills()` generates one skill from `app` and copies any authored `extras`. It replaces a dedicated output directory named `skills` and returns paths relative to that directory.

Each skill has its own directory:

```text
dist/skills/
└── my-cli/
    ├── SKILL.md
    └── commands/
        ├── my-cli.md
        └── deploy.md
```

Use `writeSkillsFromSnapshot()` when a prepared Command Snapshot is available. Omit `app` only when at least one authored extra is provided.

## Enable discovery and installation

<include lang="ts">../../../examples/modules/skills.ts#extension</include>

The Extension registers `my-cli skill` and `my-cli skill update`. It also adds an `Agent skills` section to root help and generated man pages.

```text
Agent skills
  Source: dist/skills/my-cli
```

`distDir` is read at runtime. The build hook writes generated and authored skills to the build output, and reports those files as artifacts owned by `crust:skills`.

```sh
my-cli skill
my-cli skill --all --scope project
my-cli skill update
```

`--scope` accepts `project` or `global`. With `--all`, scope comes from `--scope`, then `defaultScope`, then `global`; without `--all`, an interactive run prompts when neither setting is supplied.

## Link lifecycle and ownership

```text
project: .agents/skills/my-cli -> ../../dist/skills/my-cli
global:  ~/.agents/skills/my-cli -> /package/dist/skills/my-cli
```

Project links are relative and global links are absolute. The pre-run hook repairs stale or dangling Crust-owned links unless `autoUpdate: false`; it does not create links that were never installed.

A link is Crust-owned when its textual target ends in `skills/<name>`. Real directories and foreign links conflict unless `force: true` is passed to low-level installation.

## Supported agents

```text
project: .agents/skills/<name>
global:  ~/.agents/skills/<name>
```

Universal targets share those directories: amp, cline, codex, cursor, gemini-cli, github-copilot, kimi-cli, opencode, pi, replit, warp, and zed. Additional targets use agent-specific locations and are found through a non-executing `PATH` lookup.

When the working directory is the home directory, project scope becomes global scope. Result objects include the effective scope.

## Low-level link operations

```ts
await installSkill({ sourceDir, agents: ["opencode"], scope: "global" });
const status = await getSkillStatus({ name: "my-cli", sourceDir });
await uninstallSkill({ name: "my-cli" });
```

`getSkillStatus()` reports `linked`, `dangling`, `conflict`, or `absent` per agent directory. `uninstallSkill()` removes only owned links, including dangling links.

## Command sections

```ts
const deploy = defineCommand("deploy", {
  sections: [
    { title: "Safety", body: "Run preview first." },
    { title: "Agent procedure", body: "Inspect preview output.", only: [skill] },
  ],
});
```

Command metadata sections appear in generated skill documentation. Passing the `skill` factory in `only` limits a section to the skills renderer.

Sections with the same exact title share one heading and join their bodies. See [Command Snapshot sections](/docs/api/crust#snapshot) for shared snapshot behavior.

## Name validation

```ts
isValidSkillName("deploy-guide"); // true
isValidSkillName("Deploy Guide"); // false
```

Names contain 1 to 64 lowercase letters, digits, and hyphens. They cannot start or end with a hyphen or contain consecutive hyphens, matching the [Agent Skills specification](https://agentskills.io/specification).

## Source helpers and errors

```ts
const root = resolveSkillSource(new URL("../dist/skills", import.meta.url));
const skills = loadPackagedSkills(root);
```

`resolveSkillSource()` also checks beside the executable when the configured source is unavailable. `loadPackagedSkills()` validates each `SKILL.md` name and non-empty description, while skipping directories without a `SKILL.md`.

`SkillConflictError` covers install conflicts, `SkillSourceConflictError` covers duplicate authored names, and `SkillSourceUnavailableError` covers unresolved packaged sources.

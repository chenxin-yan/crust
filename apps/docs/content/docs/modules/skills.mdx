`@crustjs/skills` renders agent skills from a Crust command snapshot. Skills are built once, shipped as read-only files in the CLI package, and copied into an **agent directory** only when a user opts into passive discovery.

## Install

```sh
bun add @crustjs/skills
```

## Package-as-source workflow

A **skill source** is the directory shipped in your npm package. It is the single source of truth and contains both:

- A **generated skill**, rendered from the command tree and its `meta.sections`.
- Any **authored skills**, copied from hand-written bundle directories.

Build the source alongside your other package artifacts:

```ts
import { writeSkills } from "@crustjs/skills";
import { app } from "./cli.ts";
import pkg from "./package.json" with { type: "json" };

await writeSkills(app, {
  outDir: "dist/skills",
  version: pkg.version,
  bundles: ["skills/deployment-guide"],
});
```

Each skill gets its own directory containing `SKILL.md`, supporting files, and a self-describing `crust.json`. `writeSkills()` replaces `outDir` on every build and never writes to an agent directory.

Include the source in the published package:

```json
{
  "files": ["dist", "dist/skills"]
}
```

## Enable discovery and installation

Point the extension at the packaged source with a package-relative file URL:

```ts
import { Crust } from "@crustjs/core";
import { skill } from "@crustjs/skills";
import pkg from "./package.json" with { type: "json" };

export const app = new Crust("my-cli", { description: "My CLI" })
  .extend(
    skill({
      source: new URL("../skills", import.meta.url),
    }),
  )
  .action(() => {});
```

The extension registers `my-cli skill` and `my-cli skill update`. The management command reads every skill in the source and installs clean copies into selected agent directories. `--scope project|global` selects project or user locations; `--all` installs for universal and detected agents without prompting.

```sh
my-cli skill
my-cli skill --all --scope project
my-cli skill update
```

If the package-relative source cannot be found, Crust also checks for the same source directory next to `process.execPath`, which supports compiled distributions staged with their skills. An unresolved source makes the explicit `skill` command fail with a descriptive error, but does not prevent unrelated CLI commands from running.

## Updates and ownership

Every copied skill retains its `crust.json` ownership marker. Before ordinary commands run, the extension compares installed versions with the packaged source and refreshes stale copies. Set `autoUpdate: false` to disable this hook. Any version _difference_ counts as stale — there is no ordering, so two CLI versions sharing a global scope will each rewrite the installed copy toward their own packaged version.

Install, update, and uninstall refuse to clobber an agent directory without a valid marker for the requested skill. This protects manually authored and third-party directories. There is no mutable Crust store: the package skill source remains authoritative.

## Supported agents

Universal agents share one directory and appear as a single prompt choice:

- `amp`, `cline`, `codex`, `cursor`, `gemini-cli`, `github-copilot`, `kimi-cli`, `opencode`, `replit`

Additional agents are detected through a non-executing `PATH` lookup. The exported `AgentTarget` union contains the full list.

| Group      | Global path                       | Project path             |
| ---------- | --------------------------------- | ------------------------ |
| Universal  | `~/.agents/skills/<name>/`        | `.agents/skills/<name>/` |
| Additional | Agent-specific convention per CLI | Agent-specific path      |

When the working directory is the home directory, project scope resolves to global scope.

## Low-level copy operations

`installSkill()` copies one skill directory from a built source. `getSkillStatus()` and `uninstallSkill()` inspect or remove only owned agent-directory copies.

```ts
import { installSkill, getSkillStatus, uninstallSkill } from "@crustjs/skills";

await installSkill({
  sourceDir: new URL("../skills/my-cli", import.meta.url),
  agents: ["claude-code", "opencode"],
  scope: "global",
});

await getSkillStatus({ name: "my-cli" });
await uninstallSkill({ name: "my-cli" });
```

## Command sections

Add agent-facing guidance to a command's metadata. Each section is rendered as a Markdown heading and body in that command's generated documentation:

```ts
import { defineCommand } from "@crustjs/core";

const deploy = defineCommand(
  "deploy",
  {
    description: "Deploy",
    sections: [{ title: "Safety", body: "Use preview mode first." }],
  },
  (command) => command.action(() => {}),
);
```

## Name validation

Skill names follow the [Agent Skills specification](https://agentskills.io/specification): 1–64 lowercase alphanumeric characters and hyphens, with no leading, trailing, or consecutive hyphens. `writeSkills()` validates generated and authored names; `isValidSkillName()` is also exported for callers that need an early check.

## Source helpers and errors

`resolveSkillSource()` resolves a packaged source root (including the executable-relative fallback), and `loadPackagedSkills()` lists every self-describing skill directory inside it — the same discovery the extension uses.

Agent helpers back the install prompts: `detectInstalledAgents()` performs the non-executing `PATH` lookup, `getUniversalAgents()` / `getAdditionalAgents()` split the registry by class, and `isUniversalAgent()` classifies a single target.

Error classes:

- `SkillConflictError` — thrown when install, update, or uninstall would touch a directory not owned by the requested skill. Its `details` name the agent, output directory, and whether the conflict is a kind mismatch or a malformed manifest.
- `SkillSourceConflictError` — thrown by `writeSkills()` when two skills in one source share a name.
- `SkillSourceUnavailableError` — thrown when a packaged source cannot be resolved; the extension's auto-update hook treats it as "nothing shipped" and stays silent.

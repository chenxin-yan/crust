`@crustjs/skills` renders agent skills from a Crust command snapshot. Skills are built once, shipped inside the CLI package, and symlinked into an **agent directory** only when a user opts into passive discovery.

## Install

```sh
bun add @crustjs/skills
```

## Package-as-source workflow

A **skill source** is the `skills/` directory shipped in your npm package. It is the single source of truth and contains both:

- A **generated skill**, rendered from the command tree and its `meta.sections`.
- Any **authored skills**, included from hand-written bundle directories.

Build the source alongside your other package artifacts:

```ts
import { writeSkills } from "@crustjs/skills";
import { app } from "./cli.ts";
import pkg from "./package.json" with { type: "json" };

await writeSkills(app, {
  outDir: "dist/skills",
  version: pkg.version,
  bundles: ["skills/deployment-guide"],
});
```

`outDir` must be named `skills`. Each skill gets its own `skills/<name>/` directory containing `SKILL.md` and any supporting files. `SKILL.md` follows the [Agent Skills specification](https://agentskills.io/specification) and declares required `name` and `description` frontmatter. `writeSkills()` replaces `outDir` on every build and never writes to an agent directory.

Include the source in the published package:

```json
{
  "files": ["dist"]
}
```

## Enable discovery and installation

Point the extension at the packaged source with a package-relative file URL:

```ts
import { Crust } from "@crustjs/core";
import { skill } from "@crustjs/skills";

export const app = new Crust("my-cli", { description: "My CLI" })
  .extend(
    skill({
      source: new URL("./skills", import.meta.url),
    }),
  )
  .action(() => {});
```

The extension registers `my-cli skill` and `my-cli skill update`. The management command reads every skill in the source and creates links in selected agent directories. `--scope project|global` selects project or user locations; `--all` installs for universal and detected agents without prompting.

```sh
my-cli skill
my-cli skill --all --scope project
my-cli skill update
```

If the package-relative source cannot be found, Crust also checks for the same source directory next to `process.execPath`, supporting compiled distributions staged with their skills. An unresolved source makes the explicit `skill` command fail with a descriptive error, but does not prevent unrelated CLI commands from running.

## Link lifecycle and ownership

Project installations use relative symlinks to the logical package path. Global installations use absolute symlinks. The target agent must discover skills through symlinks; agents that ignore linked directories cannot use this installation method.

There is no fallback install mechanism, ownership manifest, or mutable Crust store. Package content is visible through installed links immediately. Before ordinary commands run, the extension repairs a dangling link whose textual target ends in `skills/<name>`; an exact current-source link is already healthy. It never creates a link that was not installed, and a resolving link to any other source is a conflict that automatic repair leaves unchanged. Automatic repair failures warn without preventing unrelated commands from running. `my-cli skill update` runs the same repair explicitly and reports failures. Set `autoUpdate: false` to disable the pre-run repair hook.

Install conflicts with real directories and resolving wrong-target links unless `force: true` explicitly replaces them. Replacement stages the new symlink before moving the old entry, so a staging failure preserves existing data. Uninstall removes exact current-source links and dangling suffix-matching links. `uninstallSkill()` requires `sourceDir` so resolving links to another source are left unchanged.

Symlink creation requires operating-system permission. If creation fails, installation reports a clear error suggesting that symlink permission be enabled.

## Supported agents

Universal agents share one directory and appear as a single prompt choice:

- `amp`, `cline`, `codex`, `cursor`, `gemini-cli`, `github-copilot`, `kimi-cli`, `opencode`, `replit`

Additional agents are detected through a non-executing `PATH` lookup. The exported `AgentTarget` union contains the full list.

| Group      | Global path                       | Project path            |
| ---------- | --------------------------------- | ----------------------- |
| Universal  | `~/.agents/skills/<name>`         | `.agents/skills/<name>` |
| Additional | Agent-specific convention per CLI | Agent-specific path     |

When the working directory is the home directory, project scope resolves to global scope.

## Low-level link operations

`installSkill()` links one `skills/<name>` source directory. `getSkillStatus()` reports `linked`, `dangling`, `conflict`, or `absent` for each agent directory, using `sourceDir` to distinguish dangling links from resolving wrong-target conflicts. `uninstallSkill()` removes exact or dangling owned links and requires `sourceDir` to protect resolving links to a different source.

```ts
import { installSkill, getSkillStatus, uninstallSkill } from "@crustjs/skills";

const sourceDir = new URL("../skills/my-cli", import.meta.url);

await installSkill({
  sourceDir,
  agents: ["claude-code", "opencode"],
  scope: "global",
});

await getSkillStatus({ name: "my-cli", sourceDir });
await uninstallSkill({ name: "my-cli", sourceDir });
```

## Command sections

Add agent-facing guidance to a command's metadata. Each section is rendered as a Markdown heading and body in that command's generated documentation:

```ts
import { defineCommand } from "@crustjs/core";

const deploy = defineCommand(
  "deploy",
  {
    description: "Deploy",
    sections: [{ title: "Safety", body: "Use preview mode first." }],
  },
  (command) => command.action(() => {}),
);
```

## Name validation

Skill names follow the [Agent Skills specification](https://agentskills.io/specification): 1–64 lowercase alphanumeric characters and hyphens, with no leading, trailing, or consecutive hyphens. `writeSkills()` validates generated and authored names; `isValidSkillName()` is also exported for callers that need an early check.

## Source helpers and errors

`resolveSkillSource()` resolves a packaged source root without canonicalizing its logical path and includes the executable-relative fallback. `loadPackagedSkills()` reads each `SKILL.md` frontmatter and validates that its declared name matches its directory.

Agent helpers back the install prompts: `detectInstalledAgents()` performs the non-executing `PATH` lookup, `getUniversalAgents()` / `getAdditionalAgents()` split the registry by class, and `isUniversalAgent()` classifies a single target.

Error classes:

- `SkillConflictError` — thrown when installation would replace a real directory or foreign link without `force: true`.
- `SkillSourceConflictError` — thrown by `writeSkills()` when two skills in one source share a name.
- `SkillSourceUnavailableError` — thrown when a packaged source cannot be resolved; the extension's repair hook treats it as "nothing shipped" and stays silent.

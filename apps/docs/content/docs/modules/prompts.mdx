`@crustjs/prompts` exports terminal prompts, an `$EDITOR` helper, a URL launcher, shared themes, injected terminal IO, and helpers for custom prompts. Prompt UI writes to stderr by default. A second entry, `@crustjs/prompts/extension`, asks a Crust command's missing values for you: see [Ask for missing values](#ask-for-missing-values).

## Install

```npm
npm install @crustjs/prompts
```

`@crustjs/core` is an optional peer needed only by the `@crustjs/prompts/extension` entry point; the root entry point never loads it. TypeScript is an optional peer.

## Injecting IO

<include lang="ts">../../../examples/modules/prompts.ts#io</include>

Each prompt accepts an optional second `TerminalIO` argument with optional `input`, `output`, and `signal`. Resolution is explicit IO, ambient `withTerminalIO()` IO, then `process.stdin` and `process.stderr`. Inside a Crust command the ambient `signal` is the invocation's, so a `SIGTERM`, a Ctrl-C delivered as a signal, or an aborted `execute({ signal })` cancels a waiting prompt without passing it.

The ambient `withTerminalIO()` scope is shared with `@crustjs/progress`.

## Prompts

All prompt functions accept `(options, io?)`. Choice functions preserve literal choice value types when their choices are not widened, and a `default` or `initial` outside literal choices is a compile error on that option, such as `Type '"bogus"' is not assignable to type '"eslint" | "prettier"'`. A plain-string choice is its own value, so `Choice<T>` only accepts plain strings that are themselves a `T`; non-string values such as numbers must use `{ label, value }` objects.

Keys typed ahead of a prompt are kept for it: a pasted `my-app⏎n⏎` answers two prompts in a row on the same input. A Ctrl+C or Ctrl+D among them cancels the prompt it was typed for.

### `input(options, io?)`

```ts
const name = await input({ message: "Name?", default: "anonymous" });
```


### `editor(options?, io?)`

```ts
const body = await editor({ initial: "## Summary\n", filename: "issue.md" });
```

Editor opens the user's editor on a temporary file holding `initial` and returns the file's text once the editor exits. The editor is `$VISUAL`, else `$EDITOR`, run by the shell as Git runs it, so a value such as `code --wait` works; on POSIX the shell `exec`s it, so it must be one command. It runs on the process's own stdin and stderr: its output goes to stderr, so a redirected stdout stays clean. The temporary file is named `filename`, a file name and not a path (editors pick syntax highlighting from its extension), and removed afterwards.

- Where `canPrompt()` is false it rejects with `NonInteractiveError` without starting the editor.
- It rejects when `filename` is a path, when neither variable is set, or when the editor exits with a non-zero status.
- When the resolved `signal` aborts, it stops the editor and rejects with `signal.reason`.

## Opening a URL

```ts
const url = "https://example.com/login";
if (!(await openUrl(url))) console.error(`Open ${url} in your browser.`);
```

`openUrl(url)` opens an `http` or `https` URL with the system launcher: `open` on macOS, `xdg-open`, or `rundll32 url.dll,FileProtocolHandler` on Windows. The URL is one argument, never passed through a shell, so `&` stays part of it. It resolves `true` when a launcher started and `false` when the URL is refused (another scheme, or control characters) or no launcher could start; it never throws. Always print the URL too, for a user without a browser. [`openBrowser()`](/docs/modules/auth#opening-the-browser) in `@crustjs/auth` is the same launcher with a stricter rule for URLs.

## Ask for missing values

<include lang="ts" meta='title="cli.ts"'>
  ../../../examples/modules/prompts-extension.ts
</include>

```text
$ my-cli deploy
✓ Service api
✓ Region eu
✓ Replicas 3
✓ Canary release? No
api → eu, 3 replicas, canary: false
```

The `prompts()` Extension from `@crustjs/prompts/extension` asks on a terminal for each argument and flag that has a `prompt` question and no value, before the action runs. The question's kind comes from the definition:

| Definition                                    | Question                                                                                                          |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `type: "boolean"`                             | Yes or no, [`confirm()`](#confirmoptions-io)                                                                      |
| `choices`                                     | One of them, [`select()`](#selectoptions-io)                                                                      |
| `choices` with `multiple: true` or `variadic` | Several of them, [`multiselect()`](#multiselectoptions-io)                                                        |
| Anything else                                 | Text, [`input()`](#inputoptions-io), converted as the same word on the command line: its `type` or custom `parse` |

- A value from argv, an environment variable, or another Extension, such as [`--input`](/docs/modules/extensions/json-input), is never asked for. A value that only has its `default` is asked for, with the default preselected; Enter keeps it.
- An empty answer to a question without a default leaves an optional value unset; a required one shows `A value is required` and stays open, as an empty pick does for a required list.
- A positional argument after one that is still omitted is not asked for: the command line could not take it either.
- Text the command line would reject shows the command line's own error, and the question stays open. A flag validated by a `schema` is checked after the questions, with the other values.

```text
┃ Replicas
  three│
  Expected a number for --replicas.
```

- It asks only under `execute()` where [`canPrompt()`](#non-interactive-environments) is true: never under typed `run()`, MCP, a pipe, or CI. There the command's own errors apply, such as `Error: Missing required argument "<service>"`.
- It asks nothing for a list without `choices`, a count flag, or an exclusive group. It has no masked question: ask for a secret with [`password()`](#passwordoptions-io) in the action, or take it from `env` or stdin.
- The key exists in every file of a project that imports `@crustjs/prompts/extension`, so command files need no import. Without `prompts()` in `.extend()`, a `prompt` key is a `DEFINITION` error (`unowned-key`), from source and in `crust build`. See [Own a definition key](/docs/guide/extensions#own-a-definition-key).

## Validation

```text
┃ Project name?
  │
  Name is required
```

A `validate` callback throws to reject input, and its error message renders inline. A Standard Schema parses the raw string, returns its transformed output type, and renders the first issue or `Validation failed`.

Async validators and schemas are supported. `initial` and non-interactive `default` values also pass through a configured schema or `validate` callback before being returned; a rejected value throws, for example `initial value rejected: Name is required`. `multiselect()` and `multifilter()` check `required`, `min`, and `max` on them the same way, for example `default value rejected: Select at least 2 items`.

## Non-interactive environments

```text
# input({ message: "Name?", default: "ci-user" }) on a non-TTY
ci-user

# input({ message: "Name?" }) on a non-TTY
NonInteractiveError: Prompts require an interactive terminal (TTY).
```

- With `initial`, every terminal prompt returns it without rendering; `editor()` instead seeds its file with it.
- A prompt renders only where `canPrompt(io?)` is true: its input and its output are both TTYs, and `CI` is unset (empty, `0`, or `false` in any letter case counts as unset) unless the input was injected through `io` or [`withTerminalIO()`](#injecting-io), as [`runInteractive()`](/docs/modules/testing#runinteractiveapp-argv) does. `CI` guards against a pseudo-terminal nobody answers.
- Otherwise, such as when stdin is piped or stderr is redirected, a prompt returns an explicitly supplied `default` (`password()` has none) or rejects with `NonInteractiveError`. `confirm()` defaults to yes interactively, but without a TTY only an explicit `default` counts.
- Ctrl+C or Ctrl+D rejects with a `DOMException` whose name is `AbortError`, and the prompt replaces its frame with a cancelled line, such as `✗ Project name?`.
- When the resolved `signal` aborts, the prompt draws the same cancelled line, restores the terminal (cursor shown, raw mode off), and rejects with `signal.reason`. An already-aborted signal rejects before rendering.

To choose before prompting, call `canPrompt(io?)`, the rule the prompts follow. The [`confirmation()` Extension](/docs/modules/extensions/confirmation) uses it too.

```ts
const runtime = flags.runtime ?? (canPrompt() ? await select({ choices: ["bun", "node"] }) : "bun");
```

## Custom prompts

<include lang="ts">../../../examples/modules/prompts.ts#custom</include>

`runPrompt()` owns rendering, input, submission, cancellation (Ctrl+C, Ctrl+D, and the resolved `signal`), redrawing after the terminal is resized, and theme merging. Accept `(options, io?)` and forward the IO argument to `runPrompt()`, like the built-ins, so callers and tests can inject streams. An optional `renderSubmitted` draws the submitted state and `renderCancelled` the cancelled one; without them the last frame stays on screen.

- Only one prompt may use a given input or output stream at a time.
- An error thrown by `render`, `handleKey`, `renderSubmitted`, or `renderCancelled` rejects the promise after the terminal is restored.
- `handleTextEdit()` provides the built-ins' cursor editing and returns `null` for keys it does not handle. The root also exports the fuzzy matching, list rendering, formatting, and glyph helpers the built-ins use; see [`index.ts`](https://github.com/chenxin-yan/crust/blob/main/packages/prompts/src/index.ts).

### Testing custom prompts

`renderPrompt()` from `@crustjs/prompts/testing` runs a prompt against a fake TTY, as in the example above. `type()` and `keys()` send input, `screen()` returns the latest ANSI-stripped frame (wrapped at 80 columns like a real terminal), and `answer` settles after submission. The subpath also exports `createPromptIO()` and `encodeKey()` for lower-level harnesses.

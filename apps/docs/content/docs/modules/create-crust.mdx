---
title: "create-crust"
description: Scaffold a new Crust CLI project interactively.
---

`create-crust` generates a minimal Crust application and configures it for standalone binary or Bun runtime distribution.

## Usage

Run it through your runtime's package runner or create command:

```sh
npm create crust@latest my-cli
# or
pnpm create crust@latest my-cli
# or
bunx create-crust@latest my-cli
# or
bun create crust@latest my-cli
# or
deno run -A npm:create-crust@latest my-cli
```

The optional directory argument sets the destination. Without it, the directory prompt defaults to `my-cli`.

## Prompt behavior

Explicit flags skip the corresponding prompts. Without those flags, prompts can also use defaults without rendering in non-interactive environments. For example, select Bun runtime distribution and decline dependency installation without either prompt:

```sh
bunx create-crust@latest my-cli --distribution runtime --no-install
```

The prompt defaults and behavior are:

- `--distribution`: Select `binary` for standalone executables or `runtime` for a JavaScript build run with Bun. The default is `binary`.
- `--install` / `--no-install`: Install or skip dependencies. The default is to install.
- `--git` / `--no-git`: Initialize or skip a Git repository. The default is to initialize; no repository is created when the destination is in a repo.
- `--overwrite` / `--no-overwrite`: When the destination requires an overwrite decision, `--overwrite` overwrites conflicting files without confirmation; `--no-overwrite` aborts without prompting. The default is not to overwrite.

The CLI collects every prompt before writing files, then scaffolds the project and optionally installs dependencies and initializes Git. The package name is inferred from the destination directory.

For the complete option definitions, see the [create-crust command source](https://github.com/chenxin-yan/crust/blob/main/packages/create-crust/src/index.ts), which tracks `main`.

Generated projects use the single-file `src/cli.ts` starter. See [Build and distribution](/docs/guide/build) for standalone binary workflows. The Bun runtime template uses a separate build command, `bun build src/cli.ts --target bun --outfile dist/cli.js`, and runs the result with `bun run dist/cli.js`. This is not `crust build --runtime node` and does not run Crust snapshot preparation or Extension build hooks.

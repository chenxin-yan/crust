---
title: "create-crust"
description: Scaffold a new Crust CLI project interactively.
---

`create-crust` generates a minimal Crust application for standalone binary or Bun runtime distribution.

## Usage

```sh
npm create crust@latest my-cli
pnpm create crust@latest my-cli
bunx create-crust@latest my-cli
bun create crust@latest my-cli
deno run -A npm:create-crust@latest my-cli
```

The optional directory argument sets the destination. Without it, the directory prompt defaults to `my-cli`.

## Prompt behavior

```sh
bunx create-crust@latest my-cli --distribution runtime --no-install
# Distribution mode starts at "Bun runtime package".
# Install dependencies starts at "No".
```

Explicit flags set the corresponding prompt's initial value. The distribution select and install or Git confirms still run in a TTY; the overwrite confirm runs only when the destination already needs an overwrite decision.

| Flag                             | Initial value or behavior                                                                            |
| -------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `--distribution binary\|runtime` | Selects the initial distribution; default is `binary`                                                |
| `--install`, `--no-install`      | Starts the install confirm at yes or no; default is yes                                              |
| `--git`, `--no-git`              | Starts the Git confirm at yes or no; default is yes; no prompt appears inside an existing repository |
| `--overwrite`, `--no-overwrite`  | Starts the conditional overwrite confirm at yes or no; default is no                                 |

The CLI collects prompt answers before writing files. It then scaffolds the project and optionally installs dependencies and initializes Git.

## Generated project

```text
my-cli/
├── .gitignore
├── README.md
├── package.json
├── tsconfig.json
└── src/
    └── cli.ts
```

The package name comes from the destination directory. Both templates use the single-file `src/cli.ts` starter.

```json title="runtime package scripts"
{
  "dev": "bun run src/cli.ts",
  "build": "bun build src/cli.ts --target bun --outfile dist/cli.js",
  "start": "bun run dist/cli.js"
}
```

Binary distribution uses `crust build`, while runtime distribution uses `bun build`. The runtime build does not perform Crust snapshot preparation or run Extension build hooks; see [Build and distribute](/docs/guide/build) for the binary workflow.

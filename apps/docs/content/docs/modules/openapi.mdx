title: "OpenAPI"

`@crustjs/openapi` gives a CLI backed by an HTTP API a `gh api`-style escape hatch: `<cli> api` lists and prints the operations of the OpenAPI document bundled with the CLI, offline, and sends authenticated requests to any endpoint, including ones no command wraps yet. The same client is a [Context](/docs/guide/contexts) your own commands can use.

## Install

```npm
npm install @crustjs/openapi
```

The package has a peer dependency on `@crustjs/core` and depends on `@crustjs/utils`. It uses the runtime's global `fetch`.

### Browse the spec

```sh
$ my-cli api --list
GET /users listUsers List users
$ my-cli api --spec listUsers
{"operationId":"listUsers","summary":"List users"}
```

- `--list` prints one line per operation: `METHOD path operationId summary`, leaving out an `operationId` or `summary` the spec lacks. A path item that is itself a local `$ref` (such as to `components.pathItems`) is followed, for `--list` and `operationId` lookup alike. Keys of `paths` that do not start with `/`, such as `x-*` extensions, are skipped.
- `--spec <operationId|path>` prints one line of JSON: the path item for a path such as `/users/{id}` (including its shared `parameters`), or the operation with that `operationId`. Local JSON Pointer `$ref`s (`#/...`, URI-encoded or not) are replaced by their targets, keeping sibling keys such as `description`; other `$ref`s, such as external files or `#anchor`, are kept as is, and so is a `$ref` that points back into its own chain, so recursive schemas stay finite. An unknown target fails with exit code 1.

### Send requests

```sh
my-cli api /users                                  # GET
my-cli api /users -F name=ada -F admin=true        # POST {"name":"ada","admin":true}
my-cli api /users -X GET -F page=2                 # GET /users?page=2
my-cli api /users/42 -X PATCH --body @patch.json   # body from a file; - reads stdin
my-cli api /users -H 'Accept: application/vnd.example+json'
my-cli api /users --paginate                       # every page, one JSON line each
```

`api <path>` resolves `path` below `baseUrl` (keeping the base URL's own path; an absolute URL is used as is, and `..` segments may leave that path — the boundary is the origin, not the path prefix) and sends it through the `apiClient` Context. Like `gh api`, the request must stay on the base URL's origin (scheme, host, and port, after URL normalization): an absolute URL to another origin, including tricks such as `https://api.example.com@evil.example`, fails with a `PARSE` [`CrustError`](/docs/api/errors) naming the URL and the allowed origin before any request, so credentials set with `-H` or `auth` never reach a host given on the command line. Only redirects and `--paginate` pages may leave the base URL's origin, and then without `Authorization`, `Cookie`, `Proxy-Authorization`, or any header named like an `auth` header.

- `-X, --method`: the HTTP method. Without it, the request is a `GET`, or a `POST` when fields or a body are given.
- `-F, --field key=value` (repeatable): `true`, `false`, `null`, and JSON numbers become JSON values (a number too large for a double, such as `1e309`, is rejected); anything else, such as `007`, stays a string. Fields form a JSON object body, or query parameters for `GET` and `HEAD` and when `--body` is given.
- `--body <value>`: the request body, inline, `@path` (relative to the working directory), or `-` for all of stdin. Stdin that something else already read to the end, such as `--input -` from the `input()` Extension, reads as an empty body.
- `-H, --header 'Key: Value'` (repeatable): request headers. They override the `auth` headers of the same name. A body is sent with `Content-Type: application/json` unless a header sets it.
- `--paginate`: after each successful page, calls `paginate(response)` with a copy of the response, so it may read headers or the body, and requests the page it returns until it returns `undefined`. A returned request without `init` reuses the previous request's method, headers, and body. Like a redirect target, the next page must be an `http:` or `https:` URL, and on another origin than the base URL's it is sent without `Authorization`, `Cookie`, `Proxy-Authorization`, or any header named like an `auth` header, including values set with `-H`. Each page body is printed as one JSON line (NDJSON): JSON is compacted by removing whitespace outside strings, so numbers keep their exact digits, and any other body, including an empty one, is printed as a JSON string. Without a `paginate` option, `--paginate` fails before any request.

The response body is printed to stdout as is. A non-2xx response still prints its body to stdout, then fails with an `ApiResponseError` (exit code 1) whose message, such as `GET /users/9: HTTP 404 Not Found`, goes to stderr; its `status` holds the code. A `-F` value without `=` or out of number range, a `-H` value without `:` or with a header name or value the runtime rejects, and an unreadable `--body` fail with a `PARSE` [`CrustError`](/docs/api/errors) before any request.

## `apiClient`

The `api` Context: a `fetch()` bound to the base URL and auth. `apiCommand()` provides it to every command, so a command declares it with `.use(apiClient)` and calls `(await ctx.api).fetch(path, init?)`, as `whoami` does above.

- `fetch(path, init?)` resolves `path` like `api <path>` and returns the `Response`. A `path` off the base URL's origin rejects with a `TypeError` before any request. It adds the `auth` headers the request does not set itself. Unless `init.redirect` is `"manual"` or `"error"`, `fetch()` follows redirects itself with the global `fetch()`'s rules: `http:` and `https:` targets only, at most 20 redirects per request (counted across origins), and `301`/`302` turn a `POST`, `303` any method but `GET` and `HEAD`, into a bodyless `GET`. A redirect to another origin than the base URL's continues without `Authorization`, `Cookie`, `Proxy-Authorization`, or any header named like an `auth` header, even when the request set its value. After a redirect, the response (and its `clone()`) reports `redirected` as `true` and `url` as the final URL. It passes the invocation's cancellation signal unless `init.signal` is given.
- `auth(input)` runs once per invocation, when a command first reads the Context, and receives the Context setup input (`signal`, `stdout`, `stderr`). It is not called for `api --list` or `api --spec`. Besides credentials, it may return any default headers, such as `User-Agent` or an API-version header; all of them are treated as credentials, so they go only to the base URL's origin.

## Out of scope

`@crustjs/openapi` does not generate one command per operation, filter output (`--jq`), or template endpoint paths: write commands for the operations that deserve them, with `apiClient` for the request.

Crust's command API works on Bun, Node.js, and Deno. Start with the same entrypoint; change the command that runs it.

## Run the same CLI

After [installing Crust](/docs/quick-start#manual-setup), save this as `src/cli.ts`:

<include lang="ts" meta='title="src/cli.ts"'>
  ../../../examples/quick-start/manual.ts
</include>

| Runtime | Library minimum | Run the TypeScript example            |
| ------- | --------------- | ------------------------------------- |
| Bun     | 1.4+            | `bun run src/cli.ts Ada`              |
| Node.js | 22+             | `node src/cli.ts Ada` (22.18+)        |
| Deno    | 2.8+            | `deno run --allow-env src/cli.ts Ada` |

All three print:

```text
Hello, Ada!
```

Node.js 22+ can run the published libraries, but the direct TypeScript command above needs **22.18+**. Use `"type": "module"` in `package.json` and erasable TypeScript syntax—no enums or parameter properties. See [Node's type stripping](https://nodejs.org/docs/latest-v22.x/api/typescript.html#type-stripping) for its limits.

## Choose a runtime for your project

```sh
npx create-crust@latest my-cli --runtime node
```

This selects Node.js for the generated `dev` script, TypeScript settings, and build output. Use `--runtime bun` or `--runtime deno` instead; Bun is the default choice. See [package setup](/docs/guide/build-and-distribution#set-up-packagejson) for the build and release scripts.

**The package manager does not choose the runtime.** npm, pnpm, Yarn, and Bun can install dependencies for either Bun or Node.js projects. The Deno scaffold uses `deno install`; for manual setup, use `deno add npm:@crustjs/core npm:@crustjs/extensions`.

## Deno permissions

The example above grants `--allow-env` because Crust reads environment variables during execution and terminal styling. Add permissions for the work your CLI does:

| Your CLI needs to…                | Add this flag before `src/cli.ts` |
| --------------------------------- | --------------------------------- |
| Read files in the current project | `--allow-read=.`                  |
| Write generated files to `dist`   | `--allow-write=./dist`            |
| Call an API                       | `--allow-net=api.example.com`     |
| Run Git                           | `--allow-run=git`                 |

These grants apply to library code too. Subprocesses run outside Deno's sandbox, so only allow trusted executables. See [Deno permissions](https://docs.deno.com/runtime/fundamentals/security/) for scoping and other permission types.

<Callout type="warn" title="Scaffolded Deno projects grant all permissions">
  The generated `dev` and `start` scripts use `-A` (all permissions). For sandboxed source
  execution, replace `-A` in `dev` with only the grants you need. Deno executables produced by
  `crust build` are also compiled with `-A`; choosing Deno does not make those binaries sandboxed.
</Callout>

## Build separately from running

You don't need Bun to run Node.js or Deno source. **`crust build` is separate, Bun-powered tooling**, even when producing Node.js or Deno output. The packaged CLI can use its embedded Bun runtime; Deno builds additionally require `deno` on `PATH`.

Node.js builds produce a JavaScript bundle; Bun and Deno builds produce standalone executables. Continue to [Build and distribution](/docs/guide/build-and-distribution) for targets, launchers, and publishing.

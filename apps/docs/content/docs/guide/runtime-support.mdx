Crust's command API works on Bun and Node.js. Start with the same entrypoint; change the command that runs it.

## Run the same CLI

After [installing Crust](/docs/quick-start#manual-setup), save this as `src/cli.ts`:

<include lang="ts" meta='title="src/cli.ts"'>
  ../../../examples/quick-start/manual.ts
</include>

| Runtime | Library minimum | Run the TypeScript example |
| ------- | --------------- | -------------------------- |
| Bun     | 1.4+            | `bun run src/cli.ts Ada`   |
| Node.js | 24+             | `node src/cli.ts Ada`      |

Both print:

```text
Hello, Ada!
```

Type checking needs TypeScript 5.9 or later. Before TypeScript 7, a one-character `short` outside the Basic Multilingual Plane, such as an emoji, is rejected. On 5.9, a `@crustjs/store` field's `validate` callback needs an explicit parameter type.

Node.js runs the TypeScript file directly by stripping its types. For that:

- Set `"type": "module"` in `package.json`.
- Use erasable TypeScript syntax only: no enums or parameter properties. See [Node's type stripping](https://nodejs.org/docs/latest-v24.x/api/typescript.html#type-stripping) for its limits.

## Choose a runtime for your project

```sh
npx create-crust@latest my-cli --runtime node
```

- `--runtime` selects the runtime for the generated `dev` script, TypeScript settings, and target runtime.
- The build output is a separate choice (`--artifact`); all four runtime/artifact combinations work. See the [`create-crust` options](https://github.com/chenxin-yan/crust/tree/main/packages/create-crust#options) for choices and defaults.

See [package setup](/docs/guide/build-and-distribution#set-up-packagejson) for the build and release scripts.

**The package manager does not choose the runtime.** npm, pnpm, Yarn, and Bun can install dependencies for either Bun or Node.js projects.

## Build separately from running

You don't need Bun to run Node.js source, but **`crust build` is Bun-powered tooling**, even when producing Node.js output.

- Installed from npm, `crust` embeds its own Bun, so you usually don't need to install Bun. The exception is building an arm64 host's own binary target; see [installing `@crustjs/crust`](/docs/modules/crust#install).
- Node.js binaries also need a `node` on `PATH` that meets [tsdown's executable requirements](/docs/guide/build-and-distribution#nodejs-binaries).

The runtime doesn't choose the output; `crust.artifact` does:

| Artifact          | What users need                   |
| ----------------- | --------------------------------- |
| Runtime package   | Bun or Node.js installed          |
| Standalone binary | Nothing: it embeds Bun or Node.js |

The distribution channel is a third choice. npm's generated launcher needs Node.js to select and start a binary; [direct downloads, Homebrew, or other installers](/docs/guide/build-and-distribution#custom-distribution) run the same binary without it. `crust publish` handles npm only. Continue to [Build and distribution](/docs/guide/build-and-distribution) for targets and release layouts.

An Extension contributes app-wide behavior from the root builder.

See the [Extensions module](/docs/modules/extensions) for the built-in packages.

<Callout type="warn">
  `.extend()` is root-only. A builder inside a `defineCommand()` recipe cannot call root methods.
</Callout>

## Author an Extension

<include lang="ts" meta='title="preview.ts"'>
  ../../../examples/extensions/diagnostics.ts#author
</include>

`defineExtension()` accepts flags, commands, Context dependencies, sections, build hooks, and invocation hooks. Here `preRun` prints a result and finishes before the Command Action.

Use `defineExtension(id, factory)` when callers need to configure the Extension. See [`Extension` and `ExtensionFactory`](/docs/api/types#extension-types) for the full contribution types.

## Required root metadata

<include lang="ts" meta='title="metadata.ts"'>
  ../../../examples/extensions/metadata.ts
</include>

The curried form declares metadata that must exist on the root. `.extend()` rejects the commented call at type-check time, while the versioned root gives hooks a required `string`.

Neither [`bun build`](https://bun.sh/docs/bundler) nor `crust build` runs a TypeScript check. Use `tsc --noEmit && crust build` so missing required metadata fails before the build.

## Owned flags and commands

<include lang="ts" meta='title="diagnostics.ts"'>
  ../../../examples/extensions/diagnostics.ts#owned-command
</include>

Extension commands attach at the root and appear in typed `run()` paths. Flags listed in an Extension are recursive by default; set `recursive: false` on an inline flag definition to keep it on the root.

## Command sections

<include lang="ts" meta='title="sections.ts"'>
  ../../../examples/extensions/sections.ts
</include>

The contribution targets the root with `command: []`. Help places it after Options:

```text
Options:
  -h, --help                   Show help

Environment:
  Set DEPLOY_TOKEN before running.
```

Renderers handle audience filtering and same-title merging as described by [`snapshot()`](/docs/api/crust#snapshot).

## Build hooks

<include lang="ts" meta='title="build.ts"'>
  ../../../examples/extensions/build.ts
</include>

A build hook receives the frozen Command Snapshot and absolute output directory, then returns artifact paths relative to that directory. `crust build` attributes those paths to the Extension:

```text
Preparing Command Snapshot...
  acme:manifest  1 file  acme-manifest/manifest.json
```

For package staging, each build hook must own and clean a unique top-level directory under the artifact output directory. See [`snapshot()`](/docs/api/crust#snapshot) for snapshot preparation during builds.

## Dependency injection

<include lang="ts" meta='title="providers.ts"'>
  ../../../examples/extensions/providers.ts
</include>

`provides` installs Context instances across the application tree. `uses` declares Context factories that an Extension's hooks consume through their lazy `ctx` bag.

## Hooks

<include lang="ts" meta='title="hooks.ts"'>
  ../../../examples/extensions/hooks.ts
</include>

`preRun` may finish an invocation, and `postRun` receives its completed, finished, or failed outcome. See [`ExtensionHooks`](/docs/api/types#extensionhooks) for hook contracts and the [execution model](/docs/guide/lifecycle) for ordering and error flow.

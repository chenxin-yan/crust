Import a function by default. Reach for a Context when setup is lazy and shared across commands, needs cleanup, or should own a flag.

<include lang="ts">../../../examples/guide/contexts.ts#basic</include>

```text
https://api.example.com/status
```

The Context is built only when the Command Action reads `ctx.api`. Values under `ctx` are always awaited because setup may be asynchronous.

## Setup and cleanup

<include lang="ts">../../../examples/guide/contexts.ts#setup-cleanup</include>

Contexts build on first use and dispose after the Command Action on success or failure. Put cleanup on the returned value as `[Symbol.dispose]` or `[Symbol.asyncDispose]` instead of adding `try`/`finally` to every action.

## Owned flags

<include lang="ts">../../../examples/guide/contexts.ts#owned-flags</include>

Let a Context own a flag when the flag configures that dependency rather than the command's work. `.provide()` makes the flag available to commands added below it, and setup receives the validated value.

See [`.provide()`](/docs/api/crust#provideinstances) for attachment and collision rules.

## Context dependencies

<include lang="ts">../../../examples/guide/contexts.ts#dependencies</include>

Use `uses` when one Context needs another during setup. Each dependency remains lazy until its value is read from `ctx`.

## Contexts in command trees

<include lang="ts">../../../examples/guide/contexts.ts#command-trees</include>

A reusable definition declares what it needs with `.use(factory)`, while the app supplies an instance with `.provide(factory())`. Provide the Context before adding the definition on that command path.

## Test doubles

<include lang="ts">../../../examples/guide/contexts.ts#doubles</include>

Use `.of(value)` to supply a precomputed value without running setup. It keeps the Context name and value type, so `status` runs unchanged against the fake.

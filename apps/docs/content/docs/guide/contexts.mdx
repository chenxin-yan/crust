A Context is a named command dependency. `context()` always returns a factory; invoke it and attach the resulting instance with `.provide()`.

```ts
import { context, Crust } from "@crustjs/core";

const database = context("db", (options: { url: string }) => ({
  query(sql: string) {
    return `${sql} on ${options.url}`;
  },
}));

const app = new Crust("app")
  .provide(database({ url: "postgres://localhost/app" }))
  .handle(({ ctx, stdout }) => stdout(ctx.db.query("select 1")));
```

For a factory with no options, use `void` and call it with `undefined`:

```ts
const clock = context("clock", (_options: void) => ({ now: () => Date.now() }));
const app = new Crust("app").provide(clock(undefined));
```

## Lazy construction and inheritance

Context values are constructed only after a command is routed, parsed, intercepted, and validated. A short-circuiting Extension does not construct them.

Contexts are inherited by descendant commands:

```ts
const app = new Crust("app")
  .provide(database({ url: process.env.DATABASE_URL! }))
  .command("status", (command) =>
    command.handle(({ ctx, stdout }) => stdout(ctx.db.query("select 1"))),
  );
```

Factories may be synchronous or asynchronous. Contexts on the resolved path are constructed in registration order.

## Context requirements in definitions

A reusable command declares the Context value types it needs. Mounting seeds a fresh command scope with the parent's current Context path:

```ts
import { defineCommand } from "@crustjs/core";

const status = defineCommand<{
  ctx: { db: { query(sql: string): string } };
}>()((command) =>
  command.command("check", (child) =>
    child.handle(({ ctx, stdout }) => stdout(ctx.db.query("select 1"))),
  ),
);

const app = new Crust("app")
  .provide(database({ url: "postgres://localhost/app" }))
  .mount("status", status);
```

The requirement is checked at `.mount()`, so call `.provide()` before mounting. A Context added on a later builder does not backfill an earlier mount.

## One name per command path

Providing two Context instances with the same name on one command path is a `DEFINITION` error. This includes a descendant re-providing a name it inherited.

Mounted definitions use the same rule. Because materialization starts with the parent's Context path, a definition or nested descendant that provides the same name is rejected during `.mount()`.

## Native disposal

Put cleanup on the constructed value using `Symbol.dispose` or `Symbol.asyncDispose`:

```ts
const database = context("db", async (options: { url: string }) => {
  const connection = await connect(options.url);

  return {
    query: (sql: string) => connection.query(sql),
    async [Symbol.asyncDispose]() {
      await connection.close();
    },
  };
});
```

Crust disposes constructed Context values in reverse construction order after success or failure. Prefer `Symbol.asyncDispose` when cleanup is asynchronous.

</Callout>

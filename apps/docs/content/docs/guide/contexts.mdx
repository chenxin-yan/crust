---
title: Contexts
description: Define lazy, typed dependencies with pull-based resolution and native cleanup.
---

A Context is a named dependency. `defineContext()` returns a factory; invoke it for `.provide()`, then pull its typed value with `await ctx.use(factory)`.

```ts
import { Crust, defineContext } from "@crustjs/core";

const database = defineContext("db", ({ options }: { options: { url: string } }) => ({
  query: (sql: string) => `${sql} on ${options.url}`,
}));

const app = new Crust("app")
  .provide(database({ url: "postgres://localhost/app" }))
  .action(async ({ ctx, stdout }) => {
    const db = await ctx.use(database);
    stdout(db.query("select 1"));
  });
```

The factory passed to `use()` is the token and the type source. Resolution is asynchronous, lazy, and memoized per invocation: unused providers do not run setup, and repeated or concurrent pulls return the same value.

A missing provider fails at the pull site with a `CrustError` whose message identifies the Context and recommends `.provide()`.

## Owned flags

A Context can own the flags used to construct its value. Attaching it installs those flags on the provider command and later-added descendants. Setup receives the validated owned slice only.

```ts
import { Crust, defineCommand, defineContext, defineFlag } from "@crustjs/core";

const apiKey = defineFlag("api-key", { type: "string" });
const api = defineContext("api", { flags: [apiKey] }, ({ flags }) => ({
  get: (path: string) => `${flags["api-key"] ?? "anonymous"}:${path}`,
}));

const deploy = defineCommand("deploy", (command) =>
  command.action(async ({ ctx, stdout }) => {
    stdout((await ctx.use(api)).get("/deploy"));
  }),
);

const app = new Crust("app").provide(api()).add(deploy);
```

Both `app --api-key secret deploy` and `app deploy --api-key secret` work. Hooks run before validation, so a `preRun` hook cannot pull a Context that owns flags. Pull it from the action or from `postRun` after a validated invocation; `ctx.finish()` skips validation, so its post-run path has the same restriction.

## Context dependencies

Context setup pulls other Contexts with the same typed resolver used by actions. Pull dependencies first, before acquiring resources.

```ts
const config = defineContext("config", () => ({ url: "postgres://localhost/app" }));
const database = defineContext("db", async ({ ctx }) => {
  const cfg = await ctx.use(config);
  return { query: (sql: string) => `${sql} on ${cfg.url}` };
});

new Crust("app").provide(database(), config());
```

Dependencies construct lazily when pulled and are memoized for the invocation. Provide order is free. Missing providers fail at the pull site with `missing-context`; dynamic dependency cycles fail with `context-cycle`.

Contexts are inherited by descendants present when the builder is added. Provide Contexts before `.add()`; immutable builder chains do not backfill already-added children.

## Test doubles

Every factory has `.of(value)`, which provides a precomputed value with the same name and type. It skips the real setup and its dependency pulls while retaining owned flags.

```ts
const fake = database.of({ query: (sql) => `fake: ${sql}` });
const app = new Crust("app").provide(fake).action(async ({ ctx, stdout }) => {
  stdout((await ctx.use(database)).query("select 1"));
});
```

## Cleanup

Put cleanup on the constructed value using `Symbol.dispose` or `Symbol.asyncDispose`. Values are disposed in reverse construction order after all `postRun` hooks, on success or failure.

```ts
const database = defineContext("db", async ({ options }: { options: { url: string } }) => {
  const connection = await connect(options.url);
  return {
    query: (sql: string) => connection.query(sql),
    async [Symbol.asyncDispose]() {
      await connection.close();
    },
  };
});
```

## Collisions

Context names and owned flag spellings must be unique on a command path. Extension `provides` uses the same validation as `.provide()`. TypeScript catches statically known application collisions; dynamically assembled and inherited collisions fail with `CrustError` code `DEFINITION`.

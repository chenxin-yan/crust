## Two invocation modes

Use `execute()` at a CLI entrypoint:

```ts
await app.execute();
```

It reads `process.argv.slice(2)` by default, presents failures through Extension `handleError` hooks, sets `process.exitCode` to `1` (or `130` for cancellation), and resolves.

Use `run()` for programmatic invocation:

```ts
await app.run(["deploy", "--dry-run"], {
  stdout: (line) => output.push(line),
  stderr: (line) => diagnostics.push(line),
});
```

It requires explicit argv, honors injected writers, throws the original error, does not render it, and does not modify `process.exitCode`.

## Successful invocation order

1. **Prepare definitions** — apply Extensions and reject command, flag, and alias collisions.
2. **Route** — resolve the command path.
3. **Parse syntax** — consume positional and flag tokens.
4. **Intercept** — run Extension intercepts in `.extend()` order. An intercept can stop here by not calling `next()`.
5. **Validate structure** — enforce required values, choices, and other core rules.
6. **Apply schemas** — validate and transform every schema-backed input, aggregating issues.
7. **Run the Command Handler**.

Code after `await next()` in an intercept runs while the chain unwinds, after the Command Handler beneath it.

## Error flow

Definition, routing, and parse failures occur before intercepts. Validation, schema, and Command Handler failures can unwind through intercepts that called `next()`.

With `run()`, the original value is thrown to the caller. Handler failures are never wrapped in `CrustError`.

With `execute()`, Crust first establishes a nonzero status, then invokes Extension `handleError` hooks in `.extend()` order. A hook can render and return or call `next()`; Core's default renderer terminates the chain.

A `DOMException` whose name is `"AbortError"` is cancellation. `execute()` sets status `130` and renders nothing. `run()` still throws it.

## Setup and cleanup

Use ordinary modules and closures for command-specific dependencies. Construct resources in the Command Handler and use `using` or `await using` for native, reverse-order cleanup. Use Extension `intercept` only for app-wide behavior around invocation.

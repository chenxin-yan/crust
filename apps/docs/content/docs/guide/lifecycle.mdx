## Two invocation modes

```ts
const app = new Crust("hello").action(() => "ok");
const exitCode = await app.execute({ argv: [] }); // 0
const outcome = await app.run([], {});
// { status: "completed", result: "ok", stdout: "", stderr: "" }
```

`execute()` is the terminal entrypoint: it reads argv, streams output, presents failures, and sets `process.exitCode` for them. `run()` takes a typed command path and structured input, then returns a captured `completed`, `finished`, or `failed` outcome after cleanup.

See [`execute()` options](/docs/api/crust#executeoptions) and [`run()` input and outcomes](/docs/api/crust#runpath-input-io) for the full contracts.

## Successful invocation order

<include lang="ts">../../../examples/guide/lifecycle.ts#order</include>

The captured output shows that cleanup finishes before `run()` returns.

1. Prepare the command tree by applying Extensions, recipes, flags, and sections.
2. Route the command path.
3. Parse argv for `execute()`, or bind structured input for `run()`.
4. Run Extension `preRun` hooks in registration order.
5. Check required values and positional structure.
6. Apply Standard Schemas and aggregate their issues.
7. Construct declared Contexts when first pulled.
8. Run the Command Action.
9. Run Extension `postRun` hooks in reverse registration order.
10. Settle Context setup, then dispose constructed Contexts in reverse order.

## Error flow

```ts
const outcome = await app.run([], {});
if (outcome.status === "failed") console.error(outcome.error);
// run() returns the escaping error instead of presenting it.
```

`run()` captures preparation, invocation, and cleanup failures in its outcome. `execute()` presents dispatch failures through Extension hooks and sets the terminal status. See [Error flow](/docs/guide/error-handling#error-flow) for hook, disposal, and cancellation behavior.

## Setup and cleanup

```ts
const database = defineContext("database", ({ stdout }) => ({
  [Symbol.dispose]() {
    stdout("database closed");
  },
}));
```

Use a Context for lazy command-specific setup and disposal. Use Extension hooks for app-wide work around an invocation, and keep one-off setup in the Command Action.

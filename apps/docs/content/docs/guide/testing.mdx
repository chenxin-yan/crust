Core `app.run()` captures ordinary command output. `@crustjs/testing` adds terminal execution capture and fake interactive streams for application tests.

Its required peers are `@crustjs/core`, `@crustjs/progress`, and `@crustjs/prompts`; install any your project does not already have. TypeScript is an optional peer.

```sh
bun add -d @crustjs/testing
```

## Capture command output

<include lang="ts">../../../examples/guide/testing.ts#capture-output</include>

Each `ctx.stdout()` or `ctx.stderr()` payload is captured unchanged, and payloads from separate calls are joined with `"\n"`. Embedded newlines remain in the captured string.

Use `app.run()` when you need ordinary output or the Command Action result. See the [full `run()` contract](/docs/api/crust#runpath-input-io) for outcome and failure behavior.

Default prompt and progress output reaches captured `stderr` through a non-TTY adapter. A spinner emits only its final line, but this capture does not provide interactive input.

## Capture terminal execution

```ts
import { expect, test } from "bun:test";
import { captureExecute } from "@crustjs/testing";

import { app } from "./cli.ts";

test("renders invalid input", async () => {
  const result = await captureExecute(app, ["--unknown"]);

  expect(result.stdout).toBe("");
  expect(result.stderr).toContain("Unknown flag");
  expect(result.exitCode).toBe(1);
});
```

Use `captureExecute()` for the terminal `execute()` path, including Extension error rendering and exit codes. It captures output and restores the prior process exit state after the test.

See [`captureExecute()`](/docs/modules/testing#captureexecuteapp-argv) for raw argv and cancellation behavior.

## Fake a Context

```ts
import { Crust } from "@crustjs/core";
import { database } from "./contexts.ts";

const app = new Crust("my-cli")
  .provide(database.of({ query: (sql) => `fake: ${sql}` }))
  .action(async ({ ctx, stdout }) => stdout((await ctx.database).query("select 1")));
```

Every `defineContext()` factory carries `.of(value)`, which provides a precomputed value without running setup. See [Context test doubles](/docs/guide/contexts#test-doubles).

## Test interactive commands

```ts
import { expect, test } from "bun:test";
import { runInteractive } from "@crustjs/testing";

import { app } from "./cli.ts";

test("collects a name", async () => {
  const run = runInteractive(app, []);
  await run.waitFor(/Name\?/);

  run.type("Ada");
  run.keys("return");
  await run.done;

  expect(run.screen()).toContain("Name? Ada");
});
```

Use `runInteractive()` when a Command Action renders a built-in prompt. Its `type()` and `keys()` methods send terminal input, while `waitFor()` and `screen()` observe prompt, progress, and `stderr` output in one transcript.

`stdout` does not appear in `screen()`, so use `app.run()` for stdout assertions. See [`runInteractive()`](/docs/modules/testing#runinteractiveapp-path-input) for completion and timeout behavior, and see the [prompt testing helpers](/docs/modules/prompts#testing-custom-prompts) for supported key names.

## For custom prompt authors

```ts
import { expect, test } from "bun:test";
import { renderPrompt } from "@crustjs/prompts/testing";

import { myPrompt } from "./my-prompt.ts";

test("collects a name", async () => {
  const prompt = renderPrompt(myPrompt, { message: "Name?" });
  prompt.type("Ada");
  prompt.keys("return");

  expect(await prompt.answer).toBe("Ada");
});
```

<Callout type="warn" title="Built-in prompts are already covered">
  Do not test built-in prompts here. Use this helper only for a custom `(options, io?)` prompt.
</Callout>

Use `@crustjs/prompts/testing` directly for custom prompt functions.

---
title: Testing
description: Test command results, terminal behavior, and prompts.
---

Use `run()` for values and errors, `captureExecute()` for what a terminal user sees, and `runInteractive()` for prompts.

```npm
npm install -D @crustjs/testing
```

`@crustjs/testing` requires `@crustjs/core` as a peer. `runInteractive()` lives in `@crustjs/testing/interactive` and also needs `@crustjs/prompts`; install it if your project does not already use it.

## Inspect values and errors

<include lang="ts">../../../examples/guide/testing.ts#run</include>

`run()` answers whether a Command Action completed, finished early, or failed, and captures its result, error, `stdout`, and `stderr`. Use it for tests and embedding; see the [full `run()` contract](/docs/api/crust#runpath-input-options).

When many tests target one subcommand, bind it once with [`app.at(path)`](/docs/api/crust#atpath) and call `handle.run(input?, options?)` with the same typed input and outcome.

## Capture terminal behavior

<include lang="ts">../../../examples/guide/testing.ts#capture-execute</include>

`captureExecute()` answers what `execute()` would print and which exit code it would set. It includes Extension error rendering and restores the prior process exit state after the test; see the [`captureExecute()` reference](/docs/modules/testing#captureexecuteapp-argv).

## Drive prompts

<include lang="ts">../../../examples/guide/testing.ts#interactive</include>

`runInteractive()` answers what a user sees while a built-in prompt reads fake terminal input. `screen()` contains prompt, progress, and `stderr` output, while `stdout` remains available from `run()`; see the [`runInteractive()` reference](/docs/modules/testing#runinteractiveapp-path-input).

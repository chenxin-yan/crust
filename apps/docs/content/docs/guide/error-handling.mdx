## CrustError

<include lang="ts">../../../examples/guide/error-handling.ts#crust-error</include>

Narrow a failed outcome with `instanceof CrustError`, then use `.is()` to narrow its code and details. Crust uses four codes; see the [error codes and details](/docs/api/errors#codes) for the full reference and [compile-time and runtime checks](/docs/guide/types#compile-time-checks) for what is checked where.

| Code                | Meaning                                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------------------------- |
| `DEFINITION`        | A malformed dynamic definition or collision, recipe, Extension, Context, or documentation-section error |
| `PARSE`             | Argv syntax, structured `run()` input binding, or built-in conversion failure                           |
| `VALIDATION`        | Missing or invalid values, including Standard Schema issues                                             |
| `COMMAND_NOT_FOUND` | An unknown command under the [routing rules](/docs/guide/commands#unknown-commands)                     |

## Error flow

<include lang="ts">../../../examples/guide/error-handling.ts#cleanup</include>

A Command Action failure still runs `postRun` hooks, then disposes pulled Context values. The [propagation boundaries](/docs/api/errors#propagation-boundaries) cover failures from other lifecycle phases.

### Failed outcomes

<include lang="ts">../../../examples/guide/error-handling.ts#failed-outcome</include>

`run()` returns the application error in a `failed` outcome and keeps output written before cleanup completes. See [`run()` input, output, and failure behavior](/docs/api/crust#runpath-input-io) for the full contract.

### Terminal presentation

<include lang="ts">../../../examples/guide/error-handling.ts#terminal-presentation</include>

`execute()` offers a failure to `onError` hooks and returns the terminal exit code. Returning `true` claims the failure, so Core does not render it again.

## Cancellation

<include lang="ts">../../../examples/guide/error-handling.ts#cancellation</include>

Treat an `AbortError` returned by `run()` as cancellation. The [propagation boundaries](/docs/api/errors#propagation-boundaries) describe terminal cancellation behavior.

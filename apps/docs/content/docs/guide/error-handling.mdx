## CrustError

Crust uses exactly four framework error codes:

| Code                | Meaning                                                                   |
| ------------------- | ------------------------------------------------------------------------- |
| `DEFINITION`        | An invalid command, Extension, Context, flag, alias, or schema definition |
| `PARSE`             | Argv syntax, unknown flag, or built-in conversion failure                 |
| `VALIDATION`        | Missing/invalid values or aggregated Standard Schema issues               |
| `COMMAND_NOT_FOUND` | An unknown subcommand at the current command path                         |

```ts
import { CrustError } from "@crustjs/core";

try {
  await app.run(argv);
} catch (error) {
  if (error instanceof CrustError && error.is("VALIDATION")) {
    console.error(error.details?.issues);
  }
}
```

A `CrustError` exposes `code`, `message`, `details`, optional `cause`, `.is(code)`, and `toJSON()`.

`COMMAND_NOT_FOUND` details contain `input`, `available`, `commandPath`, and `parentCommand`, a readonly serializable Command Snapshot.

## Application errors pass through

Errors from Command Handlers and Context construction or disposal are not wrapped:

```ts
const failure = new Error("service unavailable");
const app = new Crust("app").handle(() => {
  throw failure;
});

try {
  await app.run([]);
} catch (error) {
  console.assert(error === failure);
}
```

Use ordinary application error classes when callers need to distinguish domain failures.

## Terminal presentation

Extension `onError` hooks present failures for `execute()`:

```ts
import { defineExtension } from "@crustjs/core";

const serviceErrors = defineExtension("service-errors", {
  hooks: {
    onError(error, ctx) {
      if (!(error instanceof Error) || error.name !== "ServiceUnavailableError") return;
      ctx.stderr(error.message);
      return true;
    },
  },
});
```

A hook returns `true` after rendering, or a falsy value to delegate to the next hook. Core's default renderer is last. Core establishes a nonzero status before invoking the chain, so presentation cannot turn a failure into success.

`run()` never invokes these hooks. It throws the original error and leaves rendering and exit status to its caller.

## Cancellation

Prompt cancellation and other cooperative cancellation use a `DOMException` named `"AbortError"`:

```ts
try {
  await app.run(argv);
} catch (error) {
  if (error instanceof DOMException && error.name === "AbortError") {
    return;
  }
  throw error;
}
```

`execute()` treats this as silent cancellation and sets `process.exitCode` to `130`. `run()` throws the same exception.

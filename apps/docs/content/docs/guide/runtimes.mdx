## Supported runtimes

```sh tab="Bun"
bun add @crustjs/core
```

```sh tab="Node.js"
npm install @crustjs/core
```

```sh tab="Deno"
deno add npm:@crustjs/core
```

`@crustjs/core`, `style`, `prompts`, `progress`, `store`, `skills`, `man`, `extensions`, and `testing` support Bun 1.3.14+, Node.js 22+, and Deno 2.8+, as do `create-crust` and `@crustjs/create`. [`@crustjs/tui`](/docs/modules/tui) is Bun only because OpenTUI uses a native library over FFI. The `crust` build CLI is Bun tooling, while its npm package and CLIs made with `crust build --package` use a Node launcher for standalone binaries that embed Bun.

## Deno permissions

```sh
# Scope file and subprocess permissions to what this CLI uses.
deno run --allow-run=git --allow-read=. --allow-write=./dist --allow-env ./src/cli.ts
```

Deno applies its permission sandbox to library code. See [Deno permissions](https://docs.deno.com/runtime/fundamentals/security/) for the host runtime rules and flag syntax.

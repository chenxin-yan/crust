## Run from source

```sh
bun run src/cli.ts --help
bun --watch src/cli.ts
```

Keep one terminal entrypoint:

```ts
await app.execute();
```

## Test programmatically

Use the [Testing guide](/docs/guide/testing) for `captureRun()` and `runInteractive()` helpers. It also explains when custom prompt authors should use `@crustjs/prompts/testing` directly.

## Prepare the build snapshot

```sh
crust build
```

The build snapshot subprocess evaluates the entry under Bun for every target runtime, including Node and Deno. Packaged Crust uses its embedded Bun for this step. It prepares the complete command graph, validates documentation sections, and runs Extension build hooks before compilation, with a 30-second timeout for the subprocess. Target-only APIs used during preparation can fail under Bun. `--no-validate` skips this runtime validation and all build hooks; with `--package`, it also skips artifact-directory staging. See [snapshot preparation](/docs/guide/build#pre-compile-snapshot-preparation).

## Inspect input

A Command Action receives validated `args`, `flags`, Context values under `ctx`, forwarded `rawArgs`, a readonly `command` snapshot, and injectable writers. Extension hooks receive syntax-parsed invocation data and Command Snapshots.

## Project structure

Start with one `src/cli.ts`. When command files become large, export the root builder and use the [split-file pattern](/docs/guide/split-files). Keep Extensions at the root and place reusable setup in [Contexts](/docs/guide/contexts).

Use a positional argument for the thing a command acts on, and a flag for how it should act.

<include lang="ts" meta="twoslash">
  ../../../examples/guide/inputs.ts
</include>

```sh
$ convert report.md --format markdown
Converting report.md as markdown
```

The Command Action receives both values under the names in their definitions.

## Arguments

<include lang="ts" meta="twoslash">
  ../../../examples/guide/arguments-defaults.ts
</include>

```sh
$ convert report.md
report.md -> json
$ convert report.md yaml draft
report.md -> yaml (draft)
$ convert
Error: Missing required argument "<input>"
```

Positional values fill definitions in order. Each definition is one of:

| Definition       | Omitted value                | Type in the action    |
| ---------------- | ---------------------------- | --------------------- |
| `required: true` | Fails before the action runs | `string`              |
| `default: value` | The default                  | `string`              |
| Neither          | `undefined`                  | `string \| undefined` |

See [`ArgDef`](/docs/api/types#argdef) for every option.

### Variadic arguments

<include lang="ts" meta="twoslash">
  ../../../examples/guide/arguments-variadic.ts
</include>

```sh
$ copy dist a.ts b.ts
2 files to /home/me/project/dist
```

A final `variadic: true` argument takes any number of values as an array. `type: "path"` resolves each value against the working directory.

### Choices

<include lang="ts" meta="twoslash">
  ../../../examples/guide/arguments-choices.ts
</include>

```sh
$ run python
Error: Invalid value for <runtime>. Expected one of: bun, node
```

`choices` types the value as their string union (plus `undefined` here, since the argument is neither required nor defaulted). Any other value fails before the action runs.

### Pass through raw tokens

<include lang="ts">../../../examples/guide/arguments-raw.ts</include>

```sh
$ wrap -- --watch src
--watch src
```

Tokens after `--` are never parsed as flags. Use them for wrapper commands that pass options to another tool:

- They first fill declared positional arguments that are still empty: `wrap [target] -- --watch src` binds `target` to `--watch`.
- A variadic argument takes all of them.
- The rest reach the Command Action as `rawArgs`.

This follows the POSIX utility syntax guidelines ([Guideline 10](https://pubs.opengroup.org/onlinepubs/9799919799/basedefs/V1_chap12.html#tag_12_02)): tokens after `--` are operands, like the positionals before it. getopt, Node.js `util.parseArgs`, Commander, and clap behave the same way by default.

#### Only after `--`

<include lang="ts" meta="twoslash">
  ../../../examples/guide/arguments-after-double-dash.ts
</include>

```sh
$ run build core cli -- --watch
build in core, cli: --watch
```

`afterDoubleDash: true` makes an argument take only the tokens after `--`, like clap's [`Arg::last`](https://docs.rs/clap/latest/clap/struct.Arg.html#method.last). Use it when the arguments before `--` and the ones after it belong to different consumers, as in `run <task> [packages...] -- <args...>`:

- Only the last argument can set it. It can be variadic, and the argument before it can be variadic too.
- The other arguments fill only from tokens before `--`, so a variadic before it stops at `--`.
- Without variadic, it takes one token; the remaining tokens after `--` reach `rawArgs`.
- If it is required and missing, the error says to pass it after `--`.
- Help shows it after `[options]` as `[-- <extra>...]` (`run <task> [packages...] [options] [-- <extra>...]`), or `-- <extra>...` when required. Shell completion offers its values only after `--`.
- [`run()`](/docs/api/crust#runpath-input-options), `--input`, and MCP supply it by name like any other argument.

## Flags

<include lang="ts" meta='title="src/cli.ts" twoslash'>
  ../../../examples/guide/flags.ts
</include>

```sh
$ serve --color --port 3000
color=true port=3000
$ serve
color=undefined port=undefined
$ serve --port nope
Error: Expected a number for --port.
```

`.flags()` takes one record keyed by flag name, without the `--` prefix. Use boolean flags for switches and value-taking flags for named settings.

- **Names:** quote a name that is not an identifier, such as `"dry-run"`, and read it as `flags["dry-run"]`. A name must not contain whitespace or `=`, or start with `-`. TypeScript rejects such a literal name; a computed one throws a `DEFINITION` error.
- **Omitted:** a flag without `required`, `default`, or an `env` binding is `undefined`.
- **Values:** a value-taking flag needs one value, so `serve --port` fails. Built-in types convert the text and reject invalid input, including a blank number, before the action runs.

Malformed argv, such as an unknown flag or `serve --port --help`, fails before any hook runs. Invalid values fail later, after [flag handlers and `preRun` hooks](/docs/guide/extensions#hooks), so `serve --port nope --help` with [`help()`](/docs/modules/extensions/help) still prints help. An invalid value is reported before a missing required one.

### Required and defaulted values

<include lang="ts" meta='title="src/publish.ts" twoslash'>
  ../../../examples/guide/flags-required.ts
</include>

```sh
$ publish --token example
publishing to npm
$ publish
Error: Missing required flag "--token"
$ echo $?
1
```

`default` fills in an omitted value, like `registry` above. `required: true` fails before the action runs when the value is missing. Either way, the value is non-optional in the action.

### Aliases and negation

<include lang="ts" meta='title="src/serve.ts"'>
  ../../../examples/guide/flags-aliases.ts
</include>

```sh
$ serve --colour
color=true
$ serve -c
color=true
$ serve --no-colour
color=false
```

- `short` sets a one-character (one code point) alias; `aliases` sets long aliases. Every spelling writes to the flag's key.
- Boolean flags also accept `--no-<name>` and `--no-<alias>`, unless `noNegate: true`.

See the [`.flags()` contract](/docs/api/crust#flagsflags) for all accepted spellings.

### Repeated values

<include lang="ts" meta='title="src/serve-values.ts" twoslash'>
  ../../../examples/guide/flags-values.ts
</include>

```sh
$ serve --target linux -t darwin
targets=linux,darwin runtime=bun tag=undefined
```

`multiple: true` lets a flag occur more than once; each occurrence adds one value, in order. Omitted, it is `undefined` unless it has a default or `env` binding.

Repeat the flag for every value, or set a [`delimiter`](#delimiters). In `--target linux darwin`, `darwin` is a positional argument, not another target.

### Flag choices

`choices` restricts a flag to a fixed set of strings, like `runtime` above:

```sh
$ serve --runtime node
targets=undefined runtime=node tag=undefined
$ serve --runtime python
Error: Invalid value for --runtime. Expected one of: bun, node
$ echo $?
1
```

### Environment variables

<include lang="ts" meta='title="src/publish.ts"'>
  ../../../examples/guide/flags-env.ts
</include>

```sh
$ PUBLISH_TOKEN=example publish
publishing to npm tags=undefined
$ PUBLISH_TOKEN=example PUBLISH_REGISTRY=github publish --registry jsr
publishing to jsr tags=undefined
```

`env: { name: "VARIABLE" }` reads a flag from that variable when argv omits it. Variables are read when the command runs, not when the flag is defined.

- **Precedence:** argv, then env, then `default`. An environment value satisfies `required`.
- **Validation:** environment text goes through the same `type` conversion, `choices`, `parse`, and schemas as argv.
- **Booleans:** `true` or `1` is true; any other value is false. A `noNegate` flag rejects a false value, as it rejects `--no-<name>`.
- **Invalid values:** an invalid argv value fails instead of trying env; an invalid environment value, including a blank `PORT=` for a number flag, fails instead of using the default. Neither blocks `--help` or `--version`.
- **Docs:** generated documentation lists the variable as `[env: PUBLISH_TOKEN]`, never its value.
- **Programmatic calls:** [`run()`](/docs/api/crust#runpath-input-options) reads `process.env` too, for flags its input omits. Pass `{ env: {} }` (or chosen variables) to isolate a call from the caller's shell.
- **Arguments:** positional arguments have no `env`; use a flag.

#### Delimiters

Split a `multiple: true` flag's values with two independent settings:

| Setting         | Splits                   | Without it                      |
| --------------- | ------------------------ | ------------------------------- |
| `delimiter`     | Each string argv value   | Each occurrence is one value    |
| `env.delimiter` | The environment variable | The whole variable is one value |

The example uses commas on argv and colons in `PUBLISH_TAGS`:

```sh
$ PUBLISH_TOKEN=example PUBLISH_TAGS=latest::beta publish
publishing to npm tags=latest,beta
$ PUBLISH_TOKEN=example publish --tag latest,beta --tag next
publishing to npm tags=latest,beta,next
```

- Both require `multiple: true` and a nonempty literal separator. TypeScript rejects an empty literal `env.name`, `delimiter`, or `env.delimiter`; a computed empty value throws a `DEFINITION` error.
- Empty segments are dropped. Zero values after splitting follow the usual default, required, and schema rules, but an argv occurrence still wins over the environment.
- [`run()`](/docs/api/crust#runpath-input-options) takes arrays and never splits them.
- Boolean argv stays `--flag` / `--no-flag`. Repeated booleans can split environment text such as `true,false` with `env: { name: "FEATURES", delimiter: "," }`.

### Values that start with `-`

```sh
$ serve --tag=-nightly
targets=undefined runtime=bun tag=-nightly
$ serve --tag -nightly
Error: Missing value for flag "--tag"; to pass a value starting with "-", write --tag=<value>
```

Attach a dash-leading flag value with `=`. For a positional argument, pass it after `--`, as in `seek -- -5`: POSIX treats every token after `--` as an operand, even one that starts with `-`; see [raw tokens](#pass-through-raw-tokens). Arguments before an [`afterDoubleDash`](#only-after---) argument read nothing after `--`, so give them such values through a flag instead.

### Reuse across commands

<include lang="ts" meta='title="src/tools.ts"'>
  ../../../examples/guide/flags-reuse.ts
</include>

```sh
$ tools print --format yaml
print as yaml
$ tools inspect
inspect as json
```

`defineFlag()` creates one definition for several commands. Attach it under a key on each command that should parse it; the key names the flag, so `{ format }` defines `--format`.

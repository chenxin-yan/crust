`.flags(...defs)` takes values from `defineFlag(name, def)` or inline literals carrying `name`.

<include lang="ts">../../../examples/guide/flags.ts#definitions</include>

Repeated `.flags()` calls accumulate definitions. See [`FlagDef`](/docs/api/types#flagdef) for the complete definition and [`flags()`](/docs/api/crust#flagsdefs) for spelling and collision rules.

## Aliases and negation

```sh
$ bun run flags.ts --no-colour
color=false targets= runtime=bun tag=none
```

Use one character for `short`; names in `aliases` use two dashes. Boolean flags accept `--no-<flag>` unless `noNegate` is true, but they do not accept assignments such as `--name=true`. See the [`flags()` contract](/docs/api/crust#flagsdefs) for all accepted spellings.

## Required and defaulted values

```ts
.flags(
  { name: "token", type: "string", required: true },
  { name: "format", type: "string", default: "json" },
)
```

Both values are non-optional in the Command Action. Flags without `required` or `default` include `undefined` in their inferred type.

## Repeated values

```sh
$ bun run flags.ts --target linux -t darwin
color=true targets=linux,darwin runtime=bun tag=none
```

Set `multiple: true` to collect one value per occurrence in an array. Repeated boolean flags collect booleans in the same way.

## Choices

```sh
$ bun run flags.ts --runtime deno
Error: Invalid value "deno" for --runtime. Expected one of: bun, node
$ echo $?
1
```

Choices are supported on string flags, and an invalid value produces a `PARSE` failure. A literal choices tuple narrows the inferred value to its string union. Every default must belong to the choice set: known literal mismatches fail type checking with `FIX_DEFAULT_CHOICE`, while widened or dynamic mismatches throw a `DEFINITION` error.

## Reusing flag definitions

```ts
const format = defineFlag("format", { type: "string", default: "json" });
const print = defineCommand("print", (command) => command.flags(format));
const inspect = defineCommand("inspect", (command) => command.flags(format));

const app = new Crust("app").add(print, inspect);
```

Attach one descriptor to each command that parses the value. This keeps one definition without adding the flag to unrelated commands.

## Standard Schemas

```ts
import { z } from "zod";

new Crust("serve")
  .flags({ name: "port", type: "string", schema: z.coerce.number().int() })
  .action(({ flags }) => console.log(flags.port)); // number
```

See [Schema-backed definitions](/docs/guide/types#schema-backed-definitions) for schema input, output, and definition rules.

## Unsupported flag grammars

```sh
$ bun run flags.ts --tag
Error: Option '--tag <value>' argument missing
$ echo $?
1
```

A Crust flag is either boolean or value-taking. Rewrite unsupported forms before `execute()` if an upstream caller cannot use the supported form.

| Grammar | What happens | Write instead |
| --- | --- | --- |
| `--locales en fr` | `fr` is an excess positional | `--locales en --locales fr` |
| Optional value `--tag [name]` | bare `--tag` is a `PARSE` failure | `--tag` plus `--tag-name value` |
| Separated dash-leading value `--timeout -5` | `PARSE`: the value is ambiguous | `--timeout=-5` |

---
title: Values and validation
description: Convert and validate values with built-in types, custom parsing, or Standard Schemas.
---

Value definitions turn CLI text into action values; start with a built-in type, add `parse` for one synchronous conversion, and use a Standard Schema for richer validation.

## Choosing an approach

```ts
.flags({ name: "count", type: "number" })
.flags({ name: "date", type: "string", parse: (raw) => new Date(raw) })
.flags({ name: "port", type: "string", schema: Port })
```

Use the first option that expresses the input rule. A Standard Schema is worth adding when it owns validation, defaults, coercion, or is already shared with other code.

## Built-in value types

<include lang="ts">../../../examples/guide/types.ts#builtin</include>

Arguments and flags support `string`, `number`, `boolean`, `url`, `path`, and `json`. `path` resolves against the working directory, `url` returns a `URL`, and `json` parses the token; a token that fails conversion is rejected before the Command Action runs.

## Custom parsing

<include lang="ts">../../../examples/guide/types.ts#parse</include>

Use `parse` for a small synchronous transformation. The Command Action receives the parser's return type.

## Compile-time checks

<include lang="ts">../../../examples/guide/types.ts#compile-time</include>

TypeScript rejects known invalid definitions as you compose them; see the [`.args()`](/docs/api/crust#argsdefs) and [`.flags()`](/docs/api/crust#flagsdefs) contracts.

## Runtime checks

```ts
const app = new Crust("serve").flags({ name: "port", type: "number" });
const exitCode = await app.execute({ argv: ["--port", "oops"] });
// stderr: Error: Expected number for --port, got "oops"
// exitCode === 1
```

Input supplied at runtime is checked before the Command Action runs. See [`CrustError` codes](/docs/api/errors#codes) for error details.

## Schema-backed definitions

<include lang="ts">../../../examples/guide/types.ts#schema</include>

```sh
$ serve 8080
listening on localhost:8080
$ serve http
Error: Invalid input:
  - args.port: Invalid input: expected number, received NaN
```

Put a schema from any [Standard Schema](https://standardschema.dev) library (Zod, Valibot, ArkType) on a definition's `schema` key when the schema should own coercion, defaults, and validation. The Command Action receives the schema's output type, and every issue is reported in one message; see [`ArgDef`](/docs/api/types#argdef) and [`FlagDef`](/docs/api/types#flagdef) for the input contract.

### Where defaults live

```ts
const Port = z.coerce.number().default(3000);
```

Put a semantic default in the schema. A prompt's UI fallback still passes through its schema before being returned.

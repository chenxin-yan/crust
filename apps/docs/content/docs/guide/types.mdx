## Built-in value types

```ts
new Crust("inspect")
  .args({ name: "file", type: "path", required: true })
  .flags({ name: "config", type: "json" })
  .action(({ args, flags }) => {
    args.file; // string
    flags.config; // unknown
  });
```

Arguments and flags support `string`, `number`, `boolean`, `url`, `path`, and `json`. The `type` selects built-in conversion and, for flags, token consumption; a failed conversion produces a `PARSE` error.

## Custom parsing

```ts
new Crust("schedule")
  .flags({ name: "date", type: "string", parse: (raw) => new Date(raw) })
  .action(({ flags }) => {
    flags.date; // Date
  });
```

Use `parse` for a small synchronous transformation when a full schema is unnecessary. The Command Action receives the parser's return type.

## Compile-time checks

```ts
new Crust("fetch").args({
  name: "remote",
  type: "string",
  parse: async (raw) => raw.trim(),
});
// FIX_ASYNC_PARSE: parse must be synchronous; do async work in run()
```

TypeScript checks known definitions as they are authored and composed. `FIX_*` properties name the constraint and the change needed to satisfy it.

## Runtime checks

```ts
const app = new Crust("serve").flags({ name: "port", type: "number" });
const exitCode = await app.execute({ argv: ["--port", "oops"] });
// stderr: Error: Expected number for --port, got "oops"
// CrustError code: PARSE
// exitCode === 1
```

Argv and dynamic definitions are checked when they are consumed. See [`run()` input validation](/docs/api/crust#runpath-input-io) and [`CrustError` codes](/docs/api/errors#codes) for the runtime boundaries and error details.

| What | Checked by | When |
| --- | --- | --- |
| Known definitions and composition | TypeScript | Typecheck |
| Dynamic definitions | Crust | Composition or preparation |
| Argv and structured values | Crust | Invocation |

## Raw input versus action output

<include lang="ts">../../../examples/guide/invocation.ts#raw</include>

Custom parsers and schemas receive raw input, while the Command Action receives transformed output. Required and schema checks run after `preRun`, so an Extension that returns `ctx.finish()` skips them.

## Schema-backed definitions

```ts
import { z } from "zod";

const command = new Crust("serve")
  .args({ name: "port", schema: z.coerce.number().int().positive() })
  .flags(
    { name: "host", type: "string", schema: z.string().default("localhost") },
    { name: "workers", type: "string", schema: z.coerce.number().int().positive() },
  )
  .action(({ args, flags }) => {
    args.port; // number
    flags.host; // string
    flags.workers; // number
  });
```

Put a Standard Schema on a plain definition's `schema` key. The schema receives the raw value and owns coercion, defaults, requiredness, and validation; the Command Action receives its output type.

```ts
import { CrustError } from "@crustjs/core";

const outcome = await command.run([], {
  args: { port: "not-a-number" },
  flags: { workers: "not-a-number" },
});
if (outcome.status === "failed" && outcome.error instanceof CrustError) {
  console.error(outcome.error.code);
  for (const issue of outcome.error.details?.issues ?? []) console.error(issue.path);
}
// VALIDATION
// args.port
// flags.workers
```

Schema failures from one invocation are aggregated into one `VALIDATION` error. See [`run()` validation](/docs/api/crust#runpath-input-io), [`ArgDef`](/docs/api/types#argdef), and [`FlagDef`](/docs/api/types#flagdef) for the complete contract.

### The same shape across packages

```ts
const Port = z.coerce.number().default(3000);

const portFlag = { name: "port", type: "string", schema: Port };
const portField = { schema: Port };
const portPrompt = { message: "Port?", schema: Port };
```

Core definitions, store fields, and prompts all use the `schema` key. Store values must also be JSON-compatible because they are persisted.

### Where defaults live

```ts
const Port = z.coerce.number().default(3000);
```

Put semantic defaults in the schema. Prompt UI fallback values still pass through the schema before being returned.

## Choosing an approach

```ts
.flags({ name: "count", type: "number" })
.flags({ name: "date", type: "string", parse: (raw) => new Date(raw) })
.flags({ name: "port", type: "string", schema: Port })
```

Use a built-in type for direct token conversion, `parse` for one synchronous transform, and `schema` for validation, defaults, coercion, or an existing schema library.

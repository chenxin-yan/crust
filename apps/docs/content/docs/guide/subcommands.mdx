## Inline commands

`.command(name, configure)` creates and mounts a child typed from its parent:

```ts
import { Crust } from "@crustjs/core";

const app = new Crust("git")
  .flags({ verbose: { type: "boolean", inherit: true } })
  .command("clone", (command) =>
    command
      .args([{ name: "url", type: "url", required: true }])
      .handle(({ args, flags, stdout }) => {
        stdout(`${flags.verbose ? "Cloning" : "clone"} ${args.url}`);
      }),
  );
```

Nest `.command()` calls to any depth. Routing consumes command names before parsing the resolved command's arguments and flags. Metadata aliases can route to the same command.

Inline commands are convenient sugar for defining and materializing a command at the same point. Use a standalone definition when a command belongs in another file or should be reused.

## Reusable command definitions

`defineCommand<Requirements>(configure)` creates an inert command definition. Requirements declare the inheritable flags that the definition expects from any parent:

```ts
import { Crust, defineCommand, defineFlag } from "@crustjs/core";

const verbose = defineFlag({ type: "boolean", inherit: true });

const clone = defineCommand<{
  flags: { verbose: typeof verbose };
}>((command) =>
  command.args([{ name: "url", type: "url", required: true }]).handle(({ args, flags, stdout }) => {
    stdout(`${flags.verbose ? "Cloning" : "clone"} ${args.url}`);
  }),
);

const app = new Crust("git").flags({ verbose }).mount("clone", clone);
```

The definition has no name and cannot run by itself. `.mount(name, definition)` supplies the routing name, checks the requirements at that call, and creates a fresh command node. The same definition can therefore be mounted under different names or into different satisfying parents:

```ts
const git = new Crust("git").flags({ verbose }).mount("clone", clone).mount("copy", clone);
```

Missing or incompatible inherited flags are TypeScript errors on `.mount()`. A same-named parent flag only counts when it has `inherit: true`.

## Nested definitions

Definitions can mount other definitions. Nested requirements must be available at the exact nested `.mount()` call:

```ts
const environment = defineFlag({ type: "string", inherit: true });

const status = defineCommand<{
  flags: { verbose: typeof verbose; environment: typeof environment };
}>((command) =>
  command.handle(({ flags, stdout }) => {
    stdout(`${flags.environment} ${flags.verbose}`);
  }),
);

const deploy = defineCommand<{
  flags: { verbose: typeof verbose };
}>((command) => command.flags({ environment }).mount("status", status));

const app = new Crust("app").flags({ verbose }).mount("deploy", deploy);
```

## Unknown commands

An unknown subcommand produces `CrustError` code `COMMAND_NOT_FOUND`. Its details include the input, available commands, the command path, and a readonly snapshot of the parent command. The official `didYouMean()` Extension uses this information to suggest nearby names.

## Adding commands

`defineCommand(name, recipe)` creates an inert definition that carries its name; `.add(...definitions)` materializes definitions as child commands:

```ts
import { Crust, defineCommand } from "@crustjs/core";

const app = new Crust("git").add(
  defineCommand("clone", (command) =>
    command
      .args({ name: "url", type: "url", required: true })
      .action(({ args, stdout }) => stdout(`clone ${args.url}`)),
  ),
);
```

Routing consumes command names before parsing the resolved command's arguments and flags. Metadata aliases can route to the same command. Nest `.add()` calls inside definitions to any depth.

## Requirements

A definition pulls Context capabilities with `await ctx.use(factory)`. The returned value is typed from the factory, while the app decides where to provide it:

```ts
import { Crust, defineCommand, defineContext, defineFlag } from "@crustjs/core";

const verbose = defineFlag("verbose", { type: "boolean" });
const logging = defineContext("logging", { flags: [verbose] }, ({ flags, stderr }) => ({
  debug(message: string) {
    if (flags.verbose) stderr(message);
  },
}));
const repository = defineContext("repository", () => ({
  defaultBranch: "main",
}));

const clone = defineCommand("clone", (command) =>
  command
    .args({ name: "url", type: "url", required: true })
    .action(async ({ args, ctx, stdout }) => {
      (await ctx.use(logging)).debug(`cloning ${args.url}`);
      stdout((await ctx.use(repository)).defaultBranch);
    }),
);

const app = new Crust("git").provide(logging(), repository()).add(clone);
```

`.add()` creates a fresh command node. Use `.as(name)` to add one definition under different names:

```ts
const git = new Crust("git").provide(logging()).provide(repository()).add(clone, clone.as("copy"));
```

A missing Context fails when `use()` runs with an actionable runtime `DEFINITION` error.

## Nested definitions

Definitions can add other definitions. Providers available on that command path are inherited by nested definitions:

```ts
const environment = defineFlag("environment", { type: "string" });
const deployment = defineContext("deployment", { flags: [environment] }, ({ flags }) => flags);

const status = defineCommand("status", (command) =>
  command.action(async ({ ctx }) => {
    (await ctx.use(logging)).debug(`environment: ${(await ctx.use(deployment)).environment}`);
  }),
);

const deploy = defineCommand("deploy", (command) => command.provide(deployment()).add(status));

const app = new Crust("app").provide(logging()).add(deploy);
```

## Context inheritance

Adding materializes a fresh command scope seeded with the parent's current Context path. The added action and all nested descendants can pull those Context values; `use()` infers the value type directly from its factory argument.

Finalize `.provide()` calls on the parent builder before `.add()`. [Flags owned by a provided Context](/docs/guide/contexts#owned-flags) propagate only into descendants added later. Later fluent calls return a new builder and do not backfill a definition that was already added.

## Unknown commands

An unknown subcommand produces `CrustError` code `COMMAND_NOT_FOUND`. Its details include the input, available commands, the command path, and a readonly snapshot of the parent command. The official `didYouMean()` Extension uses this information to suggest nearby names.

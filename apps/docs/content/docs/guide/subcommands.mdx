title: Subcommands
description: Compose nested command trees inline or from pre-built command builders.
---

## Inline commands

`.command(name, configure)` creates a child typed from its parent:

```ts
const app = new Crust("git")
  .flags({ verbose: { type: "boolean", inherit: true } })
  .command("clone", (command) =>
    command
      .args([{ name: "url", type: "url", required: true }])
      .handle(({ args, flags, stdout }) => {
        stdout(`${flags.verbose ? "Cloning" : "clone"} ${args.url}`);
      }),
  );
```

Nest `.command()` calls to any depth. Routing consumes command names before parsing the resolved command's arguments and flags. Metadata aliases can route to the same command.

## Pre-built commands

Attach an existing builder with `.command(builder)`:

```ts
const status = new Crust("status").handle(({ stdout }) => stdout("clean"));
const app = new Crust("git").command(status);
```

A standalone builder is isolated from parent flag types. For a separate-file child that inherits parent flags and Contexts, create it with `parent.sub(name)`:

```ts
const base = new Crust("git").flags({ verbose: { type: "boolean", inherit: true } });
const clone = base.sub("clone").handle(({ flags }) => flags.verbose);
const app = base.command(clone);
```

See [Split Commands Across Files](/docs/guide/split-files) for the import-order rule and a complete layout.

## Context inheritance

Contexts attached to a parent are available to descendants. `.sub()` carries their types into a separate-file child; attaching the child merges the parent path's Context instances at runtime.

## Unknown commands

An unknown subcommand produces `CrustError` code `COMMAND_NOT_FOUND`. Its details include the input, available commands, the command path, and a readonly snapshot of the parent command. The official `didYouMean()` Extension uses this information to suggest nearby names.

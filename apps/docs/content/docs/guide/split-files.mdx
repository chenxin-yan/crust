---
title: Split Commands Across Files
description: Declare command requirements without coupling command files to the application root.
---

For a small application, prefer inline `.command(name, configure)`. When a command becomes large or reusable, export an inert definition and mount it by name at the root.

## Shared requirements

Keep reusable flag definitions and requirement types in a dependency-free shared module:

```ts title="src/shared.ts"
import { defineFlag, type CommandRequirements } from "@crustjs/core";

export const verbose = defineFlag({ type: "boolean", inherit: true });

export interface AppCommandRequirements extends CommandRequirements {
  flags: { verbose: typeof verbose };
  ctx: { logger: { write(message: string): void } };
}
```

Using the same flag constant makes the required value shape and the root definition agree.

## Standalone command definition

A command file imports `defineCommand` and shared requirements, never the application builder:

```ts title="src/commands/greet.ts"
import { defineCommand } from "@crustjs/core";
import type { AppCommandRequirements } from "../shared.ts";

export const greetCommand = defineCommand<AppCommandRequirements>()((command) =>
  command
    .args([{ name: "name", type: "string", default: "world" }])
    .flags({ greeting: { type: "string", default: "Hello", short: "g" } })
    .handle(({ args, flags, ctx, stdout }) => {
      if (flags.verbose) ctx.logger.write("Preparing greeting");
      stdout(`${flags.greeting}, ${args.name}!`);
    }),
);
```

The configure callback is typed from the declared requirements. The exported definition is inert: importing it does not build or run a command.

## Completed root

Define the root and its application-wide Extensions independently:

```ts title="src/app.ts"
import { defineContext, Crust } from "@crustjs/core";
import { help, version } from "@crustjs/extensions";
import { verbose } from "./shared.ts";

const logger = defineContext("logger", (_options: void) => ({
  write(message: string) {
    console.error(message);
  },
}));

export const app = new Crust("my-cli")
  .meta({ description: "A split-file CLI" })
  .extend(version("0.2.0"), help())
  .flags({ verbose })
  .provide(logger(undefined));
```

## Mount and execute

The composition root imports both sides and chooses the routing name:

```ts title="src/cli.ts"
import { app } from "./app.ts";
import { greetCommand } from "./commands/greet.ts";

await app.mount("greet", greetCommand).execute();
```

`.mount()` checks that `app` provides a compatible inheritable `verbose` flag and `logger` Context. Missing or incompatible requirements are reported at this line.

## Finalize before mounting

Fluent builders are immutable, and a mount captures the parent scope used at that call. Add required `inherit: true` flags and Contexts before `.mount()`:

```ts
const complete = new Crust("app")
  .flags({ verbose })
  .provide(logger(undefined))
  .mount("greet", greetCommand);
```

A later `.flags()` or `.provide()` call creates a new parent builder; it does not backfill a definition that was already mounted.

## Inline or split?

Use inline `.command(name, configure)` when the implementation is short and local. Use `defineCommand<Requirements>()(configure)` plus `.mount(name, definition)` when a separate file improves readability or when the same command should be mounted more than once.

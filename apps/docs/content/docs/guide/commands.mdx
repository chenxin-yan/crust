A command combines metadata, inputs, dependencies, and one Command Action.

```ts
import { Crust } from "@crustjs/core";

const app = new Crust("greet", { description: "Print a greeting" })
  .args({ name: "name", type: "string", required: true })
  .flags({ name: "loud", type: "boolean", short: "l" })
  .action(({ args, flags, stdout }) => {
    const text = `Hello, ${args.name}!`;
    stdout(flags.loud ? text.toUpperCase() : text);
  });

await app.execute();
```

## Command Action context

A Command Action receives validated `args`, `flags`, Context values under `ctx`, forwarded `rawArgs`, a readonly `command` snapshot, and injectable writers through a typed `CrustCommandContext`:

  path="../../../../../packages/core/src/command/crust.ts"
  name="CrustCommandContext"
/>

```ts
const command = new Crust("inspect").action(({ command, stdout }) => {
  stdout(command.meta.name);
});
```

Throw ordinary errors from Command Actions. Crust does not wrap them.

## Immutable builders

Every builder method returns a new `Crust` value. Keep the returned value:

```ts
const base = new Crust("app", { description: "My app" });
const withFlags = base.flags({ name: "verbose", type: "boolean" });
```

Fluent methods remain immutable, permitting safe composition while preserving input inference.

## Subcommands

Routing consumes command names before parsing the resolved command's arguments and flags. Nest to any depth.

For app-local leaf commands, chain `.command(name, recipe)` on the root:

```ts
const app = new Crust("my-cli").command("build", (command) =>
  command
    .flags({ name: "minify", type: "boolean" })
    .action(({ flags, stdout }) => stdout(`minify: ${flags.minify ?? false}`)),
);
```

For commands that need their own file, reuse, or a package, `defineCommand(name, recipe)` creates an inert definition that carries its name; `.add(...definitions)` materializes definitions as child commands:

<include lang="ts">../../../examples/guide/subcommands.ts</include>

Static root metadata belongs in the constructor. Subcommand metadata belongs in `defineCommand()` config, and metadata aliases route to the same command:

```ts
import { defineCommand } from "@crustjs/core";

const greet = defineCommand(
  "greet",
  { description: "Print a greeting", aliases: ["hello"] },
  (command) => command.action(() => {}),
);
```

`.add()` creates a fresh command node. Use `.as(name)` to add one definition under different names:

```ts
const app = new Crust("git").add(clone, clone.as("copy"));
```

Definitions can `.add()` other definitions. Definitions that declare Context dependencies with `.use()` are covered in [Contexts in command trees](/docs/guide/contexts#contexts-in-command-trees).

<Callout type="info">
  A command without a Command Action is valid when it owns subcommands. Invoking it directly
  resolves to `{ status: "completed", result: undefined }`; register the `help()` Extension to
  present the container's help instead.
</Callout>

### Inline or split?

Start with one `src/cli.ts`. Use inline `.command(name, recipe)` on the root for app-local leaf commands that stay short. Extract to `defineCommand` when a command needs its own file, reuse, or a package; the `.use()` contract keeps its dependencies explicit and type-checkable either way. Keep Extensions at the root and place reusable setup in [Contexts](/docs/guide/contexts).

## Unknown commands

During argv routing with `execute()`, an unmatched subcommand token produces `CrustError` code `COMMAND_NOT_FOUND` when the parent has no Command Action. A parent with an action treats that token as a positional argument instead; parsing or validation may then reject it. Typed `run()` resolves a failed outcome carrying `COMMAND_NOT_FOUND` for unknown command-path segments rather than treating them as arguments.

`COMMAND_NOT_FOUND` details include the input, visible available commands, the command path, and a readonly snapshot of the parent command. Hidden commands are omitted from `available`. The official `didYouMean()` Extension uses this error to suggest nearby names; it cannot suggest a correction when argv routing treats the typo as a positional argument.

## Invocation

Use `execute()` at the terminal entrypoint and `run()` for programmatic invocation. See the [execution model](/docs/guide/lifecycle) for both modes.

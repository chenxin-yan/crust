Create a CLI with `new Crust(name)`, define what it does with `.action()`, and call `.execute()` to run it.

```sh
$ bun src/cli.ts

```

<Callout>
  Print with the action's `stdout(text)` and `stderr(text)`, not `console.log` or
  `process.stdout.write`. Only that output is captured by
  [`run()`](/docs/api/crust#runpath-input-options), and [tests](/docs/guide/testing), and kept in
  order with Crust's own output, such as rendered errors.
</Callout>

Add subcommands in either way, or mix both in one app:

- **`.command()` inline:** small CLIs, or short subcommands used only by this app.
- **`defineCommand()` + `.add()`:** separate command files or reusable definitions.

## Grow in one file

`.command(name, config?, callback)` defines a subcommand's flags and action in place. The optional `config` is the same metadata `defineCommand()` takes, such as the `description` help lists. Call `.command()` inside the callback to nest another level.

<include lang="ts" meta='title="src/cli.ts" twoslash'>
  ../../../examples/guide/commands.ts
</include>

```sh
$ tool build --minify
minify: true
```

## Documentation sections

Document what help can't infer, such as exit codes or environment variables, with `sections`: in a command's `defineCommand()` config, or in `new Crust()` metadata for the root.

<include lang="ts" meta='title="src/cli.ts"'>
  ../../../examples/guide/commands-sections.ts
</include>

```sh
$ my-cli deploy --help
my-cli deploy - Deploy a release

Usage:
  my-cli deploy [options]

Options:
  -h, --help                   Show help

Exit codes:
  0  Deployed
  1  Deploy failed
```

- A section renders on its own command only, in every Extension that documents commands.
- Limit it to some of them with `only` or `except`; see [`CommandSectionInput`](/docs/api/types#commandsectioninput).
- [Contexts](/docs/guide/contexts#documentation-owned-by-a-context) and [Extensions](/docs/guide/extensions#command-sections) can add sections too.

## Run commands from code

`.execute()` is the terminal entry point: it parses argv, renders errors, and sets the exit code. From a script, server, or test, call `.run()` with a typed path and structured input instead.

<include lang="ts" meta='title="src/script.ts"'>
  ../../../examples/guide/commands-split-files/script.ts
</include>

`run()` resolves to an outcome with captured `stdout` and `stderr`. Check `status` before reading `result`.

Unlike `.execute()`, it never renders errors, sets `process.exitCode`, or reads flag `env` fallbacks. See the [`run()` reference](/docs/api/crust#runpath-input-options) for input rules and [Testing](/docs/guide/testing) for tests.

## Stream events

To report progress to programs while a command works, write its action as an `async function*`: each `yield` emits an event, and the `return` value becomes the result.

<include lang="ts" meta='title="src/script.ts"'>
  ../../../examples/guide/commands-stream.ts
</include>

Events are for programs: Crust never prints them. A terminal user sees only the action's `stdout(text)` and `stderr(text)`.

- **Delivery:** each event goes live to the selected [renderer's](/docs/guide/extensions#renderers) `event`, if any, then to `options.onEvent` of `run()` or `execute()`. The action pauses at each `yield` until both return.
- **Outcome:** `run()` collects every event in `outcome.events`, typed from the yields, whether the command completes or fails mid-stream. Ordinary actions have no `events`.
- **Cancellation:** when the invocation's `signal` aborts, Crust closes the generator at its next `yield`, so its `finally` blocks run, and the invocation fails with the abort reason. Pass `signal` to the work between yields to stop sooner.
- **Throwing consumers:** a throwing renderer `event` or `onEvent` closes the generator the same way and fails the invocation.
- **Failed cleanup:** if closing the generator throws, the invocation fails with a `SuppressedError` (`error`: the cleanup failure, `suppressed`: the original), as with a failed [Context disposal](/docs/api/errors#propagation-boundaries). A cancelled invocation still exits `130` (`143` after `SIGTERM`).
- **Returned generators:** an action that returns an async generator object, such as `async () => watch()`, streams the same way. Other async iterables are ordinary results.

## Unknown commands

```sh
$ tool deploy
Error: Unknown command "deploy".
$ echo $?
1
```

`tool` from [Grow in one file](#grow-in-one-file) has subcommands but no action of its own, so an unknown name fails with exit code `1`.

If the parent has its own `.action()`, matching subcommands still win, and unmatched words become its [positional arguments](/docs/guide/arguments-and-flags#arguments).

## Immutable builders

```ts
const base = new Crust("app", { description: "My app" });
const withFlags = base.flags({ name: "verbose", type: "boolean" });
```

Every builder method returns a new `Crust` value, so keep the returned value. `base` above remains unchanged while `withFlags` has the flag.

## Subcommands

```ts
const app = new Crust("my-cli").command("build", (command) =>
  command
    .flags({ name: "minify", type: "boolean" })
    .action(({ flags, stdout }) => stdout(`minify: ${flags.minify ?? false}`)),
);
```

Routing consumes command names before parsing the resolved command's arguments and flags. Use root-only `.command(name, recipe)` for a short app-local leaf command.

For commands that need their own file, reuse, or a package, `defineCommand(name, recipe)` creates an inert definition. `.add(...definitions)` materializes definitions as child commands.

<include lang="ts">../../../examples/guide/subcommands.ts</include>

Static root metadata belongs in the constructor. Subcommand metadata belongs in `defineCommand()` config, and metadata aliases route to the same command.

```ts
const greet = defineCommand(
  "greet",
  { description: "Print a greeting", aliases: ["hello"] },
  (command) => command.action(() => {}),
);
```

`.add()` creates a fresh command node. Use `.as(name)` to add one definition under different names.

```ts
const app = new Crust("git").add(clone, clone.as("copy"));
```

Definitions can `.add()` other definitions. Definitions that declare Context dependencies with `.use()` are covered in [Contexts in command trees](/docs/guide/contexts#contexts-in-command-trees).

<Callout type="info">
  A command without a Command Action is valid when it owns subcommands. Invoking it directly
  completes with an undefined result; register the `help()` Extension to present the container's
  help instead.
</Callout>

### Inline or split?

Start with one `src/cli.ts`. Extract to `defineCommand` when a command needs its own file, reuse, or a package; keep Extensions at the root and reusable setup in [Contexts](/docs/guide/contexts).

## Unknown commands

<include lang="ts">../../../examples/guide/commands.ts#routing</include>

<include lang="ts">../../../examples/guide/commands.ts#unknown</include>

An unknown command-path segment makes `run()` return a failed `COMMAND_NOT_FOUND` outcome. For argv routing with `execute()`, an unmatched token produces the same error only when the parent has no Command Action; a parent action can instead receive the token as a positional argument.

See [`run()` input and output](/docs/api/crust#runpath-input-io) for the complete error details. The `didYouMean()` Extension can use this error to suggest a visible command.

## Invocation

<include lang="ts">../../../examples/guide/commands.ts#invocation</include>

Use `execute()` at the terminal entrypoint and `run()` for programmatic invocation. See the [execution model](/docs/guide/lifecycle) for both modes.

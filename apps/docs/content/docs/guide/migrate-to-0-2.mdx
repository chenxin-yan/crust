---
title: Migrate to 0.2
description: Apply every hard-cut API and package change from Crust 0.1.
---

import { Callout } from "fumadocs-ui/components/callout";

Crust 0.2 is a hard cut. Remove superseded APIs rather than keeping compatibility wrappers.

## Core command API

### Command Handlers: `.run(handler)` to `.handle(handler)`

Before:

```ts
const app = new Crust("app").run(({ args }) => {
  console.log(args);
});
```

After:

```ts
const app = new Crust("app").handle(({ args, stdout }) => {
  stdout(JSON.stringify(args));
});
```

`.run()` now means programmatic invocation. It requires argv, accepts injectable writers, throws the original error, and does not change exit status:

```ts
await app.run(["deploy"], { stdout, stderr });
await app.execute(); // terminal entrypoint
```

### Setup and cleanup: remove `.preRun()` and `.postRun()`

Before:

```ts
new Crust("app")
  .preRun(async () => openDatabase())
  .postRun(async () => closeDatabase())
  .run(handler);
```

After, use a Context for command dependencies and native disposal:

```ts
const database = context("db", async (url: string) => {
  const db = await openDatabase(url);
  return {
    db,
    async [Symbol.asyncDispose]() {
      await db.close();
    },
  };
});

new Crust("app").provide(database(url)).handle(({ ctx }) => handler(ctx.db.db));
```

For app-wide cross-cutting behavior, use Extension `intercept`:

```ts
const timing = extension("timing", {
  async intercept(ctx, next) {
    const start = performance.now();
    await next();
    ctx.stderr(`${performance.now() - start}ms`);
  },
});
```

## Extensions

### Package and attachment names

Before:

```ts
import { helpPlugin, versionPlugin } from "@crustjs/plugins";

new Crust("app").use(helpPlugin()).use(versionPlugin("0.1.0"));
```

After:

```ts
import { help, version } from "@crustjs/extensions";

new Crust("app").extend(help(), version("0.2.0"));
```

`.extend()` is root-only because Extensions are app-wide.

All six capability factories lose the `Plugin` suffix.

Before:

```ts
helpPlugin();
versionPlugin();
completionPlugin();
didYouMeanPlugin();
noColorPlugin();
updateNotifierPlugin(options);
```

After:

```ts
help();
version();
completion();
didYouMean();
noColor();
updateNotifier(options);
```

### Authoring contract

Before:

```ts
const feature = extension("feature")
  .flag("feature", { type: "boolean" })
  .command(featureCommand)
  .beforeRun(before)
  .wrapRun(wrap)
  .afterRun(after)
  .onError(renderError);
```

After:

```ts
const feature = extension("feature", {
  flags: { feature: { type: "boolean" } },
  commands: [featureCommand],
  async intercept(ctx, next) {
    await before(ctx);
    await next();
    await after(ctx);
  },
  async handleError(error, ctx, next) {
    if (!(await renderError(error, ctx))) await next();
  },
});
```

`flags` and `commands` are owned definitions. `intercept` replaces run wrapping and before/after hooks. `handleError` is presentation-only and runs for `execute()`, not `run()`.

### Hook context and output

Before:

```ts
async function before(ctx: ExtensionRunContext) {
  ctx.output.write("starting");
}
```

After:

```ts
async function intercept(ctx: ExtensionContext, next: ExtensionNext) {
  ctx.stdout("starting");
  await next();
  ctx.stderr("finished");
}
```

`ExtensionOutput.write` is removed. Use `ctx.stdout` and `ctx.stderr`, which honor writers injected into `run()`.

### Option type names

Before:

```ts
import type {
  CompletionPluginOptions,
  DidYouMeanPluginOptions,
  UpdateNotifierPluginOptions,
} from "@crustjs/plugins";
import type { SkillPluginOptions } from "@crustjs/skills";
```

After:

```ts
import type {
  CompletionOptions,
  DidYouMeanOptions,
  UpdateNotifierOptions,
} from "@crustjs/extensions";
import type { SkillOptions } from "@crustjs/skills";
```

### Collisions now fail

Before, a conflicting contribution could be skipped:

```ts
// 0.1: setup warns, then skips the conflicting flag or command.
await app.execute();
```

After, Extension command names and aliases, and flag names, short forms, and long aliases are checked against the app and every Extension:

```ts
try {
  await app.run([]);
} catch (error) {
  if (error instanceof CrustError && error.is("DEFINITION")) {
    console.error(error.message);
  }
}
```

There is no warn-and-skip behavior.

## Contexts

### `.context()` to `.provide()`

Before:

```ts
const app = new Crust("app").context(dbContext);
```

After:

```ts
const app = new Crust("app").provide(dbContext);
```

### `context()` always returns a factory

Before, a zero-option definition returned an instance:

```ts
const clock = context("clock", () => ({ now: Date.now }));
new Crust("app").context(clock);
```

After, invoke every Context factory, including a no-option factory:

```ts
const clock = context("clock", (_options: void) => ({ now: Date.now }));
new Crust("app").provide(clock(undefined));
```

A factory with options reads naturally:

```ts
const db = context("db", (options: { url: string }) => connect(options.url));
new Crust("app").provide(db({ url: "postgres://localhost/app" }));
```

## Validation

### Delete `@crustjs/validate`

Before:

```ts
import { arg, commandValidator, flag, parseValue } from "@crustjs/validate";

const validate = commandValidator({
  args: { port: arg(parseValue(Number)) },
  flags: { host: flag.string() },
});
```

After, put a Standard Schema directly on each definition:

```ts
import { z } from "zod";

const app = new Crust("serve")
  .args([{ name: "port", schema: z.coerce.number().int() }] as const)
  .flags({ host: { type: "string", schema: z.string().default("localhost") } })
  .handle(({ args, flags }) => {
    args.port; // number
    flags.host; // string
  });
```

Remove all `@crustjs/validate` imports, including `arg`, `flag`, `commandValidator`, and `parseValue`. A schema exclusively owns coercion, defaults, requiredness, choices, and validation.

## Errors and cancellation

### Remove `_tag`

Before:

```ts
if (error instanceof CrustError && error._tag === "VALIDATION") {
  // ...
}
```

After:

```ts
if (error instanceof CrustError && error.is("VALIDATION")) {
  console.error(error.details);
}
// or: error.code === "VALIDATION"
```

`CrustErrorTag` is removed.

### Error code changes

Before:

```ts
new CrustError("CONFIG", message);
new CrustError("EXECUTION", message);
```

After:

```ts
new CrustError("DEFINITION", message);
```

`CONFIG` is renamed to `DEFINITION`. `EXECUTION` is removed: errors thrown by Command Handlers and Contexts pass through unwrapped.

The complete framework code set is `DEFINITION`, `PARSE`, `VALIDATION`, and `COMMAND_NOT_FOUND`.

### Cancellation

Before:

```ts
import { CancelledError } from "@crustjs/prompts";
if (error instanceof CancelledError) return;
```

After:

```ts
if (error instanceof DOMException && error.name === "AbortError") return;
```

`execute()` handles `AbortError` silently with exit status `130`; `run()` throws it.

## Command Snapshots and tooling

### `CommandNode` and `prepareCommandTree()`

Before:

```ts
const tree: CommandNode = await app.prepareCommandTree();
```

After, public boundaries use readonly serializable `CommandSnapshot` values. Unsupported first-party tooling can prepare one through the explicit tooling entrypoint:

```ts
import { prepareCommandSnapshot } from "@crustjs/core/tooling";

const snapshot: CommandSnapshot = await prepareCommandSnapshot(app);
```

Application Authors should normally invoke the app instead of using the unsupported tooling bridge.

### Remove `@crustjs/core/internal`

Before:

```ts
import { parseArgs, resolveCommand } from "@crustjs/core/internal";
```

After, the `/internal` export does not exist. Use supported application invocation:

```ts
await app.run(argv, { stdout, stderr });
```

### Pruned root type exports

Before, applications could import type plumbing from the root:

```ts
import type {
  EffectiveFlags,
  InferArgs,
  InferFlags,
  InheritableFlags,
  MergeFlags,
  ParseResult,
  Resolve,
  ResolveBaseType,
  ValidateCrossCollisions,
  ValidateFlagAliases,
  ValidateNoPrefixedFlags,
  ValidateVariadicArgs,
} from "@crustjs/core";
```

After, let the builder infer Command Handler types. Import supported definition types only when a named type is needed:

```ts
import type { ArgDef, ArgsDef, CommandMeta, FlagDef, FlagsDef, ValueType } from "@crustjs/core";
```

### Validation protocol constants moved

These unsupported build-protocol constants now live under tooling:

```ts
import { VALIDATION_FORCE_EXIT_ENV, VALIDATION_MODE_ENV } from "@crustjs/core/tooling";
```

Application Authors should not depend on this protocol.

### Parser and router exports removed

Before:

```ts
const route: CommandRoute = resolveCommand(root, argv);
const parsed = parseArgs(route.command, route.argv);
validateParsed(parsed);
```

After:

```ts
await app.run(argv, { stdout, stderr });
```

`parseArgs`, `validateParsed`, `resolveCommand`, and `CommandRoute` are not public APIs.

## `create-crust`

The `--template` option and modular template are removed.

Before:

```sh
bun create crust my-cli --template modular
```

After:

```sh
bun create crust my-cli
```

The generator ships one minimal template. Organize larger apps with [the split-file pattern](/docs/guide/split-files).

## Manual pages

`WriteManPageOptions.argv` and `WriteManPageOptions.logWarnings` are removed because manual pages render from Command Snapshots.

Before:

```ts
await writeManPage({
  app,
  name: "my-cli",
  outfile: "man/my-cli.1",
  argv: ["--help"],
  logWarnings: true,
});
```

After:

```ts
await writeManPage({ app, name: "my-cli", outfile: "man/my-cli.1" });
```

Check the [Man module reference](/docs/modules/man) for the current output options.

## Final checks

```sh
rg '@crustjs/plugins|@crustjs/validate|\.use\(|\.preRun\(|\.postRun\(' src
bun run check:types
bun test
```
